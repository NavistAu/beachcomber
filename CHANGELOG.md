# Changelog

All notable changes to beachcomber will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

The configuration is a new shape, and the cache a new model. Config has two roots, `[daemon]` and `[client]`; a provider is a namespace of Sources, each a jinja function with `root`, `data`, `result` and `return`, written on an engine (`exec`, `url`, `plugin`, `read`, `lup`, `fromjson`, `fromini`, `merge`, `map`, `pluck`, `dirname`, `tojson`); `_` tables and `| super` give prototypes; instances are found by `root` and cascade or answer `| nearest`; Sources can call Sources; a provider can be disabled; an edit under `providers` reloads in place. The cache is one tree read at any depth, with layers (`put`, `config:`, Source) and the `:template`, `:put`, `:source` and `:cache` facets, and `null` means absent. The BREAKING entries under Changed and Removed list what 0.9.1 files and clients must change.

### Added

- **`comb get`, `comb status` and `comb watch` write a cached template's memo back after they print, and `status` names a memo.** `comb get` resolves every key, prints, and then writes back the memos its cached leaves rendered (one `memo` op each, on the connection the read used), so the caller has its output before the write; `comb status` does the same once its table is printed, and a rendered row served from its memo says SOURCE `memo` with the memo's AGE, and ran nothing; a watch (`comb watch`, `ResolvedWatch`, every SDK's `watch`) writes back after each resolution, before its frame is handed on. The watch fan-in compares a frame's memo half too (ages aside, as the daemon does, through the one `libbeachcomber::protocol::memo_without_ages`), so a memo whose hash was dropped (`comb refresh`, a template edit, a data write under the field) re-renders the leaf, and the frame is printed only when the value changed. An SDK's `get` was already served and stored through `resolve`; the conformance fixture `get/cache_filter_renders.json` runs the filters over the C ABI in every SDK, and `comb get -f json` and `bc_get` agree on a cached leaf. `--force` means compute afresh on every key: on a namespace a `put` made, a forced read of an address with a template is answered (the client renders past the memo), and only one with no template is `cannot --force static namespace '<p>': no source to re-execute from`.
- **A memo is a lifecycle entry, and its triggers drop its hash.** A `memo` write makes the memo's address a lifecycle entry of its own (its provider, its directory, `memo`, and the leaf as its `node`), started afresh by each write and renewed by nothing else: a read of the leaf does not renew it. A `ttl` is `poll(ttl, 1)` with decay 1, as a `put`'s: when the ttl runs out the memo's hash is dropped, and one decay step later (twice the ttl) the memo is evicted, its value at `<p>:memo` and its record at `<p>:cache` with it, and its readers are woken. Its `watch` paths register through the scheduler's registrar when it is written (Pending, then Active; a path not there yet is watched through the nearest directory above it that is, and its creation is a change) and, as every instance's watches, only while it is Active: a change to one drops the memo's hash and wakes the namespace at the memo's directory, and entering decay lets go of them, so `introspect watches` reports none once every memo has decayed. A write-back naming a path the memo already watches keeps its registration. A memo with no `ttl` is watch-only, Active for twelve minutes and then down its provider's `_.decay` ladder, evicted about six hours after its write at the default depth. A write that displaces memos above or below its address at that directory takes their entries too, and a configuration reload leaves memos alone. `introspect demand`, `lifecycle` and `timers` give a static address's entry its `node` (`{"source": "memo", "node": "context", …}`; a put with a ttl too), `comb check lifecycle` names it `kubecontext.context (<dir>)`, and a memo's `comb status` row is a lifecycle row. The eviction of a directory's last memo unlists the directory, so a data or template write no longer looks there for memos to invalidate.
- **`watch()`, `ttl()` and `cache()`: a client template memoises its value.** A leaf piped through `| cache()` renders once per change instead of once per read: `{{ 'kubectl config current-context' | watch((env.KUBECONFIG or '~/.kube/config') | split(':')) | ttl('10m') | cache(env.KUBECONFIG) | exec() }}`. `watch(paths...)` records the files whose change invalidates the memo (a string or a list of them; `none` and `''` add nothing; with no argument the piped value; `~` the render's `HOME`, a relative path against the render's directory, canonicalised when it is there), `ttl(d)` how long it is valid (whole seconds, at least `1s`), and `cache(inputs...)` hashes its inputs (the piped value when it has none) and each watched file's stamp as it is now. When the memo the daemon holds for the leaf (the `get` response's memo half, found up the directory chain) is live under that hash, the render ends there and the leaf's value is the memo: nothing after `cache()` runs, so a hit costs no spawn and is served even where `exec()` is off. Otherwise the leaf renders, and its final output, absence included (a memo of absence), is written back with the `memo` op at the read's directory after the value is computed; a leaf that fails writes nothing, `--force` renders past the memo, a stale memo or one whose hash was dropped is a miss. A hit is as old as its memo. The hit ends the render as an error carrying the memo, which the one evaluator turns back into the value in every form: one `{{ }}`, statements before it, and inside an imported macro. `comb eval`, `-f` and `bc_eval` store nothing of their own text: there the three pass their input through (a field they read whose template caches is read as every read of it is). The three are a new tier of the template library, `memo`, on the client alone: on a Source's `root`, `data` or `result` line they are a load error (`cache(): a client template's filter; a Source's records are the daemon's`), a provider's line refuses `cache` as it refuses IO, and a Source's `return` keeps its `watch` and `ttl` decorators. A client template that calls `cache()` and is not one expression is a load error, and a `put` to `:template` is refused for it (`a cached leaf is one expression: {{ … | cache() | … }}`); a `cache()` that ends its tag is a warning (`cache() with nothing after it stores a value already computed`). `libbeachcomber::resolve::Fetch` gains `memo(&MemoWrite)`, which `Client`, `Session` and the watch fan-in implement with the `memo` op; `resolve()` and `eval_with()` write their memos back before returning, `resolve_traced()` leaves them in `Traced::memos` for the caller to write after it has handed the value on (`resolve::write_back`), and `Traced::memo_hit` says whether the addressed leaf was served from its memo. `libbeachcomber::eval::used_names` is the one scan of the names a line calls or pipes into (it was the provider lint's). See "Caching a template" in `website/docs/reference/template-library.md`.
- **`sys`, a plugin compiled into `comb`, for what only the operating system can say.** `plugin('sys', '<symbol>')` in a Source's `data` line answers `hostname` (`{name, short}`), `loadavg` (`{one, five, fifteen}`), `uname` (`{sysname, release, version, machine}`), `uptime` (`{seconds}`), `user` (`{name, uid}`, `name` absent for a uid with no entry), `network` (`{interface, ip, ipv6, vpn_active, vpn_name, ssid, online}`) and `battery` (macOS `{percent, charging, status, time_remaining_secs}` from `pmset`; Linux `{percent, charging, status_raw, status, time_remaining_secs}` from sysfs, the estimate from the driver or the energy or charge over the rate; `{}` with no battery). Each symbol is a plugin symbol of the one C ABI, held in a table in the binary: the call takes the path a library's does, from the engine function through `call_symbol` (which the `dlopen` path now uses too) to the C call, and only the finding of the function differs. A symbol takes no arguments (given any, it returns `NULL`), answers an object and leaves out what the machine has no value for; its answer lives in a thread-local string of its own until its next call on that thread, so it takes no lock. The name is reserved: `sys` is never looked for on `[daemon.plugin] path`, and `comb check config` warns of a `libsys.dylib` or `libsys.so` there (`[daemon.plugin] path: <file> is shadowed by the built-in sys plugin, and never loaded`). On Linux, `network` takes the preferred interface from `/proc/net/route`, not `ip route`. The built-in `hostname`, `load`, `uname`, `uptime`, `user`, `network` and `battery` providers read the OS through the same functions until their shipped files replace them; what they answer is unchanged.
- **The `:memo` facet, the `memo` op, and the memo half of a read — the daemon's half of caching a template.** A template leaf whose expression pipes through `| cache()` has its value stored daemon side by the client that rendered it: `{"op":"memo","key":"<p>.<f>","path":"<dir>","hash":"<16 hex>","data":<value>,"watch":["/abs/path",…],"ttl":"10m"}` writes the leaf's memo for the reader's directory — its value at `<p>:memo.<f>`, and its record at `<p>:cache.<f>`: the client's `hash`, the `watch` paths, and with a `ttl` (whole seconds, at least `1s`) `poll` `{interval, count: 1}` and `decay` 1 — replacing any memo at that address, or above or below it, there. The key is a provider's field (a facet or a bare provider is refused), the hash sixteen lowercase hex digits, each watch path absolute. A memo may record absence: a leaf that rendered nothing stores a record with no value, never `null`. A `get` that carries a template half carries the memo half beside it, `memo`: `{hash, stale, age_ms, data}` for a string template (`hash` absent once dropped, `data` for a memo of absence), a tree of those shaped like a group, found up the chain from the requested directory, nearest first; a watch frame carries it too, and is sent when it changes (a dropped hash is a frame; an older age is not). `<p>:cache.<f>` of a template leaf with a memo answers `source: memo` with the memo's age and stored keys; `comb get <p>:memo[.<f>]` reads the values, each aged by its memo; `layers` (`comb status --tree`) lists a template leaf's memo records first, the nearest the answer while it has its hash and is within its ttl; `comb status` shows each memo with a value as a `<p>:memo` facet row, SOURCE `memo`. The daemon drops a memo's hash, keeping its record and value and notifying the namespace's watchers at its directory, when the leaf is invalidated: a `put`, removal or reseed of `<p>:template` at or above it, a data write at or under it (a `put`, its removal or expiry, a configuration seed, a Source's run), and `comb refresh <p>[.<f>]`, which drops every such hash at every directory and is now ok on a key with no Source when a memo was there. A `put` to `<p>:memo` is `<p>:memo is written by cache(); edit <p>:template.<f>, or refresh <p>`. The protocol version stays `1.0`: the response field is additive and the op new. `libbeachcomber::resolve::Got` gains `memo`, and `protocol::Response::with_template` is `with_halves(template, rest, memo)`. BREAKING (wire): `memo` joins the closed facet set, so the refusal reads `invalid facet key: <head> (a facet is template, macro, memo, put, source or cache)`.
- **A config Source's stat inputs are the files its lines read.** A record was checked on a read for its Source's `watch(...)` declaration only, whose paths are constants, so a config Source could not name a file its lines computed (a linked worktree's `HEAD`, `env.AWS_CONFIG_FILE`, a file named by a hash), and a Source that only polls was checked for nothing but its lifetime. Now each file a Source's `data` and `result` lines read is an input of the record its run makes, stamped immediately before it is read, beside the declared ones (stamped before the run, as before; a path both declared and read keeps its declared stamp). `read`, `stat` and `realpath` read their path; `lup` every path its walk probed, hits and misses (a marker made nearer is a change), with `git=true` also each `<dir>/.git` it read to find the root; `glob` each directory it listed, as a node, and each literal component it found missing or ended on. The next read after a rewrite of such a file answers the new value, 100 times in 100, with no `watch()`; while nothing changes, reads run nothing. A run reads at most 64 files that count: past that a file is not checked and the daemon logs once per Source (`<p>.<s>: 150 files read; the first 64 are checked on read`). A read that finds an input changed takes the run in flight only if what that run has read so far is still as it was. A client's render (`comb get`, the SDKs) keeps no account and changes in nothing; a `root` line's walk is not an input (its root is kept by the registry); what an `exec` child reads is still not checked. A `cache::Stamped` holds `libbeachcomber::fs::Touch` stamps, each with the moment it was taken (a stamp's racy window runs from its own); `Stamped::and_read` adds what a run's lines read to what it declared.
- **A client template imports macro libraries.** `{% from "scanline:macro.usage" import usage %}` and `{% import "scanline:macro.rate" as rate %}` read a library by its address, written as a string, in every template the client renders: a leaf, a `put` to `:template`, `comb eval`, `-f`, a `comb status` row and an SDK's `get` and `eval`, which go through `resolve` with no ABI change. Before a render the resolver reads the template's imports and theirs, each address once through its memo, and the one engine of the resolution loads them by name. A library renders in the importer's context, so what it reads is read for the importer, and a `comb[...]` in it makes the read lazy. A library is a dependency, so `comb watch` re-renders when it is edited, and it is text, so its age is no value's. A library nothing answers fails that value (`<key>: scanline:macro.rate: no macro library there`) and a group omits it; something other than a string there is a configuration error; an error inside a library gives its own words and place (`(in scanline:macro.rate:3)`), not the import's; two libraries importing each other end in `recursion limit exceeded`. Conformance fixtures `get/macro_import.json` and `eval/typed_after_statements.json` run in every SDK.
- **Macro libraries and the `:macro` facet.** `[client.providers.<p>] macro.<name> = '''…'''` declares a macro library: a string under a name the name rule allows, holding `{% macro %}` definitions, top-level `{% set %}`s and imports of other libraries. Each layer seeds its libraries at `<p>:macro`, labelled with its file, so a later file replaces one library and keeps its siblings, and a provider named only by its macros is a provider. A library is linted as a client template is, and prints nothing: one that does not compile, or has text, a `{{ }}` or a `{% call %}` outside a `{% macro %}`, is a load error (`config(<file>): [client.providers.p] macro.x: …`) and is not seeded; one, or a template, that imports a library no layer declares is a warning. `comb get scanline:macro` reads every library of `scanline` and `scanline:macro.rate` one text, nearest directory first, with no template half; a `put` there is checked as configuration is. `macro` under `[daemon.providers.<p>]` is `unknown key`, and `facet('macro', …)` on a `return` is accepted and ignored. Facet rows show each library per layer under `comb status -a` or `--filter facet=macro`, and `check config --origins` lists them. BREAKING (wire): `macro` joins the closed facet set, so the refusal reads `invalid facet key: <head> (a facet is template, macro, put, source or cache)`. See `website/docs/reference/macros.md`.
- **Macros within a template; `include`, `extends` and `block` refused.** `{% macro %}` and `{% call %}` work in every line comb renders: a client template, a Source's `root`, `data`, `result` and `return`, and a provider's `template`, `result` and `return`. A macro returns the text its body prints. `{% include %}`, `{% extends %}` and `{% block %}` are refused on every line (`{% include %} is refused: text is reused with a macro`): a load error in configuration, a refused `put` to `<p>:template`, and a compile error (exit 2) in `comb eval` and `-f`. A daemon line cannot `{% import %}` or `{% from %}` (`macros are client templates: a Source's line cannot import`), and a client template's import names its library as a string, `"<p>:macro.<name>"`. No template's name turns on escaping. See `website/docs/reference/macros.md`.
- **The PUC-Lua subprocess tier honours `env`, the socket, colour and `exec`, and offers `eval`.** A call's `opts.env` is the spawned `comb`'s whole environment (the command runs as `env -i K=V …`, every pair shell-escaped, with the absolute path to `comb`), where a `get` with an env used to be `unsupported`; with no `env` it is the process's, as under ffi. `--socket`, `--color` and `--no-exec` are passed as for the Node tier, and `eval` is one `comb eval -f json -- <template>`. `watch` stays refused, and the reason given for it is corrected: `io.popen` has no timed read and no cancel (the old comment blamed block buffering, but `comb watch` writes a line per frame; the hang it saw was a key that missed and printed nothing). The Lua conformance runner now skips only `hello`, `introspect` and `watch`.
- **The Node subprocess tier offers `watch`.** `client.watch` without `koffi` no longer throws `UnsupportedError`: it spawns one long-lived `comb watch -f json <key> [--path P | --global]`, as `get` is spawned (the call's `env` map as its whole environment, `--socket`, `--color`, `--no-exec`), so every event is the value the FFI tier's watch answers and a miss is the event `null`. `nextEvent(timeoutMs)` waits for the next line against a timer and is a `TimeoutError` when it runs out; the child exiting 0 ends the stream (`null`), and exiting 2 is a `ServerError` in the daemon's or the resolver's words. `cancel()` and `close()` send the child SIGTERM, and `close()` is idempotent. The `watch/*` conformance fixtures now run on the subprocess tier.
- **`comb eval -f json|text|sh`, and the Node subprocess tier offers `eval`.** `eval` takes the value formats `get` and `watch` print in, through an `eval_format` value parser (`e.j` and `e.s` work as suffixes); text stays the default. `-f json` keeps a number a number and prints `null` for an absent value. The Node tier's `eval` is one `comb eval -f json [--path P | --global] -- <template>`, spawned as its `get` is, so the `eval_*` conformance fixtures run on it; a template that does not compile is a `server_error` there, where FFI reports `parse_error`.
- **`comb --no-exec` - render with `exec()` off.** A global flag, beside `--color` and `--socket`. `get`, `eval`, `watch` and `status` build their resolution inputs through one `cli::inputs`, which reads it; a template that calls `exec()` then fails with `exec() is disabled in this context`, and a `status` row renders as failed. Without the flag nothing changes. It is how a subprocess-tier SDK honours a client whose `exec` is off.
- **A Source's watches register off the scheduler loop, and each is Pending, Active or Failed.** The scheduler registered a watch inside its own loop, awaiting the kernel: FSEvents takes from milliseconds to seconds on a loaded host, and for that long the loop took no message and its heartbeat stopped. Measured with a 20 000-file tree on the polling backend, a 1.4 s registration left a tick 868 ms late and a status request waiting 1.37 s; a native registration after a first read held an `introspect watches` for 5–56 ms. A worker thread now owns the watcher and makes every registration while the loop goes on (the same tree: the latest tick 0.7 ms late, the status request 10 ms; the `introspect` 0.04–0.27 ms). `comb check watches` (`introspect watches`) shows each path as `pending` until it is made, then `active` or `failed` with its error; a failed one is asked for again by the next read of a Source that watches it, and `comb check daemon` warns of it. A watched path that does not exist yet is watched through the entries of the nearest directory above it that does (`active`, `via` that directory), so its creation runs the Source, where before the registration failed and nothing ever saw the file appear.
- **`comb check config --origins [KEY]` — how the configuration came together.** Every leaf of the composed configuration — `[daemon]` settings, Source and provider lines, `_` prototypes, `enabled`, `cache._.decay` and `[client.providers.*] template.*` — is a row with its key in key form (`daemon.providers.git.sources._.return`, a name holding a `.` as `template['a.b']`), the file that set it and its value, and beneath it every earlier file that set the same leaf and was overridden, marked `shadowed`, the one it overrode first (`conf.d/` last to first, then `config.toml`, then `defaults/`), drawn as `comb status --tree` draws a value's layers. A setting no file sets that `comb` gives a value of its own (`daemon.log_level`, `daemon.provider_timeout_secs`, `daemon.budget.execute`, `daemon.plugin.path`) shows `default` as its file. `KEY` limits the rows to that key and what is below it. `-f json` prints one object per leaf, `{key, value, file, shadowed: [{file, value}]}`, `file` absolute or `null` for a default; `--color` and `--ascii` work as for `status`, and each of these options is a usage error without `--origins`. It reads the files as the daemon composes them and needs no daemon; a file that cannot be read or parsed, or breaks a rule, is reported as `comb check config` reports it and exits 2, while the files that loaded are still shown. Before, the cache's `config(<file>)` label named only the file that won a leaf, and nothing showed what it overrode.
- **`comb status --tree` — the layers behind each value.** Each value row is followed by the layers a read of it consults, in the read's order: the template records (`:template`, nearest directory first), a leaf a provider line computed, then for each directory nearest first its `put`, its `config(<file>)` seeds and the Source records at the instances the read reaches (cascade and `| nearest` as for a read). The layer that answers is drawn plainly and the rest are dimmed, or marked `shadowed` in FIELD with colour off, under `├─`/`└─` (`|-`/`` `- `` with `--ascii`); each layer shows its label, raw value (a template's expression), PATH and its own AGE. A row on the caller's directory chain is read from the caller's directory; a row stored elsewhere from its own. `--tree` destructures to leaves unless `--depth` is given, and works with `human`, `table` and `json` (each row gains a `layers` array); any other format is an error. The stacks come from a new protocol op, `{"op":"layers","key":…,"path":…}` — a tree shaped like the value with an ordered `[{label, facet?, path, value, age_ms, stale, answered?}]` at each leaf, warming nothing and signalling no demand, like `:cache` — with `layers` on `libbeachcomber`'s `Client` and `Session`. It is CLI-only: no SDK or C ABI function binds it.
- **An edit under `providers` reloads the running daemon; only the bare `[daemon]` and `[client]` keys restart it.** A change that touches only `[daemon.providers]` or `[client.providers]` (Sources, `template`/`result`/`return` lines, `cache` tables, `enabled`, a provider newly named or no longer named) no longer restarts the process: the config watch builds the new providers once (the load that gates the edit is the one the reload uses), plans the reseed of the template and `cache` facets, and only if both are sound swaps them in, so an edit that cannot be seeded changes nothing. The scheduler then brings its lifecycle entries to match, and puts the new providers in force for requests. A Source that is gone, whose provider is now disabled or whose body changed (its `root`, `data` and `result` lines, `_` prototypes included) is evicted with its records, stored `:cache` keys, watches, kept roots and failure state, and runs on the next read that asks for it, so an edited body is served at once; a Source whose schedule changed (`poll`, `watch`, `failback`, `ttl`, `budget`, `nearest`, or the decay depth that applies, so a `cache._.decay` edit retunes the provider's instances) is retuned in place: it keeps its records and place in the lifecycle, registers its new watches at once and restamps the schedule stored with its records without running; every other Source keeps its records, timers, watches and failure count. A run in flight that the reload overtook (its Source evicted or retuned) writes nothing and goes again under the new providers, and a run that spans a reload still reads the Sources it calls. Kept `root`s are worked out afresh, `put`s are untouched (the namespace of a removed provider that still holds puts stays reachable), loaded plugin libraries stay loaded, a request in flight finishes on the providers it began with, and a `watch` stream works out again what it reads. An edit whose providers do not load changes nothing. A provider named only in a root is registered and unregistered by the reload. A change to `socket_path`, `log_level`, `plugin.path`, `budget.execute`, the watchdog keys, `idle_shutdown_secs` or any other bare key of `[daemon]` or `[client]` still restarts the daemon.

- **`[daemon.providers.<p>] enabled = false` switches a provider off.** It sets the provider's `result` to `"{{ {} }}"` and its `return` to `"{{ result }}"`, and none of its Sources is selected, called or run: a `get` of it (or of a field) is a miss with no template half, so a template-only provider (`aws`, `op`, `conda`, `gcloud`, `kubecontext`, `talos`) switches off the same way, and nothing executes, polls, watches or keeps warm any Source of it. It works on built-in providers (`[daemon.providers.git] enabled = false`). `comb refresh <p>` is `nothing to refresh: <p> is disabled`, `comb get --force <p>` is an error as for a static namespace, and `comb check providers` marks it `disabled`. The `<p>:template` facet is still seeded and readable by name, and a `put` under `<p>` is still read. A call to a disabled provider's Source, `daemon.providers.<p>.sources.<s>()`, is a miss that runs nothing and not a load error, since a later layer may set `enabled = true` again (layers replace the key like any other). `enabled = false` wins over a `result` or `return` on the same provider (both are still checked, not read). `enabled` must be a boolean; it is an error on `[daemon.providers._]` and on a name no built-in, Source or client template gives a provider, and stays an error anywhere else.
- **A Source or provider line may call a Source.** A Source's `data` line reads a sibling with `sources.<source>()` and any provider's Source with `daemon.providers.<provider>.sources.<source>()`; a provider's `result` and `return` lines read the latter, so `return = "{{ result | merge(daemon.providers.gitstats.sources.repo()) | facet('template', template) }}"` loads. A call answers with the called Source's stored record as a read of it from the same directory would (a cascading Source merges up its chain, a `| nearest` one answers alone), without any `put` over it. A Source with nothing stored is run inline once, by the read or refresh that needs it (callers racing for it take turns, and it runs once); a provider line's calls are warmed by the `get` before it renders, and a `watch` or `:cache` read runs nothing and renders no `root`. A called Source is kept warm while it is called: a read demands it, and demanding a Source demands what its last run called, however that run ended (a poll of the caller does not, and a branch not taken calls nothing), so it is polled and watched on its own schedule and decays with its caller, staying at its last decay step while a caller that is still cached names it, and a `watch` follows it. `get --force` and `--wait` reach the Sources a provider's lines call. What a line computes from a called record is as old as the record. A called Source's own failure is the caller's miss, an instance of a cascading Source that fails included: the call goes on up its chain, as a direct read does. A Source cannot call itself, a call to an unknown provider or Source is a load error naming it, and Sources that call each other in a ring are a load error naming the ring (the runtime error `sources: <p>.<s> calls itself` stays as a backstop).
- **Provider lines — `template`, `result`, `return` — and the abstract provider.** `[daemon.providers.<p>]` takes three jinja lines, and `defaults/00-comb.toml` now carries the abstract provider `[daemon.providers._]` that every provider without a line of its own takes: `template = "{{ client.providers[_.name].template }}"` joins `[client.providers.<p>] template` in as the `:template` facet (rendered once per configuration layer over that layer's `[client]` tree, labelled with the layer's file), `result = "{{ merge(sources) }}"` merges the provider's own Sources at read time (`sources.<s>()` is that Source's stored record where the read stands, or none), and `return = "{{ result | facet('template', template) }}"` hands the data out with the facet beside it. `facet(name, obj)` attaches `obj` as the facet `name`, one of the four; only `template` is consumed, so a `return` that never calls it carries no template half. A provider may override any line; `_.name` is the provider, and `| super` pipes a value into the `return` one step up (on a `template` or `result` line, which is the whole value, it is a load error). What `return` gives is what the provider answers, and a field read addresses into it (`return = "{{ result | merge({'x': 1}) | facet('template', template) }}"` makes `comb get p.x` answer 1); under any `result` or `return` other than the shipped ones a field read demands every Source, since the line decides what exists. The shipped lines are done natively, not rendered, so a default read costs what the old merge did. A provider with no Sources renders its `result` once at the global entry (a literal answers; the default gives nothing). In an explicit `merge(sources.a(), sources.b())` the last Source wins and two Sources may declare the same field; the default merge still refuses that at load. A schedule decorator, `exec`, `read`, `lup`, `url` or `plugin` on a provider line is a load error (the lines run on every read and do no IO), and a line that fails to render is a miss (for that layer, for `result`; for the whole read, for `return`, which never falls back to the data), logged once per distinct failure. A Source's `comb.<p>` sees what a `get` of `<p>` answers, `return` included. A leaf an explicit `result` or `return` computes is labelled `computed(result)` / `computed(return)` in `:cache`, with no decay, and is as old as the oldest input behind it. Within a layer a provider's Sources now merge in declaration order (a config Source's is its name order) where they merged in name order: this differs only for built-in Sources that overlap on a sentinel field.

- **Sources as functions — `[daemon.providers.<p>.sources.<s>]`.** A Source is `root`, `data`, `result` and `return`: `data` is the body, a jinja line on the daemon's engine (`exec`, `url`, `plugin`, `read`, `lup`) that sees `env` (the daemon's own, never the caller's) and `comb.<provider>` (the provider as a `get` of it answers: put over source, through its `return` line, a cold Source run first); `result.<field>` lines shape it into fields, or `result = "{{ data }}"` owns the whole provider node; `return` is the result with decorators (`poll`, `watch`, `ttl`, `failback`, `budget`) that say when it runs again. `root` names the directory an instance answers for; empty is the one instance at `~`. A table named `_` is a prototype: `[daemon.providers.<p>.sources._]` for `<p>`'s Sources, `[daemon.providers._.sources._]` for all; a Source's own line wins whole, an absent line takes the nearest `_`'s, and `| super` extends it. The abstract Source ships in `defaults/00-comb.toml` (`poll('60s', 12) | failback('1s', 3)`). A new Source table may be added to a built-in provider; two Sources of one provider may not declare the same field; a broken `return` chain (including an unused `_`) is a load error naming its table. Config Sources are built from the composed layers: `result.<field>` in `conf.d` replaces one expression, a `return` line replaces the schedule whole, and removing a file removes what it added. A request whose path resolves through a `root` line no longer holds an async worker. A Source with no `return` anywhere is watch-only with the engine's `failback` and `budget`. The config self-watch runs startup's checks before a restart: a config the daemon would refuse to start on is logged and the running daemon stays up.

- **The `:cache` facet — the daemon's metadata about a field, as a tree.** `comb get git:cache.branch` answers `{age_ms, stale, source, …}` for the record `git.branch` resolves to at that path, so a value is never reported with another record's metadata. It mirrors `git.<path>` at any depth: a leaf answers with an object and an object node with the tree of its leaves' answers. `age_ms`, `stale` and `source` are derived at the read (`source` is `put`, `template`, `config(<file>)`, `computed(<line>)` or `source(<name>)`, e.g. `source(head)`); `poll` (`{interval, count}`), `watch` (an array of patterns) and `decay` are stored when a Source registers or a `put` carries a `ttl`. A value served by a template reports `stale` false and `source` `template`, and no `age_ms`: the client renders it, so it is as old as the inputs that render reads, which the daemon never sees (`comb status` shows that age on the rendered row). A `:cache` key cannot be refreshed, a watch on it wakes on a write to its namespace, and a `put` to it is refused except for a `_.decay` prototype (`<key> is derived and cannot be written` for `age_ms`/`stale`/`source`, `<key> is written by the daemon` for the rest).
- **Layer facets — `<p>:put` and `<p>:source`.** A field's value is the first layer that has it: the effective template, then `put` (what `put` and the `config:` seeds stored), then the Source. Each of the last two is readable on its own, with the provider's shape, at any depth — `comb get git:source.branch` shows what the Source computed even where a `put` hides it. Both are read-only (`git:put and git:source are read-only; write git.<node>`), never warm a Source or start a lifecycle, and `refresh` on one is `cannot refresh <key>: a layer facet is read-only`. `put` and `source` are therefore not valid facet names for a config table.
- **Decay depth is data — `<p>:cache._.decay` and `*:cache._.decay`.** The fixed four-step ladder is now a number stored in the `:cache` facet: a Source takes the nearest `_` prototype, looking at each directory from the requested one up to `$HOME` for `<p>:cache._.decay` and then `*:cache._.decay` (every provider), and 4 when there is none. `comb put '*:cache._.decay' 3`, `comb put git:cache._.decay 6 --path ~/proj`, and `comb get git:cache._.decay` read it back; a value other than a positive integer is refused. A lifecycle fixes its depth when it registers, so a prototype put afterwards applies to instances registered after it. A `put --ttl` stores 1. In configuration the line is `[daemon.providers._.cache._] decay = 4` (shipped in `defaults/00-comb.toml`) for every provider, or `[daemon.providers.<p>.cache._] decay = N` for one; a reload retunes the instances it applies to.
- **`fg`/`bg` jinja filters — hex colour to truecolor SGR at use.** `{{ "text" | fg("#rrggbb") }}` wraps `text` in `\x1b[38;2;R;G;Bm` ... `\x1b[0m`; `{{ "text" | bg("#rrggbb") }}` is the same with `48;2`. Comb values store colours as `#rrggbb` hex (e.g. scanline's published theme) so a stored colour stays in one canonical format; a consumer rendering to a terminal — a shell prompt, a statusline template, `comb eval` piped into a prompt string — converts at the point of use instead. The `#` is optional and hex digits are case-insensitive (a value may arrive already stripped); anything else is a filter error naming the offending value, not silent passthrough. Empty input text returns the empty string with no escapes emitted, so a conditional colour segment composes cleanly. Registered in `filters::build_env()` alongside `truncate`/`basename` — pure string transforms, safe on every surface with no `exec()`-style gating needed.
- **The Source engine — the functions a Source's lines are written in.** `data`, `result` and `return` run on one jinja engine: `exec` (below; a string under `sh -c`, or a list as argv, and the filter `cmd | exec()`), `url(address, method='GET', headers={}, body=none, timeout='10s')` (daemon only), `plugin(name, symbol, args...)` (daemon only, on `[daemon.plugin] path`), `path | read` (a file's text, or none), `lup(name, all=, files=, dirs=, follow=, git=, root=)` (the nearest path called `name` at or above the instance's directory, stopping at `~`), `fromjson`, `fromini`, `merge` (as a filter, or `merge(a, b)` / `merge(list)`; the last wins), `map` over objects (`obj | map('filter', args…)` keeps the keys), `pluck('a.b[0]')`, `dirname` and `tojson`. All but `url` and `plugin` also render on the client, in a template. `env` in a Source is the daemon's own and `comb.<provider>` reads the provider as a `get` would; a provider's own `result`/`return` lines get the pure subset and do no IO.
- **`exec()` — spawn a command from a value expression.** `exec(cmd, timeout='10s', stdin=none, sh='sh')` takes one command: a **string** runs under `sh -c` (`sh=` names another shell), a **list** is argv with no shell (`exec(['git', 'rev-parse', 'HEAD'])`, each element exactly one argument). `'cmd' | exec()` is the same call as a filter; a command from both the pipe and an argument is an error, and so is more than one positional. The child's environment is exactly the render's `env` map (the `comb` process's environment for the CLI, an SDK's `env_json`) — `$FOO` in a string and `env.FOO` read the same value — and its working directory is the render's. It returns the command's stdout: lossy-UTF-8 decoded, with at most one trailing newline (and a preceding `\r`) stripped. Every list element is coerced to a string argv entry: a string passes through as-is, a bool becomes the literal `"true"`/`"false"` (not minijinja's `Display`, which would print `True`/`False`), and a number renders in its canonical string form; `undefined`/`none` (typically a missed daemon ref reaching `exec()` un-guarded), a sequence, or a map is a positioned error — structured data goes through `stdin=` instead, which must itself be a string (`| tojson` first). `timeout` is a duration (`'2s'`, `'500ms'`, or a number of seconds) defaulting to `'10s'`; a command that times out, exceeds the 1 MiB stdout cap, or exits non-zero is an eval error naming the command and carrying truncated stderr. `exec()` is registered wherever a value expression is evaluated, but only *runs* where the evaluating surface opted in: `comb get`, `comb eval`, `comb status` and `comb watch` enable it (the CLI user already has a shell — canon `field_resolution.md` invariant 15 names all four), and so does an SDK client constructed with `exec` on (below); every formatting surface (`-f fmt`, `watch -f fmt`, `comb status`'s per-row `-f fmt` context) and an SDK client without the option register the same function name but keep it disabled, so a call there fails at the call site with `exec() is disabled in this context` rather than a generic "unknown function" error. Evaluation of a template is client-side. A Source's `data` line runs it on the daemon, where `env` and the child's environment are the daemon's own (its `env_file` included). `$BAR` inside a string is the shell's expansion of that environment and invisible to the engine, so prefer `exec('cmd ' ~ env.bar)`, which writes what the command reads into the line (a future `cache()` hash of the line would otherwise miss it).
- **`git` provider: `lineage` source — how far a branch has moved from the branch it came from.** Six new path-scoped fields, polled every 60s. `branch_parent` is the branch this one was forked from, read from the oldest `branch: Created from <X>` entry of the branch's reflog when X names a local branch that still exists; otherwise it is the default branch. `lines_added_parent` / `lines_removed_parent` are the `git diff --numstat` totals from the merge base with `branch_parent` to `HEAD`. `branch_default` is the default branch, from `origin/HEAD` or whichever of `main`/`master` resolves, and `lines_added_default` / `lines_removed_default` are the same counts against it — when `branch_default` came from `origin/HEAD` the comparison is against `origin/<name>`, so a checkout sitting on the default branch reports its unpushed work. These counts describe committed divergence in the commit graph, not the working tree, which `lines_added` / `lines_removed` already cover. The merge base is `git merge-base --fork-point`, falling back to plain `git merge-base` when the reference branch's reflog is missing or pruned. A detached HEAD emits no lineage fields; a repository with no detectable default branch emits no `*_default` fields. Linked worktrees resolve the parent through the common dir, where branch reflogs live. Git now has five sources: `head`, `refs`, `diff`, `lineage`, `status`.
- **`comb check --connect-timeout <DURATION>`** bounds how long a check keeps trying to reach the daemon before reporting it unreachable: `0` for a single attempt, or `250ms`, `2s`, a bare number of seconds. Default `1s`. Accepted before or after the subcommand. Previously `comb check daemon` against a stopped daemon inherited the client's full restart-window retry budget (1.75s) before printing FAIL.
- **`put` writes at any node — `comb put <namespace>.<node…>`.** A put key is now the same dotted address `get` takes: `comb put my.deploy.status '"green"'` writes one record inside `my.deploy`, and `comb get my.deploy` reads the object back. Intermediate objects are created as needed, and a scalar standing in the way of the address is replaced by the object the write needs. Because a node below the root is a value rather than a map of records, `data` there may be any JSON — a string, a number, a bool, an array, an object. At the namespace root it must still be an object; a scalar there is `put data at the root must be an object`. A `null` put addresses a node too, so `comb put my.deploy null` drops just that subtree and leaves its siblings; at the namespace root it drops every static record of the entry, and the entry itself survives if a Source still contributes to it. Both halves of an address are depth-capped, because a key arrives off the socket with no length bound of its own and each of its segments is one step of a tree walk: the node may carry at most `MAX_JSON_DEPTH` (10) segments — beyond that is `put key is nested too deeply (limit 10 segments)` — and the value below it is converted to that same depth, so a record's total tree depth reaches at most twice the bound and the walk is bounded either way. On the wire this is `Request::Put`'s existing `key`; `libbeachcomber`'s `Client::put`/`Session::put` need no change to use it. The SDKs are untouched.
- **Every `get` returns the node's template half — `template` and `rest`.** A `get` on a key whose namespace carries no facet now does two lookups at the requested path: the data at the addressed node, as before, and the same node in the merged tree of that namespace's `template` facet (`<provider>:template`). Whichever exist come back, so `get scanline.widgets.foo` on a namespace holding only templates is `{"ok":true,"template":"{{ env.SCANLINE_FOO }}"}` — a hit with no `data` at all, not a miss. `template` is a JSON tree whose string leaves are value expressions the **client** renders and whose objects are groups; the daemon never renders one. Walking the key through that tree: landing on an object or a string with the key consumed makes that node the `template`; landing on a string with segments left over makes that string the `template` and returns the unused remainder as `rest`, so `get scanline.stats.cpu` against `stats = "{{ {'cpu': 40, 'mem': 12} }}"` answers `{"ok":true,"template":"{{ {'cpu': 40, 'mem': 12} }}","rest":"cpu"}` and the client applies `cpu` to what the expression renders. A miss, or a non-string scalar — in the way, or *at* the address — attaches nothing, though a non-string leaf **inside** a group is passed through untouched as part of that group. A sub-path the data half cannot resolve (`get box.widgets.foo` where `box.widgets` is an object with no `foo`) is a miss only when no template answers there either — the template half is read first and decides. The two halves are addressed from different places: the data half sits where the provider's records live (scope-narrowed — the global entry for a provider with no path-scoped source, the project root for one that walks to it), while a template is a static record and so is read from the **requested** directory itself and resolves up the chain from there, so `get git.branch --path <repo>/sub` reads git's records at `<repo>` and its templates from `<repo>/sub`. A bare `get p` returns the whole template tree. A `get` on a facet key (`p:template.widgets.foo`) is already inside a facet and reads its records as plain `data` — it never carries a template half. `watch` frames carry the same two halves, so a streamed value renders exactly as a fetched one: a write to a namespace or to any of its facets wakes the namespace's watchers, and frames are deduped on **both** halves, so editing a template alone delivers a frame carrying the new `template` and no new `data`. A namespace is answered when a record for it — or for its `template` facet — sits anywhere on the chain, so a namespace whose daemon provider was retired still answers with its templates.
- **Facet keys — `provider:facet`.** A provider name containing exactly one colon addresses a facet: a namespace holding data about the provider (e.g. `scanline:template`), addressed, stored and read like any other name — the colon is just part of it. Syntax is checked at the request boundary for `get`, `put`, `refresh` and `watch`: the facet after the colon is `template`, `put`, `source` or `cache` (see Changed), and anything else (another name, a second colon, an empty base or facet) is rejected with `invalid facet key: <head> (a facet is template, put, source or cache)`. `template` is the facet a `get` resolves for its template half.
- **Configuration seeds the `template` and `cache` facets, with a `config:<file>` label per record.** Every `[client.providers.<p>] template` table is written into the cache at namespace `<p>:template`, and every `[daemon.providers.<p>.cache._] decay` at `<p>:cache._.decay` (`*:cache` for the abstract provider `_`; the shipped `defaults/00-comb.toml` sets `[daemon.providers._.cache._] decay = 4`), at the global path when the daemon starts, before it serves — so `[client.providers.python] template.venv_name = "{{ python.venv }}"` makes `comb get python.venv_name` answer with that template and `comb get python:template` return the tree. The TOML maps 1:1: nested tables are groups, string leaves are value expressions. Layers are seeded one file at a time in composition order (`config.toml`, then `conf.d/*.toml` lexically) rather than deep-merged first, so each record carries the file that set it: `comb status -a` shows `python:template  venv_name  config(~/.config/beachcomber/config.toml)` and `python:template  version  config(~/.config/beachcomber/conf.d/10-mine.toml)`, kind `static`. Every file keeps its own records, a leaf two files set included: a read takes the leaf from the later file in composition order (`defaults/`, then `config.toml`, then `conf.d/`), so a get, its `:cache` `source` and the `_.decay` a provider resolves are the later file's, and `comb status -a` lists a row for each file that sets the leaf. `comb status --tree` shows the earlier files' records under the answering one as shadowed, so what a file overrode is visible; removing that file shows the next one down, without a restart. Rules are checked file by file, because seeding is, and enforced at daemon start, on reload and by `comb check config`, which validates the config file itself rather than only relaying the daemon's view; each error names its file: `[client]` holds only `providers`, `[client.providers.<p>]` only `template`, and `[daemon.providers.<p>]` takes `cache` (whose only key is `_`, holding only `decay`, an integer from 1 to 16 — `put` of `<p>:cache._.decay` takes the same range), `sources`, `enabled` and the `template`/`result`/`return` lines; anything else is an error naming the key; an empty key, or a template leaf that is neither a string nor a table is an error; a provider name holds no `:` or `.` and is no reserved word (`env`, `comb`, `_`, `*`; see Changed); and the `[providers]` root, colon-named tables included (`[providers."<p>:template"]`), is `unknown table [providers]`, which says where its contents went (see Removed). A provider exists if either root names it: one named only there is a provider with no Sources (unless the config disables it). Errors keep their existing effect — the daemon refuses to start. Seeding is driven by `Config`'s new `config_path` field, which only `Config::load()` sets: a daemon handed a `Config` built in memory corresponds to no file on disk, so it seeds nothing and watches nothing rather than picking up the ambient `~/.config/beachcomber`.
- **Managed `defaults/` — the shipped templates are configuration files the daemon writes and seeds.** The built-in templates (`terraform`, `python`, `conda`, `op`, `aws`, `gcloud`, plus `kubecontext` and `talos`, whose fields are now `exec()` templates over `kubectl` and `talosctl`) live in the repository at `defaults/<namespace>.toml`, embedded in the binary only so `comb daemon` can write them to `~/.config/beachcomber/defaults/` before it loads configuration, each headed by `# Managed by comb <version>`. Per shipped name: absent → written; a marker for another version → rewritten; no marker at all → rewritten (the name is shipped, so the file is managed); this version's marker → untouched even if edited below it; per other `*.toml` in the directory: a marker → deleted (a retired default), otherwise left alone and reported as unmanaged; a directory the daemon cannot write is a refusal to start (exit 2). `defaults/` is the lowest layer of composition — `defaults/*.toml` lexically, then `config.toml`, then `conf.d/*.toml` — so every record is labelled with the file that set it (`comb status -a` shows `python:template  venv_name  config(~/.config/beachcomber/defaults/python.toml)`) and a user overrides one field by setting the same key in `config.toml` or `conf.d/`. The config self-watch snapshots the directory like `conf.d/`: an edit to a defaults file re-seeds in place, and a settings key in one restarts like anywhere else. `comb check config` reports the directory without writing anything: `PASS defaults <dir> (9 files, comb <version>)`, `WARN … <k> shipped file(s) missing or stale — the daemon writes them on its next start`, `WARN … holds <n> file(s) comb did not write`, and `FAIL … not writable: <error>` from a dry probe in the directory or its nearest existing ancestor. A `fromjson` jinja filter joins `build_env()` for `talos.toml`: `{{ (exec(['talosctl', 'config', 'info', '-o', 'json']) | fromjson).context }}` parses a command's JSON into a navigable value; text that is not JSON is a filter error carrying serde's message.
- **`libbeachcomber::resolve` — the one client-side resolver.** `resolve(key, &Inputs, &mut dyn Fetch) -> Result<Option<Value>, ResolveError>` is the single implementation behind `comb get`, `comb eval`, `bc_resolve`/`bc_eval` and every SDK: it asks the daemon for a node, gets `data` and/or `template` (plus `rest`) back, renders the template with the caller's environment and directory, walks any leftover address into what the template rendered to (an object by key, an array by decimal index), and for a whole namespace renders the template tree shape-for-shape and deep-merges it over the cached fields, rendered winning. `Inputs` carries everything a resolution reads — `cwd`, `env`, the `Slot` it addresses (`Cwd`, `Path`, `Global`), `force`, `wait`, `allow_exec` — and `Fetch` is one method over whatever transport the surface has (`ClientFetch` over a `Client`; the CLI's session), so the resolver opens no socket, reads no environment variable and parses no configuration, and its tests run against a map. Each distinct `(key, path)` is fetched once per top-level call; `resolve_with_deps`/`deps` return that set, in first-fetch order, for a watch fan-in to subscribe to. A cycle pushes every node being rendered — groups included, so a leaf referencing its own group is a cycle naming both — and `MAX_VIRTUAL_DEPTH` (128) bounds the chain. Errors are typed: `ResolveError::Config` (does not compile, cycles, too deep), `Runtime` (a failed or disabled `exec()`), `Fetch` (`Transport`, or the daemon's `Rejected` reason for the key). `resolve::eval(src, …)` renders a source that is stored nowhere with every ref resolved as it would be inside a stored template, so `comb eval '{{ p.f }}'` and `comb get p.f` agree by construction.
- **`exec` option on every SDK client — `exec()` in templates is opt-in per client.** `bc_client_new` reads `"exec": bool` from its options JSON, `ClientConfig` gains `exec: bool`, and each SDK exposes it under its idiom: `Client(exec=True)`, `Beachcomber::Client.new(exec: true)`, `new Client({ exec: true })`, `beachcomber.WithExec(true)`, `comb.connect{ exec = true }`, `bc_client_new("{\"exec\":true}")`. Default off — an embedding caller does not spawn processes on the user's behalf unless it says so — and a template that calls `exec()` on a client without it fails with `exec() is disabled in this context`. This is what lets an SDK render `kubecontext.context` and `talos.context`, which are `exec()` templates now.
- **The client library's `get` result carries the template half — `CombResult::Template`, and every SDK follows.** A raw `Client::get` now hands back the daemon's answer as it arrived: `Hit` carries `template`/`rest` beside `data`/`age_ms`/`stale`, and a node holding only a template is the new `CombResult::Template { template, rest }` variant instead of a false `Miss`; `is_hit()`/`is_miss()`/`template()`/`rest()` classify across all three. `parse_response` is now `parse_node` plus `From<resolve::Got>`, one wire parser shared by the raw and resolving paths. The FFI `get`/`bc_session_get` envelope adds `template`/`rest` to the inner object only when set — a data-only hit and a miss are byte-identical to before, and a template-only node is `{"data":null,"template":…,"rest"?:…,"age_ms":null,"stale":null}` — and every SDK result type (Python, Ruby, Node, Go, Lua, the C envelope) follows: `is_hit` stays "data present", `is_miss` becomes "no data and no template", and a template-only result — an address whose value `resolve` renders — is neither. Three new conformance fixtures (`get/template_half`, `get/template_and_data`, `get/template_rest`; 45 total) pin the three shapes with a `template` status and `template_equals`/`rest_equals` expect keys, and every runner now fails on an unknown expect key or status value instead of passing vacuously. The Lua subprocess tier cannot see the template half (`comb get -f json` prints the bare resolved value), so it reports `template`/`rest` as nil there and skips the three fixtures explicitly.
- **`tests/suite/cli_ffi_equivalence.rs` — `comb get -f json` and `bc_resolve` proven to answer identically.** One spawned daemon, one cwd and one environment map drive both surfaces for 24 keys — plain fields, templated leaves and groups, a string template walked by key and index, misses, `env.*`, `:cache` facet keys, and the four error shapes — the CLI with the map as its whole environment, `bc_resolve` with the same map as `env_json` and an `exec`-enabled client; each key's hit/miss/error classification must agree between the two and a hit's value must be equal. `comb eval '{{ key }}'` is checked the same way against `bc_eval` for six scalar hits, and every disagreement across the run is collected into one report.
- **`libbeachcomber::watch` — `ResolvedWatch`, the fan-in behind `comb watch` and `bc_watch_open`.** `ResolvedWatch::open(&Client, key, &Inputs)` opens one daemon `Watch` subscription per key the addressed key's resolution reads, and `next(timeout)` re-resolves on any frame, reporting a value only when the resolved value actually changed — a template edited under the watch fires it exactly as a changed cache record does. `env`/`env.X` is refused up front (`WatchError::EnvKey`, `env keys cannot be watched`) since there is nothing to subscribe to; a facet key (`p:template`) has no template half, so its frames are the daemon's raw stream, unrendered. `ResolvedWatch::open_owned(Arc<Client>, …) -> ResolvedWatch<'static>` borrows nothing, which is what lets a `bc_watch_*` handle outlive the stack frame that opened it. `comb get`/`bc_resolve` are clients of `resolve`; `comb watch`/`bc_watch_open` are now clients of this module the same way.
- **`comb refresh` (`comb r`) — the one daemon op the CLI lacked.** `comb refresh <key> [path] [--path <path>] [--global]` is the daemon's `refresh` op and nothing more: it re-executes only the Sources the key demands — every Source of the namespace for a bare `provider`, the one Source owning the field for `provider.field` — each at its own scope, and reads nothing back. Exit 0 and no output on success; the daemon's refusal alone on stderr and exit 2 for a key with no Source behind it (`nothing to refresh: <key> has no sources` — a `put`-created namespace, an unknown name, an unowned field). The path defaults to the current directory as `get` and `put` do, a relative path is the caller's, and `--global` addresses `$HOME`. `comb get --force` is the read-and-refresh form; `refresh` is the re-execution alone. **The Lua SDK's subprocess transport offers `refresh` again**, as one `comb refresh <key>` with the daemon's line as the error message — the op it dropped when its `comb get --force` stand-in went — so `Client:refresh` now works over both transports and the PUC-Lua conformance runner runs the `refresh` fixture instead of skipping it. **The Node SDK's subprocess transport now runs `refresh` through it too**, one `comb refresh <key> [--path P | --global]` with the same daemon-refusal-as-error-message shape, so `Client.refresh` no longer throws `UnsupportedTransportError` there and the subprocess-tier conformance run picks up `refresh/sourceless_namespace_is_an_error`.
- **`[daemon.plugin] path` — where `plugin()` finds libraries.** `plugin(name, symbol, args...)` calls a function in a shared library from a Source's `data` line: `plugin('demo', 'bc_sum', 1, 2)` loads `libdemo.dylib` (macOS) or `libdemo.so` (Linux) from the first directory of `path` that holds it, and a `name` containing `/` is a library path (absolute, or `~/...`). `path` is a list of directory strings, absolute or starting `~/`, default `["<config dir>/plugins"]`; a later file's list replaces an earlier one's. A symbol is `const char* symbol(const char* input)`: the input is the arguments as a NUL-terminated JSON array, the output a NUL-terminated JSON value owned by the library and valid until the next call into it, `NULL` is failure, and the function must not unwind (a panic out of an `extern "C"` function aborts the daemon). A library stays loaded for the daemon's life and is not looked up again, so a rebuilt plugin is picked up at the daemon's next start. Not found is `plugin(): lib<name>.<ext> not found on [daemon.plugin] path (<dirs>)`. A key other than `path` under `[daemon.plugin]`, or a `path` that is not a list of directory strings, is a config error.
- **`[daemon] budget` — how long a read waits for a Source.** Any duration of at least `1ms` (`"250ms"`, `"2s"`), default `"50ms"`; a Source whose `return` names `budget(...)` keeps its own. A read of a record past its lifetime waits this long for the record's run (see Changed, "a read waits up to its budget").
- **A built-in Source is retuned by `return`.** `[daemon.providers.git.sources.diff] return = "{{ result | poll('15s', 8) }}"` replaces that Source's invalidation, failback, decay and budget whole, as it would a config Source's; `comb get git:cache.lines_added` shows the new `poll`. A failback or budget the line does not name is the engine's, and `| super` extends the nearest `_` Source's line (`<p>.sources._`, then `_.sources._`). A built-in with no `return` keeps its own schedule: the `_` lines apply to config Sources only, so the shipped `poll('60s', 12)` does not turn the watch-driven built-ins into pollers. Its table takes `return` and nothing else (`git.diff is a built-in Source: only return can be set`). The retuned metadata is validated as a code-declared Source's is, and a relative `watch(...)` on a Source with one instance (`hostname.host`) is a load error naming the table, since only an absolute path is ever watched there; a table of only `return` for a Source the provider does not have (`git.sources.dif`) says what the provider has.
- **A key walks up the instances — `Source::root`.** A Source answers `root(dir)`: the directory whose instance serves `dir`, or none for the one instance at `~`. A read of `p.<key>` from a directory asks the nearest instance first (`R1 = root(dir)`); if the key is missing there it moves to the parent of that root (`root(parent(R1))`) and asks again, ending at the instance at `~` and never past it — an instance already visited ends the walk at `~` instead of repeating. That is **cascade**, the default (mise, asdf's `.tool-versions`): each leaf comes from the nearest instance that has it. A Source whose `return` line says `| nearest` is answered by `R1` alone instead: a key it lacks is absent and the walk does not move up, and no root found means no instance and no value, never the instance at `~` (a `root` line that renders none; a `$HOME` found is an instance). `nearest` takes no arguments and records like the other decorators (the nearer line's setting applies across `| super`, a prototype's reaches a Source whose line calls `| super`, and a built-in's own `return` replaces the declaration whole); on a Source with one instance it is a load error. There is no `cascade` decorator. Records written by `put`, and the `config:` seeds, merge up the path chain whichever a Source does. A cold `get` executes `R1`, reads, and only on a miss executes the next; a namespace read takes every instance on the way and merges them per leaf, the nearer winning. Every instance the read reached is demanded (`SchedulerMessage::QueryActivity` carries the `(source, root)` list), and a root that cannot be worked out fails the read with its error rather than answering from `~`. A config Source's `root` line is that hook; each rendered root is kept per directory while the directories on its walk are as they were, until the instance it names is evicted (see Fixed, "a kept `root` is found again"), and a first render runs on the blocking pool, never on an async worker. The built-ins that walk to a marker (`git`, `direnv`, `asdf`, `terraform`, `python`, `mise`) override `root`; the rest have the one instance at `~`.
- **A Source's schedule registers when an instance is first requested, not at load.** The first demand for `(provider, root, source)` creates its lifecycle entry and registers its `watch` paths: relative paths as patterns under the instance's root, absolute ones (`/…`, `~…`) as they are. At the instance at `~` relative paths register nothing — a recursive watch of `$HOME` is the firehose — and a relative `watch` on a Source whose `root` is always none (a config Source with no `root` line, or a built-in retuned by a `return` that names one) is a load error instead of a watch that silently covers nothing.
- **`pick`, `omit` and `clamp` — three more template filters.** `obj | pick('profile', 'region')` keeps only the named keys of an object and `obj | omit('stash')` drops them; a key the object lacks is not an error, a non-object subject or a key that is not text is. `n | clamp(lo, hi)` holds a number to `lo..=hi`, and a `none` side is open (`(w - 6) | clamp(0, none)`); a bound that is not a number, or `lo` above `hi`, is an error. As for every filter, an absent subject gives undefined once the arguments have been checked. They are pure items: available on a provider's lines as well as the client and a Source's.
- **`ramp`, `pct`, `compact` and `bytes` — numbers for display.** `p | ramp([50, 80], [th.green, th.orange, th.red])` picks the value for the first threshold the number is under (`n < t`), else the last; the thresholds must ascend and the values be one longer, or it is an error. `0.423 | pct` is `42%` and `0.4236 | pct(1)` is `42.4%`, rounding as `'%.1f' | format` does (up to 20 digits). `1234 | compact` is `1.2k` and `56789 | compact` is `57k`, in steps of 1000 (`k`, `M`, `G`, `T`, `P`); `1288490188 | bytes` is `1.2G`, in steps of 1024 (`B`, `K`, `M`, `G`, `T`, `P`), and a negative size is an error. Both choose the unit after rounding, so `999950 | compact` is `1.0M`, not `1000k`. An absent subject gives undefined once the arguments have been checked.
- **`hash`, `b64encode`, `b64decode` and `urlencode`.** `v | hash('sha256')` is the lowercase hex digest of a string's bytes, for `md5`, `sha1`, `sha256` and `crc32` (eight hex digits, `'beachcomber' | hash('crc32')` is `48484316`); any other value is hashed as its JSON with keys sorted, so a map hashes the same however it was built, and an algorithm that is not one of the four is an error naming them. `s | b64encode` and `s | b64decode` are standard base64 (padding optional on decode); text that is not base64, or whose bytes are not UTF-8, is an error. minijinja's `urlencode` is switched on (`{'q': 'a b'} | urlencode` is `q=a%20b`) and, like every filter, gives undefined for an absent subject. All are pure items. Adds the `md-5`, `sha1`, `sha2`, `crc32fast` and `base64` crates to `libbeachcomber` (`sha2`, `crc32fast` and `base64` were already in the lock file); the release `libbeachcomber` dylib grows by about 33 KB (1,759,136 to 1,792,368 bytes).
- **`expanduser`, `ext`, `relpath`, `shorten_path` and `realpath` — path filters.** `'~/.kube/config' | expanduser` writes a leading `~` as the render's `HOME` (`~user` is an error, as everywhere paths are taken); `'a.tar.gz' | ext` is `gz`, and a name with no extension or a dotfile is undefined; `'/a/x' | relpath('/a/b')` is `../x`, worked out lexically against the render's directory for relative operands; `'/Users/j/ws/beachcomber/docs' | shorten_path(2)` is `~/w/beachcomber/docs`, writing home as `~` by the rule `comb status` uses and cutting the other components before the last `n` to their first character (a leading `.` keeps the next). `p | realpath` follows symlinks and is undefined for a path that is not there. All but `realpath` are pure items, available on a provider's lines; `realpath` reads files, so it is an `io` item. The `$HOME` display rule moved from the daemon crate into `libbeachcomber::path::Home`, so the CLI and the template library share it; `Home::literal` is the same rule with no look-up on disk, for the pure `shorten_path`.
- **`pct(digits=2)` and `shorten_path(n=2)` take their option by keyword as well as by position,** as `pad(align=)` and `truncate(end=)` do. Each is checked as the other items' optional arguments are: given twice, too many, or an unknown keyword is an error `name(): ...`.
- **`fromtoml`, `fromyaml`, `regex_search` and `regex_replace`.** `'Cargo.toml' | read | fromtoml | pluck('package.version')` and `'~/.kube/config' | read | fromyaml | pluck('current-context')` parse a document into data (a TOML datetime is its text; YAML with more than one document is an error, and `''` is undefined as for `fromjson`). `'v22.1.0' | regex_search('(\d+)\.(\d+)')` is the list `['22.1', '22', '1']` (the whole match, then each group, `none` for a group that took no part; no match is undefined), and `branch | regex_replace('^feat/', '')` replaces every match, or the first `count`, with `$1` and `${name}` standing for groups. Patterns use Rust `regex` syntax and are checked before the subject. All are pure items. Adds `regex`, `toml` (parse only) and `yaml-rust2` to `libbeachcomber`; the release `libbeachcomber` dylib grows by about 0.93 MB (1,825,824 to 2,757,648 bytes), nearly all of it the `regex` crate's engine and Unicode tables (built without its `perf` features).
- **`glob` — files by pattern.** `'*.tf' | glob | length > 0` is the sorted list of paths a shell would expand the pattern to (`[]` for none). `*`, `?` and `[..]` stay within a component, `**` crosses directories, and, as in a shell, a leading `.` must be written, so `*` and `**` pass over dotfiles and hidden directories (`.*.tf` finds `.hidden.tf`). A relative pattern is against the render's directory and gives relative paths; `~` is the render's `HOME`; an absolute pattern gives absolute paths; a trailing `/` keeps directories. An invalid pattern is an error, and a directory it cannot read is passed over. An `io` item: not on a provider's lines. Adds the `glob` crate (its component matcher) to `libbeachcomber`: the release dylib grows by about 17 KB (2,757,648 to 2,774,400 bytes).
- **`spark(values, lo=none, hi=none)` — a sparkline.** `spark([1, 5, 3, 8])` is `▁▅▃█`: one of eight block glyphs per number, scaled from `lo` to `hi` (the data's own minimum and maximum when `none` or not given). A value outside the scale is held to it, a `none` value is a space, and when the ends are equal every glyph is the middle one. A `values` that is absent gives undefined; one that is not a list of numbers, a bound that is not a number, or `lo` above `hi` is an error, checked before the values. A pure item.
- **`p | stat` — what a file looks like.** `{size, mtime, kind, mode}` of the file `p` names: `kind` is `file`, `dir`, `symlink` or `other` (a final symlink is described, not followed), `mtime` is epoch seconds (a whole number, with a fraction where the filesystem keeps one), and `mode` is the permission bits as a number. A path that is not there is undefined, so `| default(x)` fires; a subject that is not a string is `stat(): the path must be a string`, and any other OS error is `stat(): <path>: <error>`. A relative path is against the render's directory and `~` is the render's `HOME`. An `io` item: available on the client and in a Source's lines, a load error on a provider's. The `lstat` reader is `libbeachcomber::fs`.

### Changed

- **BREAKING (pre-1.0, wire + CLI + SDKs): an instance watches its files only while it is Active; `fsevents_reinstate` is gone.** Git's `head`, `refs` and `status`, mise, asdf, direnv, python and terraform, and every config Source with a `watch(...)`, kept their watches through decay, and a file event on a decaying instance brought it back to Active and ran it: an idle daemon held a kernel watch on every path an instance had watched, until it was evicted. Now entering decay drops an instance's watches, whatever it watches; a file event on a decaying instance does nothing; and the read that reinstates it registers them again. A decaying record stays correct without its watch, since a read checks its files by stat, and once every instance has decayed `introspect watches` reports none. `SourceMetadata::fsevents_reinstate` and `SourceLifecycleConfig::fsevents_reinstate` are removed, and so are the status row's `fsevents_reinstate` (from the wire's `CacheRow`, `sdks/api.json` and every SDK's row type: Go's `FseventsReinstate`, Python's and Ruby's `fsevents_reinstate`, Node's `fseventsReinstate`), `comb status --filter fsevents_reinstate=` (now `unknown filter key`), the `FSEVENTS_REINSTATE` column of `-f csv`, `tsv` and `sh`, and the `⊙`/`+` TTL indicator: `∙`/`-` marks an entry that watches its files while it is Active.
- **BREAKING (pre-1.0, wire + CLI + C ABI + SDKs): `wait` is a duration on every surface.** A read's `wait` was a boolean: wait for the run however long it takes, or not at all. Now it says how long, a duration in the one grammar or `forever`, spelt the same on every surface: `comb get --wait 0`, `--wait 250ms`, `--wait forever` (the bare `--wait` is a usage error); the wire's `"wait": "250ms"` (absent or `null` is the budget; a boolean is an invalid request); `Inputs.wait: Wait { Budget, For(Duration), Forever }` in `libbeachcomber` (`libbeachcomber::Wait`, which `Fetch::get` takes); and every SDK's `get(…, wait: "250ms")`. A stored record that is stale or whose inputs changed waits the call's `wait` instead of its Source's budget, and a cold read and `--force` wait the call's `wait` instead of their run's end: `--wait 0` answers at once with what is stored, a miss when nothing is, while the run goes on and records itself. A client's read of a `get` may take its timeout plus the `wait`, and `forever` has no deadline, so a `get` that waits forever outlasts a 100 ms `timeout_ms`. `bc_get` and `bc_session_get` take `options_json` (`{"force": true, "wait": "250ms"}`, NULL for neither; another key, or a `wait` that is neither, is a `parse_error`) where they took a `flags` bitmask: `BC_GET_FORCE`, `BC_GET_WAIT` and the `bad_flags` error kind are gone, from the header, `sdks/api.json` and every SDK (`BadFlagsError`, `ErrBadFlags`, Lua's `"bad_flags"`). Python `get(key, cwd=None, env=None, force=False, wait=None)`, Ruby `get(key, cwd: nil, env: nil, force: false, wait: nil)`, Go `Get(key, cwd, env, ...GetOption)` with `Force` and `Wait("250ms")`, Node `get(key, { cwd, env, force, wait: '250ms' })`, Lua `get(key, { cwd, env, force, wait = "250ms" })`: each sends the options its caller gave, the wait as given, and the library reads it, so a `wait` that is no duration is the same `parse_error` on every SDK. The Node and Lua subprocess tiers pass it as `--wait=<wait>` and report `comb`'s refusal of it as that `parse_error`, in the library's words. The conformance fixtures `get/wait_is_a_duration.json` and `get/wait_that_is_no_duration_is_refused.json` hold every runner to it, and `benches/validity.rs` measures `--wait 0` and `--wait forever` beside the default read.
- **BREAKING (pre-1.0, Rust API): a warm read checks its record's files, and git's `head` runs only when `HEAD` changed.** A read answered a stored record until a file event or a poll replaced it, so a read straight after a change lost the race to the watcher: a config Source with `watch('state.json')` answered the old value 92 times in 100 straight after a rewrite. Now a run stamps its Source's stat inputs immediately before it executes (`dev`, `ino`, size, mtime in nanoseconds and kind, following symlinks, with the link's own inode and mtime; an absent path has a stamp of its own), and a read stats them again before it answers: one `stat(2)` per input, on the request task. A record whose inputs changed runs again, the read waiting up to the Source's budget as for a stale one, so the read after a change answers the new value whether or not the event has arrived; a change during a run fails the next check, one run more and never a stale answer. A Source's inputs are its `watch(...)` declaration (a relative entry under the instance's root, an absolute one as written, a declared directory by its own mtime) and, for a config Source, the files its lines read (see Added); a Source that only polls and reads no file has none and is checked for its lifetime only. Git names its own: `head` is `<gitdir>/HEAD` (and `<root>/.git` when it is a gitfile, for linked worktrees and submodules), `refs` adds `packed-refs` and the branch's loose ref, `status` is `<gitdir>/index`. So `git head` is no longer run on every read: `git.branch` is answered from its record while `HEAD` is as it was, and its `age_ms` grows. An input on a network or FUSE mount is never stat'd on a read (a warning names the mount once) and its record is checked for its lifetime; a stamp taken within the mount's timestamp resolution of the file's mtime (at least 10 ms) is racy, and the first read once that window has closed runs the record again. `:cache.<field>.hash` shows the record's validity hash, 16 hex digits (FNV-1a 64, `libbeachcomber::validity`, with golden vectors), written by the daemon alone. A Source's own reads (`comb.<p>`, `sources.<s>()`) check the records they read too, and wait for a run to its end. `Source::read_always` and `Source::watched_files` are gone; `Source::inputs` replaces both.

- **BREAKING (pre-1.0, wire + CLI): a read of a stale record waits up to its budget for the record's run, and `:cache` says when a run is executing.** A record past its lifetime (older than its Source's poll) was served as it was, `stale: true`, and nothing ran it until the next poll: a Source polled every 10 minutes answered a value up to 10 minutes old, every time. Now the read runs the Source, or takes the run in flight, and waits up to the Source's budget (`budget(...)` on its `return`, else `[daemon] budget`, default `50ms`), counted from the read's start: in time it answers the fresh value; late it answers the stored one, still `stale: true`, and the run goes on and records itself, for the next read and for any `watch` of the key. A read with nothing stored, and `--force`, wait for their run as before (a read's own `wait` says otherwise: above); a record within its lifetime is answered as is, and so is an instance in failback backoff, which runs nothing. Budget exceeded is not `stale`. `:cache.<field>.executing` (derived, beside `age_ms`, `stale` and `source`, refused to `put`) is `true` while a run of the record's instance is in flight, whoever started it, so a template can show a spinner. A namespace read (`comb get git`) starts the runs of every Source it needs before it waits for any, so its Sources run together instead of one after another; the Sources a provider's lines call run together too, after the provider's own. In the Rust API `SourceMetadata::budget_execute` is `budget`, and `DEFAULT_BUDGET_EXECUTE` is `DEFAULT_BUDGET`.
- **BREAKING (pre-1.0, `libbeachcomber` API + C ABI): a watch waits on one `poll(2)`, and an idle one never wakes.** The fan-in behind `comb watch`, `bc_watch_*` and every SDK's watch read its streams in turn, each for up to 50 ms, so a change on the last of `k` streams waited up to `(k − 1) × 50 ms`, a cancel up to 50 ms a stream, an idle watch woke twenty times a second a stream, and opening one waited up to 50 ms a stream for each first frame. Now a wait is one `poll(2)` over every stream and a cancel pipe: a frame on any stream is seen when it lands, `bc_watch_cancel` (`CancelHandle::cancel`) ends a pending `bc_watch_next` at once, `next(Some(d))` returns once `d` has passed and not before, and a watch with nothing happening sleeps until something does. Opening a watch sends its subscriptions and waits for none; a subscription's opening frame is read when it arrives, and its refusal drops it as before. A re-resolve reads over one connection the watch holds rather than a connection per key, and a frame showing the node the latest resolution read there costs none. `ResolvedWatch::cancel_handle` returns a `CancelHandle` (was an `Arc<AtomicBool>`); `bc_watch_open` returns NULL when the process is out of file descriptors as well as memory. Measured by `benches/watch.rs` (`docs/performance.md`).
- **BREAKING (pre-1.0, CLI): a `comb watch -f json` frame for a miss is `null`, as `comb get -f json` prints it.** A json watch printed nothing for a miss, so a script reading it could not tell a key nothing answers from a watch still waiting, and a value going away (`put <key> null`) printed nothing either. Under `-f json` a miss is now the frame `null`: the first frame on a key nothing answers, and the frame after its value goes. Every other format, a `-f` template included, still prints no line for a miss, as `get` prints nothing for one. The FFI tiers already reported a miss as an event with no data; conformance fixture `watch/miss_is_an_event.json` pins it in every SDK.
- **BREAKING (pre-1.0, templates): statements and one `{{ }}` keep that expression's type.** A text of statements and comments, then its only `{{ }}`, with nothing but whitespace between, is typed on every line, client and daemon alike: `{% set x = 1 %}{{ x }}` is the number `1`, not the text `"1"`, and a list or map built in a `{% for %}` is that list or map, with no `tojson`/`fromjson` round trip. A macro's, a call's or a block `set`'s body does not count, since it prints nothing where it stands. The statements print nothing: one that does (a `{% call %}`) is `a typed line's statements print nothing`. `eval::classify` gives the new `Form::Statements`. A text that wants the string writes text around the tag, or `| string`.
- **BREAKING (pre-1.0, wire + CLI): one run per instance, whoever starts it, and `--force` keeps the last good value when its run fails.** A read that found an instance cold ran the Source in its own request task, beside any run the scheduler had under way, and recorded the result there; a poll, a file event or a refresh ran it again in the scheduler on another path; and a Source's call from another took a third, blocking turn. So a read and a poll at the same moment ran it twice, a refresh during a read's run started a second run beside it, a reload overtook only the scheduler's runs (a read's run wrote back the schedule the reload had just replaced), and two Sources reading each other's providers (`comb.<p>`) from two reads at once waited on each other until both timed out and answered misses. Now every run goes through one table (`src/run.rs`): at most one run of an instance is in flight and at most one is queued behind it. A cold read, a Source's call and an instance's first demand take the run in flight; a poll takes it too, since it brings the instance up to date as well as a new one would; a file event, a refresh and `--force` queue the one run that begins after them. The run executes on the blocking pool under its `timeout` and records itself, so a read that stops waiting (its connection gone) takes nothing with it. A reload overtakes any run in flight of a Source it removes, changes or reschedules, however it was started; a rescheduled one runs again under the new Source, and a read waiting on it answers from that run. A Source's run waits for another's from its blocking thread, and a wait that would close a ring of runs waiting on one another reads the last stored value instead: a Source never waits on itself. `--force` no longer drops the Source's map before it runs, so a forced run that fails leaves the last good value, which the read answers, as a run cut off at its timeout does. An embedded server's `refresh` (no scheduler) is a fresh run that respects the failback, as the daemon's is, and `introspect daemon`'s `in_flight` counts every run, not only the scheduler's.

- **One evaluator for every line.** A client template, a Source's `root`, `data` and `result` lines and a provider's `template`, `result` and `return` lines all run through `libbeachcomber::eval::evaluate`, so the one-tag-keeps-its-type rule, absent for `none` and undefined, and the structural refusals are written once. A resolution builds its engine once and renders every node in it. Every engine prints a `none` inside text as nothing, and every error drops the engine's own frame: a provider line's error no longer ends `(in <expression>:1)`. The client's errors keep their words (`<key>: template compile error: …`).
- **Templates: `bar(width, part, ..., empty=, fill_fg=, text_fg=, label_fg=, bold=)`.** One styled row of exactly `width` terminal columns from labels and tracks: a track fills a fraction of its columns from either edge (or stacks coloured segments), carries one marker column, and overlays text cut and padded to its width; labels take their own width and the tracks share the rest. Every column is its own `c | fg | bg | bold` run, so a bar is one call where scanline looped over every cell in jinja. Byte-for-byte equal to scanline's painter on every recorded row (`libbeachcomber/tests/fixtures/scanline/bars.json`), except one: a marker on a wide character keeps the row its width where the painter dropped a column.
- **Templates: `now`, `strftime`, `fromiso`, `ago` and `spinner`, and the clock is a resolution input.** `now()` is the clock in epoch seconds, one value for a whole client resolution (a `comb watch` re-resolve takes a fresh one) and for a Source run; `t | strftime(fmt, tz=)` formats in `tz=`, else the render's `TZ`, else the system zone; `s | fromiso` reads ISO 8601 / RFC 3339 (no offset is the render's zone, a date alone its midnight, a fraction a float); `t | ago(parts=2, floor='s')` is `3h12m ago` or `in 3h12m`; `spinner(frames, step='1s')` picks a frame by the clock. They are the new `clock` tier of the library: a provider's lines and a `return` decorator cannot call them (a load error). `libbeachcomber::resolve::Inputs` and `EngineCtx` gain `now`; the CLI, the C ABI and the watch set it from the system clock. Zones and time formatting are the `jiff` crate.
- **BREAKING (pre-1.0, CLI + templates): durations gain `d`, and one formatter takes parts and a floor.** The duration grammar (flags, settings, decorators, keyword arguments) accepts days: `1d`, `2d3h`. The library is documented in `website/docs/reference/template-library.md`.

Errors stay 2. The daemon crate's own `fork_daemon`/`wait_for_daemon`/`ensure_daemon` and its `DaemonSpawner` seam are gone.
- **A spawned daemon says when it serves, so an autostart costs what the daemon's start costs, and a daemon that cannot start is reported at once.** `comb daemon --ready-fd <FD>` writes a newline to the inherited descriptor `FD` once its socket is bound, or once it finds a daemon of its own build already serving it, and closes it; a daemon that exits first closes it unwritten. `libbeachcomber::spawn::ensure`, behind the CLI and every SDK, hands the daemon a pipe this way and waits on it, where it polled the socket on a doubling backoff that noticed a 40ms start at 70ms or 150ms, and a daemon that had already exited only after 1.6s. A daemon that exits before serving is reported the moment it exits, with its exit status and the first error it wrote to its log (`error: daemon: could not start: exited before serving (exit status: 2): …`); an SDK sees `daemon_not_running`, as before. A daemon that neither serves nor exits is given 5s, and left running. `spawn::ensure` returns a `spawn::Error` (`Socket`, `Io`, `Exited`, `TimedOut`) instead of an `io::Error`, and `spawn::launch` starts any `comb daemon` command line the same way; the test harness starts its daemons through it. The daemon ignores `SIGPIPE`, so a spawner that stopped waiting cannot kill it with the newline; the commands it runs start with the default.

The `daemon.pid` file the CLI's spawn wrote beside the socket is gone: the singleton's `pid` is the only pid file, and `comb kill` reads the pid through the client's `introspect{daemon}` with no file fallback.
- **BREAKING (pre-1.0, wire + SDKs): the wire has no `context` op; a session keeps its directory itself.** `{"op":"context","path":…}` set a directory on the daemon's side of a connection that later `get`, `refresh` and `watch` requests used when they named none — and that `put` ignored, so a session's `put` went to the global entry while its `get` read the session's directory. The op is gone (the daemon refuses it as an unknown op), and a connection holds no directory of its own. `libbeachcomber::Session::set_context` now keeps the directory in the session and sends it with every request that names no path — `get`, `put`, `refresh` and `layers` alike — so every SDK's `set_context`/`setContext`/`SetContext` means the same thing, `put` included. A new `bc_session_refresh` runs a refresh on the session (its connection and its directory), and every SDK's session `refresh` calls it where it used to fall back to a fresh, directory-less client connection.
- **BREAKING (pre-1.0, wire + CLI + FFI): one path normaliser, and the daemon takes only absolute paths.** `libbeachcomber::path::normalise` is the one reading of a directory a caller names: a leading `~` is the home directory, a relative path is made absolute against the caller's working directory, and naming none is that directory. The CLI's path arguments, every request `libbeachcomber` builds (`get`, `put`, `refresh`, `watch`, `layers`), and the FFI's `bc_resolve`/`bc_eval`/`bc_watch_open` `cwd` all go through it, so an SDK `put(…, path="~/ws")` and `comb put … ~/ws` now write the same entry. The daemon refuses a `path` that is not absolute — `""`, `"."`, `"rel/x"`, `"~/x"` — with `path must be absolute: "<path>"`, where it used to store `~/ws` literally, join a relative path to its *own* working directory, and read `""` as that directory. A NULL `cwd` on `bc_resolve`, `bc_eval` or `bc_watch_open` now addresses the global entry, as `comb get --global` does, where it was an error; a template's `exec`, `lup` and `read` then run in `$HOME` from `env_json`.
- **BREAKING (pre-1.0, CLI + config + templates): a leading `~` is read one way wherever comb takes a path, and `~user` is an error.** One function, `libbeachcomber::path::expand_tilde`, writes a leading `~` (alone, or before a `/`) as the home directory, for a `--path`/trailing directory, `[daemon] socket_path` and `env_file`, `[daemon.plugin] path`, `plugin()`, `read`, and a `watch()` path. Before, `socket_path` took no `~` at all, `env_file` took `~/` but not a bare `~`, a `--path` or `read` of `~bob/x` quietly became a relative `~bob` directory or file, and a `watch()` path expanded a `~` after any `/` (`/a/~/b`). Now `~user` is an error naming the path everywhere — a config error for `socket_path` and `env_file`, exit 2 for a CLI path, a render error for `read` — and only a leading `~` expands.
- **BREAKING (pre-1.0, CLI + SDKs + config): a template reads any address jinja can write — `comb['git:cache'].branch`, `comb[name]`, `env[var]`, `git['x']`.** Ref discovery reads a template's text, so it bound only literal dotted chains, and anything else bound nothing at all: `comb['p']` and `env['X']` were silently undefined on the client, and `comb[...]` was a load error in a Source's `data` line. Now a literal attribute chain is still read exactly (`comb.git.branch` fetches `git.branch` alone, so only git's `head` Source runs), and a ref used any other way — subscripted, filtered, iterated — reads the node at the end of its literal chain whole, as `comb.aws_profiles[name]` already read `aws_profiles`: a provider named alone (`scanline['widgets']`, `p | tojson`) is that provider resolved, where it bound nothing; and `env` is the caller's whole environment, so `env[var]` and `env | items` work and an unset variable is still undefined. `comb` alone is every provider, so it is lazy: `comb[...]` reads the provider it names when the render asks for it — a facet head (`comb['git:cache']`, `comb['p:put']`) or a computed name — once per resolution, and a literal `comb.<p>.<f>` beside it stays exact. What a render read, lazily or not, is its dependency list, so `comb watch` follows a computed name to whatever it names now. A failed lazy read fails the resolution as an eager one does. On the client a render with a lazy `comb` runs on a scoped thread while the resolver answers its reads; any other render is as before. In a Source's `data` line `comb['<p>']` and `comb[name]` read stored records at the instance's directory as `comb.<p>` does, never running a Source. A function the engine registers (`exec`, `lup`, `merge`) is no longer reported as a name a template reads.
- **BREAKING (pre-1.0, CLI): the default `comb status` lists what a read here answers, and no record it shadows.** A put over a Source's field, a template over cached data, a nearer put over a global one: each listed both records as values, and a Source's leaf that a root put had replaced was still listed though `comb get` of it is a miss (`git.detached` beside `put git '{…}'`). `status` now asks the daemon for each leaf's layers (the same `layers` stack `--tree` draws) and marks every record on the caller's directory chain that the read does not take as shadowed; a new filter key, `shadowed`, selects them, and its default `shadowed=false` joins `facet=-` and `value!=-`, so the default table is one row per leaf, the one `comb get` gives. `-a` lists the shadowed records too, `--filter shadowed=true` lists only them, and in `-f json` such a row carries `"shadowed": true`. Records stored at directories off the chain are other directories' values and are listed as before. Under `-a --tree` a shadowed row's children show what shadows it, and no row is repeated as its own child.
- **A TOML parse error says why.** `comb check config`, the daemon's refusal to start and the reload log kept only the first line of the toml crate's error — `config:<file>: TOML parse error at line 39, column 1` — and dropped the reason the crate prints below its snippet. The one line each shows now carries both, the reason folded onto it: `config:<file>: TOML parse error at line 5, column 1: duplicate key `glyph``.
- **BREAKING (pre-1.0, CLI): a trailing directory starts with `/`, `~` or `.` on every command.** `get` read its last argument as a directory only when it started so, but `put`, `refresh`, `watch` and `eval` took any last argument for one: `comb get git.branch repo` read the key `repo`, while `comb watch git.branch repo` watched the directory `repo`. The one rule now holds for all five: an argument is a directory only when it starts with `/`, `~` or `.`. Where the last argument can only be a directory, anything else is refused before a daemon is started, with the spelling that works: `repo is not a directory: write ./repo or --path repo`.
- **BREAKING (pre-1.0, CLI + config): one duration grammar, everywhere a duration is taken.** Each place had its own: `put --ttl` took `30`, `30s`, `1m` but was only checked by the daemon, after it had been started; `check --connect-timeout` took `0`, `250ms`, `2s` but not `1m`; `kill --timeout` and `check procs -d` took integers only (`5s` was `invalid digit`); `[daemon]` watchdog keys refused an integer that a decorator would take; and `0ms` was no duration while `0s` was. Now every one — the four flags, the `[daemon]` duration keys and the decorators — takes whole numbers each with a unit, `h`, `m`, `s` or `ms`, largest first (`250ms`, `30s`, `1m30s`, `2h14m`), a bare number (or a TOML integer) being seconds — so every duration comb shows reads back — and refuses anything else as `invalid duration `<text>`: whole numbers each with a unit, …`, the flags before a daemon is started. Zero is zero in every unit; what each may be is its own (a ttl is whole seconds of at least 1s, refused in the CLI as `ttl must be a whole number of seconds, at least 1s`; `procs --duration` is whole seconds; a `budget` is at least 1ms). `kill --timeout` and `check procs -d` default to `5s` and `60s`. The keys that carried a unit in their name take this grammar too (see the entry on `timeout`).
- **BREAKING (pre-1.0, config + templates): a Source's run has a `timeout`, and every duration is spelled as one.** `[daemon] provider_timeout_secs` (integer seconds, one cap for every run) is `[daemon] timeout`, a duration in the one grammar (default `"10s"`), and a Source may set its own with a `| timeout('30s')` decorator on its `return`, as it sets `budget(...)`; a built-in Source takes the `[daemon]` value unless a `return` line retunes it. The timeout now cuts off a run a read starts inline as well as one the scheduler starts, so a cold `comb get` no longer waits out a slow command; the run fails with `timed out after 300ms` and the last good value stands. `[daemon] idle_shutdown_secs` is `[daemon] idle_shutdown` (whole seconds, `"5m"`), and `[daemon.budget] execute` is `[daemon] budget` (`"50ms"`): a `[daemon]` key named for a decorator is that decorator's default. `exec()` and `url()` take `timeout='5s'` (a duration, or a number of seconds) where they took `timeout_ms=5000`. Each old spelling is an error that names its replacement — `[daemon] provider_timeout_secs is removed: write [daemon] timeout = "10s" (a duration)`, `exec(): timeout_ms= is removed: write timeout='10s'` — never read. The grammar itself lives in `libbeachcomber::duration`, which the daemon's flags, settings, decorators and the template keywords all call.
- **BREAKING (pre-1.0, config): `comb.<p>` in a Source's `data` line is a read like any other.** It read only what was stored, so a provider nothing had read yet was absent to every line that named it until something else warmed it and the reader ran again (`data = "{{ comb.up.v }}"` gave nothing on a cold daemon). Now a read through `comb.<p>` or `comb[name]` first brings the provider up to date as a `get` of it would — each of its Sources, and each Source its lines call, runs a cold instance inline, once — and then reads it as before: put over source, through its `return` line. A Source never waits on itself: one that reads its own provider, or reads round a ring of `comb.` reads back to itself, finds its own last stored value, which before its first run is nothing. The Sources a run reaches this way are noted against it, as a Source call's are, so whatever keeps the reader warm keeps them warm too. A Source call (`sources.<s>()`, `daemon.providers.<p>.sources.<s>()`) still differs where that is its point: it reads one Source's raw records, without a `put` over them or the provider's lines, and calling oneself is an error.
- **Every configuration error names its file the one way, and every mistake is reported at once.** An error read `config:<file>: …` for a file's own rules, `[daemon.providers.p.sources.s] has no data line` with no file for the shape checks, `p.s: data: …` for a Source's lines, `daemon.providers.p.sources.s: no such source` for a call, and `… (…, set in config:<file>)` for the watchdog. Now each is `config(<file>): …` — the file the label every surface shows, `~` for `$HOME`, and the file the one that set what the error is about — and names the table at fault as written: `config(~/.config/beachcomber/config.toml): [daemon.providers.p.sources.s] data: unknown name 'nope' (…)`. The daemon's two refusals to start (before its logger, and after it) are one function and say the same lines, which `comb check config` and the reload log show too. And `comb check config` no longer reports a stage at a time: a `[daemon]` setting that does not deserialize leaves the providers and templates checked, a Source table that does not build leaves the others built and linted, a call to a Source whose table is there but did not build is not reported again as `no such source`, and a provider none of whose Sources built is not reported again as declaring none.
- **BREAKING (pre-1.0, config): a client template is checked where it is written, and one linter checks every line.** A `[client.providers.<p>] template` leaf, and a `comb put` to `<p>:template`, was stored unread, so `template.t = "{{ git.branch "` loaded and failed only when a client rendered it. Now each leaf the seed writes is checked as the value expression it is: one that does not compile is a load error — the daemon refuses to start on it, a reload is not applied, `comb check config` fails — naming it, `config(<file>): [client.providers.p] template.t: syntax error: …`; one that reads a name no provider has (`{{ gti.branch }}`) is a warning, a `WARN` in `comb check config` and a line in the daemon's log, and loads, since a `put` may yet make that provider. A `put` of a template that does not compile is refused (`p:template.t: syntax error: …`) and writes nothing; one naming a provider nothing has yet is taken. The daemon's own checks go through the same linter (`libbeachcomber::eval::lint`) and the one table of what each kind of line reads: a Source's lines report every line that reads a name its stage does not see, not the first, and a provider's line every such name.
- **BREAKING (pre-1.0, CLI + SDKs): a template runs in the directory it is addressed at.** A template's `exec()`, `lup()` and `read` ran in a different directory depending on who asked: `comb get t.x ./repo` and `comb watch t.x ./repo` ran them in the process's own directory while reading `t.x` at `./repo`, `comb eval '{{ t.x }}' ./repo` and an SDK's `resolve` ran them in `./repo`, and `--global` ran them wherever `comb` happened to be started. The resolver now decides, the same for every surface: the directory the resolution addresses — the explicit path, else the caller's directory — and `$HOME` (the caller's) for the global entry. So a template that reads `.git`, a local file or `pwd` describes the directory it is asked about, whether that is `comb get`, `comb eval`, `comb watch`, a status row or an SDK.
- **BREAKING (pre-1.0, wire + CLI + config): `env`, `comb`, `_` and `*` are reserved, and no provider may take one as its name.** Each means something of its own — `env.X` is the caller's environment, `comb.<p>.<f>` in a template is the stored value of `<p>.<f>`, `_` names a prototype table and `*:cache._.decay` is the decay of every provider — but a `put` or a config table could still claim one, and then one key meant two things: `comb put env.FOO '"x"'` succeeded while `comb get env.FOO` went on reading the shell and an SDK's raw `get` answered the put, and `[client.providers.comb] template.y` made `comb get comb.y` print a value that `{{ comb.y }}` in a template could never reach. One rule, `libbeachcomber::key::reserved`, now refuses them in one message wherever a name is given: a `put` (`'env' is reserved: env.X is the caller's environment`), any key the daemon is asked about (`comb get comb.x`, `refresh _`), and either config root (`invalid provider name 'comb' in [client.providers]: …`). `[daemon.providers._]`, the prototype table, and the key `*:cache._.decay` keep their meanings. `cwd`, which ref discovery skipped though nothing bound it, is an ordinary name.
- **BREAKING (pre-1.0, wire + CLI + SDKs): one key grammar, jinja's, with brackets as the quoting form.** A key is a head — a provider, or `provider:facet`, running to the first `.` or `[` — and an address of segments written `.seg`, `[n]` or `['…']`/`["…"]`, so `comb get` takes the address a template writes: `p.list[0]` is `p.list.0`, and `mise['go:golang.org/x/tools/gopls']` reads the mise tool of that name, which the dots in it made unaddressable. A dotted segment holds any character but `.`, `[` and `]`, so `mise.cargo:cargo-nextest` and `mise.npm:@scope/pkg` read their tools where a colon after the first dot was `invalid key`; only a colon in the head names a facet. In a quoted segment a backslash escapes only the quote and the backslash. A key the grammar cannot read is `invalid key: <key>`: an empty head or segment, a head starting with `/` or `~`, a stray `]`, an unterminated bracket or quote, an index that is not a canonical decimal. One parser, `libbeachcomber::key`, serves the daemon (planning, `put`, the template half's walk, the `:cache` and status rows) and the client (`env.*`, `rest`, watch, the Node and PUC-Lua subprocess tiers' `:cache` keys); `protocol::split_key` is gone. Every address comb prints is canonical — bare segments joined by `.`, a segment that is empty or holds `.`, `[` or `]` as `['…']` — so `comb get mise` prints `['go:golang.org/x/tools/gopls']=0.16.0` and the status FIELD column `['go:golang.org/x/tools/gopls']`, either of which can be typed back. A field named with a dot is no longer found by its literal dotted text (`a.b` is always the walk; the field is `['a.b']`). A name holding a `.` is written as it is read, in a `put` key (`comb put 'p["a.b"]' 1`), in `put` data (`{"a.b": 1}`) and as a quoted TOML key in a template (`template."a.b"`) or a Source's `result` (`result."a.b"`): it is one name, never a path. A provider name now also holds no `[` or `]` and does not start with `/` or `~`.
- **BREAKING (pre-1.0, wire + CLI + templates): `pluck`, every array walk and every name follow the key grammar.** `pluck` read paths with a grammar of its own, so `{{ l | pluck('[-1]') }}` was the last element while `comb get 'p.l[-1]'` was `invalid key`, and `pluck('l[01]')` read index 1 where a key refuses `[01]`. Now one grammar serves both: a negative index counts from the end in a key as in `pluck` (`p.l[-1]`, `p.l.-1`, as jinja's own `l[-1]`), a non-canonical index (`01`, `-0`) is `invalid key` in a key and `pluck(): malformed path` in `pluck`, and `pluck` takes the key grammar's quoting (`['it\'s']`). One reading of an index serves every walk: a key, `pluck`, a rendered value and a write. A provider name follows one rule wherever a name is given — a config table, a `put`, a key the daemon is asked about, and a Source name: non-empty, no `:`, `.`, `[`, `]` or `*`, and not starting with `/`, `~` or `<` — and the reserved words besides. `put` refused none of these before (`comb put '<x>.v' 1` succeeded), a key naming such a provider now reads `invalid provider name '<x>': …` as a reserved word's already did, and a Source name gains `[`, `]` and a leading `/` or `~` to its refusals; an empty provider name reads as the rule rather than `empty provider name`. The `:cache` facet of a node now answers a leaf whose name holds a `.` (`comb get p:cache` left `a.b` out of the tree), and a template's ref binds a key with a quoted segment at its segments rather than splitting inside the quotes.
- **BREAKING (pre-1.0, CLI): a trailing directory argument starts with `/`, `~` or `.`.** `comb get <keys…> [path]` took its last argument for the directory whenever it held a `/` anywhere, so `comb get mise.npm:@scope/pkg` read no key at all and printed nothing, and a key holding a `/` last in a list was read as a path. Now the last of two or more arguments is the directory only when it starts with `/`, `~` or `.` — which no key can, since a provider name holds no `.` and starts with neither `/` nor `~` — and a lone argument is always a key (`comb get .` is `invalid key: .`). `comb get git.branch sub/dir` reads the key `sub/dir`: write `./sub/dir` or `--path sub/dir`. A leading `~` the shell did not expand, because it was quoted, is `$HOME` for every command that takes a path (`get`, `put`, `refresh`, `watch`, `eval`), where `'~/x'` used to land under the current directory.
- **Every command that addresses a directory takes it the same three ways.** `get`, `put`, `refresh`, `watch` and `eval` each take a trailing `[path]`, `-p`/`--path <path>` and `--global`, which conflict with one another, and each `--help` describes them in the same words. `put` gains the trailing path (`comb put KEY DATA [PATH]`), `put`, `refresh`, `watch` and `eval` gain `-p` (only `get` had it), and `eval` gains `--path` and `--global`; `comb eval --global` resolves its refs from the global entry.
- **BREAKING (pre-1.0, config): the config shape.** Configuration has two roots, `[daemon]` (settings, `plugin`, `budget`, and `providers`) and `[client]` (`providers.<p>.template`); a provider exists if either names it. A provider is a namespace made of Sources and three optional lines, `template`, `result` and `return`; a Source `[daemon.providers.<p>.sources.<s>]` is a jinja function (`root`, `data`, `result`, `return`), and `_` tables are prototypes. Everything the 0.9 file spelled differently is an error, naming the file and where it went: the `[providers]`, `[lifecycle]`, `[failback]` and `[tree]` roots, `type`/`backend`/`command`/`url`/`library_path`/`fields`/`invalidation` providers, `scope`, `marker`, `output`, `extract`, `poll_interval`/`poll_count`, `fsevent_*`, `failback_*`, `budget_*`, a provider-level `enabled` outside `[daemon.providers.<p>]`, `fsevent_lifespan` and `[providers.<p>.virtual]` (see Removed). Migration: a script provider is a Source whose `data` calls `exec()`, an HTTP one `url()`, a library one `plugin()`; a schedule is the `return` line; a template is `[client.providers.<p>] template.<leaf>`; `[lifecycle] idle_shutdown_secs` is `[daemon] idle_shutdown_secs`.
- **BREAKING (pre-1.0, config + wire): `exec()` takes one command, and the environment is `env`.** `exec('cmd …')` is a string for `sh -c`, `exec(['cmd', 'arg'])` is argv with no shell, and a second positional argument is an error (`exec('git', 'rev-parse')` does not work: write the list). The child's environment is exactly the render's `env` map: the daemon's for a Source (not the environment of whoever asked), the caller's for a client template, so `$FOO` and `env.FOO` read the same value; `${VAR}` in a URL or header is `env.VAR` in the call. Prefer `exec('cmd ' ~ env.bar)` to `$BAR` in the string: the engine cannot see a shell expansion.
- **BREAKING (pre-1.0, config): decay depth is data, and its line is `[daemon.providers._.cache._] decay = 4`.** The fixed four-step ladder (`decay1..4`) is the number `decay` in the `:cache` facet, 1 to 16, shipped as 4 and set per provider by `[daemon.providers.<p>.cache._] decay = N` or by `comb put`. A line spelled any other way (a colon table, a key under `[lifecycle]`) is an error.
- **BREAKING (pre-1.0, wire): git, direnv, python and terraform answer from their nearest instance alone.** Their Sources are `| nearest` (above): a nested repository shows only its own values, a directory under `$HOME` with no repository of its own reads the `$HOME` repository's (or nothing), and a directory outside any repository has no git values and creates no git instance. A read that took a leaf from an outer instance or from the global entry now misses. mise and asdf still cascade. A retune of one of them (`[daemon.providers.git.sources.diff] return = …`) replaces the whole declaration, so it says `| nearest` again or the Source cascades.
- **BREAKING (pre-1.0, wire + CLI): `put --ttl` makes each put address its own lifecycle entry.** `comb put --ttl N` is `poll(N, 1)` with decay depth 1: valid for N, readable but `stale` for one decay step, then evicted — where before it only set an expected interval on a record that never left the cache. Each put address (key and directory) has its own lifecycle, so `comb put --ttl 300 build.status '"passing"'` and `comb put --ttl 60 build.eta '"4m"'` expire independently, a re-put without a ttl drops the expiry, and `comb status` shows the row as any lifecycle entry (source `put`); `git:cache.<node>` reports its `poll` and `decay`. A ttl of `0s` is `ttl must be at least 1s`, an unparsable one is `invalid ttl: <ttl>` (it used to be silently dropped), and a ttl with a `null` put is refused.
- **BREAKING (pre-1.0, wire + CLI + SDKs): an array is an array.** The daemon stored a list as an object keyed by decimal index, so `comb put demo.l '[1,2,{"z":3}]'` read back as `{"0":1,"1":2,"2":{"z":3}}`, a template saw a mapping (`{{ demo.l[0] }}` was empty, `{{ demo.l is sequence }}` false) while an array a template produced stayed an array, and `comb status` guessed index-keyed objects back into arrays for display. A list is now a value of its own through `put`, a Source's result, configuration seeds, the cache, the wire, every `comb get` format, templates and the SDKs, and `status` shows it as the array it is (`--depth` never expands one). An array is a leaf: a put of an array replaces whatever is at its address whole, and a nearer or later layer's array replaces a farther one's whole, as a scalar does — elements never merge across layers. A `null` element is absent and the array closes up behind it (`[1, null, 3]` is `[1, 3]`), where it used to leave a hole at index 1. An element is addressed by decimal index (`demo.l.0`, `demo.l[0]`), and the `:cache` facet answers for an element with its array's record. A put at an index writes into the put's own array: inside it the element is replaced, at one past its end it is appended, and `put demo.l.0 null` removes the element and closes the array up; a put at any other index, or into an array another layer holds, writes the address as an object, as a put through any other value in its way does. The `:cache` facet's `watch` is an array of patterns.
- **BREAKING (pre-1.0, CLI + SDKs): a group with no present leaf is absent.** A template group whose every leaf came out absent read as `{}` and exited 0 while each leaf was a miss: `comb g.j kubecontext` printed `{}` with no context set, as did `python`, `terraform`, `gcloud`, `conda` and `talos` outside anything they report on, and `{{ kubecontext is defined }}` was true. A group the client assembles — a template tree, at any level, and the data under it once the template has claimed its leaves — is now absent when nothing in it is present: a miss on `comb get` (nothing under `text`, exit 2 under `-f json`), undefined in a template, and not a member of the group above it. An object stored as data is a value even when empty: `{}` written below a namespace root by a `put` (`put demo.q '{}'`, or `{"a": null}`, whose only member is absent) or produced by a Source reads back as `{}`.
- **BREAKING (pre-1.0, wire + CLI + SDKs): built-in providers leave out what they have no value for.** Several fields stood in `""` or `0` for "none", against "null means absent": `git.branch` was `""` on a detached HEAD; `git.upstream`, `git.tag`, `git.commit`, `git.commit_summary` were `""` and `git.last_commit_age_secs` `0` when there was no upstream, tag or commit; `git.ahead`/`behind` were `0` without an upstream, `push_ahead`/`push_behind` `0` without a push remote, and `state_step`/`state_total` `0` outside a rebase; `network.interface`, `ip`, `ipv6`, `vpn_name` and `ssid` were `""` with nothing to report; `battery.time_remaining_secs` was `0` with no estimate (a full battery, or none given); `python.venv_version` was `""` when `pyvenv.cfg` names no version; an empty `.terraform/environment` gave `terraform.workspace = ""`; and `user.name` was `""` for a uid with no name. Each is now absent there: a miss, undefined in a template, and hidden by `comb status`'s default. A template that tested `git.tag == ''` tests `not git.tag` instead. Counts and flags keep their value: `git.stash` is `0` with no stashes, `network.online` and `vpn_active` are `false`, `git.state` is `clean`. And a read of a field the Source's last run left absent no longer runs that Source again: it was one inline run per read, so a prompt reading `git.upstream` in a repo without one spawned `git status` on every prompt. A field the last run left absent is absent until the Source runs again, as a field it produced is present until then.
- **BREAKING (pre-1.0, wire + SDKs): `null` means absent, never `""`.** A `put` of `null` at an address removes it, and a `null` inside the data is an absent leaf: JSON null used to become `""` on the way in, indistinguishable from a real empty string. `data` is required on the wire (a request without it is `invalid request: missing field `data``), and removal is the ordinary put with the language's null in every SDK. Arrays are still returned as objects keyed by index.
- **BREAKING (pre-1.0, CLI + SDKs): a client template whose one tag yields `none` or undefined is absent, not `""`.** `template.workspace = "{{ env.MYAPP_ENV or comb.myappcache.workspace }}"` with neither set used to resolve to `""`; it is now a miss (`comb get` prints nothing, `-f json` reports the miss, `resolve` and `eval` give the language's null), and a group read omits the leaf, as the daemon's own lines always have. Text around a tag still prints `none` as nothing (`"on {{ none }}"` is `"on "`). A number JSON cannot hold (`{{ 1 / 0 }}`) is a runtime error on both sides, where it used to be the string `"inf"`.
- **BREAKING (pre-1.0, CLI + SDKs): an unset `env.X` is absent in a client template, not `""`.** It is undefined, as in the daemon's lines: `{{ env.X | default('d') }}` gives `d` where it gave `""`, `{{ env.X }}` alone is a miss, and `comb get env.X` of an unset variable is a miss (under `text` it still prints nothing). A variable set to `""` is still `""`. A test written `env.X != ''` is now true for an unset variable; write `env.X | bool` for "set and non-empty" — the shipped `op.service_account` does.
- **`kubecontext`, `talos` and `python.venv_name` are absent when there is nothing to report.** `kubecontext.context` and `talos.context` were an error (`expression eval error: … current-context is not set`, exit 2) whenever no context was set or the tool was not installed, and `comb status` showed that error as the value; `python.venv_name` was `""` outside a virtualenv. All three are now a miss there: `kubecontext.context` is `exec('kubectl config current-context 2>/dev/null || true') or none`, `kubecontext.namespace` renders only `if kubecontext.context`, `talos.context` parses `{}` when `talosctl config info` fails, and `venv_name` takes `basename` only `if env.VIRTUAL_ENV`. A context that is set reads as before.
- **BREAKING (pre-1.0, defaults): `op.signed_in` is `op.service_account`.** The field never told whether `op` was signed in — only whether `$OP_SERVICE_ACCOUNT_TOKEN` is set and non-empty in the shell (`env.OP_SERVICE_ACCOUNT_TOKEN | bool`), never the token itself — so it is named for what it reads, after 1Password's own variable. `comb get op.signed_in` is now a miss.
- **BREAKING (pre-1.0, wire): a key is found by walking up the key, and a Source can answer for a whole node.** The Source for a key was looked up by its first segment only, so an undeclared name found no Source and nothing ran. It is now the Source of the nearest ancestor node that declares one: `mise.node.version` finds the Source that declares `node`. A Source that cannot list its field names in advance declares a sentinel field (a name starting `<`, such as `<tool>`) that answers for the provider node itself.
- **BREAKING (pre-1.0, templates): the daemon-read template namespace is `comb.*`, not `cache.*`.** `{{ comb.git.branch | truncate(12) }}` forces a read of `git.branch` from the daemon, so the namespace cannot be confused with the `:cache` facet. The shipped defaults, the conformance fixtures and every SDK move with it.
- **BREAKING (pre-1.0, wire + library): a watch may address any key, and a write to any facet wakes the namespace's watchers.** The watcher registry keys every facet (`p:template`, `p:put`, `p:cache`) by its base namespace, so a template edit or a data write notifies a watch on `p`, and `libbeachcomber::watch` no longer opens its extra `<p>:template` subscription. `watch` on a key nothing answers yet (an unknown provider, a node not yet written) is a miss that a later write wakes; the library's resolve treats a key the daemon rejects as a miss while watching.
- **BREAKING (pre-1.0, lifecycle): a watch-only Source decays like any other, and its Active window is the default poll lifespan.** Pure-watch Sources used to hold a fixed 120 s or 300 s keep-alive, or never decay at all. A Source's Active window is `interval × count` whether or not it also watches files, and a watch-only Source, which has no interval of its own, takes the default 60 s × 12 — it starts decaying twelve minutes after its last read, and runs again on the next. `poll_count` moves into `InvalidationStrategy::Poll` and `WatchAndPoll` (`count`), `StateTransition::ResetKeepAlive` is `ResetActive`, and the status `TTL` column's count is the Active-window poll count.
- **The Node and PUC-Lua subprocess tiers read `<key>` plus `<p>:cache.<rest>` instead of `<key>:age <key>:stale`.** Both ask `comb get -f json` for the value and its `:cache` answer in one spawn; for an object node the age is the largest of its leaves' and the node is stale if any leaf is. A facet key is asked alone and reports age 0, and a rendered value reports age 0 and not stale.
- **BREAKING (pre-1.0, wire): `get` of an unknown provider is a miss, not `unknown provider`.** An address nothing answers is `{"ok":true}` with no `data`, as an unknown field already was, and as a `watch` on it already was; only invalid facet syntax (`a:b:c.x`) is an error. `libbeachcomber::resolve`'s watch no longer swallows a rejected key.
- **BREAKING (pre-1.0, CLI): `comb status` renders the caller's template leaves as rows of their own, and every row now shows its SOURCE.** The daemon holds templates as data under `<p>:template` and never evaluates them, so `status` used to show a column of raw expressions — `{{ env.SCANLINE_FOO }}` — where the user wanted to know what their prompt would actually get. Every template leaf visible from the caller's directory (its own path, an ancestor, or the global entry) is now resolved exactly as `comb get` would resolve it, with this shell's environment and `exec()` enabled (canon `field_resolution.md` invariant 15), and added as its own row beside the raw template and any cached value at the same address — so a cached `git.branch` with a `git:template.branch` over it shows both, and a leaf whose expression fails shows the failure as its value. The cached rows are read after the leaves render, so a record a render's read ran on a cold daemon (`python.version` reading `comb.mise.python` runs mise) is a row of the same `status`. A rendered row's AGE is that of the oldest cached value its render used (a `comb.*` or provider ref, read lazily or not), and `-` when it used none, as for a template over `env` or `exec()` alone: a rendered value has no age of its own. In `-f json` such a row has no `age_ms`. A rendered row carries `source: template` and `kind: template`, is marked in the VALUE cell (cyan with colour on, a `▸ ` — `> ` under `--ascii` — with colour off), and is selectable with `--filter lifecycle=template`. The new SOURCE column names what produced each row's value — a Source of the provider, `put`, `config(<file>)`, or `template` — and sits after FIELD in `human`/`table`, after FIELD in `tsv`/`csv` (14 columns now, not 13; the CSV header gains `SOURCE`), and as `<KEY>_SOURCE` in `sh`. In `human` the cell keeps its tail past 24 characters (less at a narrow `--max-width`) — a `config(<file>)` label is a whole path, and uncapped it pinned VALUE and PATH at their floors across the table — unless `--no-trunc`. Anything parsing `status` by column position must shift.
- **BREAKING (pre-1.0, CLI): `comb status` hides facet rows and absent values by default, and `--filter` takes `!=` and the keys `facet`, `source` and `value`.** The default table is the values a read would answer: two filters apply unless the user gives one on the same key — `facet=-` hides facet rows (`aws:template`, `*:cache`), which describe a provider rather than answer a read, and `value!=-` hides absent values — and `-a`/`--all` drops both, in every format (`-f json` included: a script that read the raw template rows passes `-a`). Every filter key now takes `key!=value` as well as `key=value`. `facet` matches the facet after the colon (`template`, a glob such as `*`, or `-` for none), `source` globs the SOURCE label shown, and `value` globs the value shown, with `-` for absent (a glob matches present values only, so `value=*` is "not absent"). `provider` now matches the base name, so `provider=aws` selects `aws` and `aws:template` alike (combine it with `facet`); before, it matched the whole `aws:template` string. A template leaf that renders nothing is now a row of its own with value `null` and kind `template` — hidden by the default, shown by `-a` or `--filter value=-`, as `null` (dimmed with colour on) in the table — where before it was no row at all.
- **BREAKING (pre-1.0, wire + CLI): a record's label reads in one function form wherever it is shown.** A `:cache` answer's `source`, a `status` row's `source` on the wire, and the SOURCE column of `comb status` in every format (and what `--filter source=` matches) are `source(<name>)` for a Source (`source(head)`), `config(<file>)` for a configuration seed, `computed(result)` / `computed(return)` for a leaf a provider line computed, `put`, or `template` for a row `comb status` rendered. `:cache` said `config:<file>` and `computed:return`, and `status` gave a Source's bare name (`head`), so a Source named `template` or `put` read as that word. The stored labels are unchanged; only what leaves the daemon is presented, by one function. Configuration error messages still name the file as `config:<file>: …`.
- **BREAKING (pre-1.0, CLI): `comb status` sorts by provider, then field, by default.** `--sort default` was path, then provider, then field, so the global rows came first as a group and a provider's rows split across one group per directory (the rendered template rows, stamped with the caller's directory, landed apart from its global data). It is now the provider's base name, its plain rows before each facet's (by facet name), the field, then the path with the global entry first. `--help` now lists the `lifecycle` and `poll_interval` sorts too.
- **BREAKING (pre-1.0, wire): an address nothing answers is a miss at any depth — the `unknown field` error is gone.** `get p.project.nonesuch` where `project` exists, or `get p.lit.x` where `lit` is a scalar, used to answer `{"ok":false,"error":"unknown field: …"}` while `get p.nonesuch` was a plain miss; and the client's own walk past a *template* scalar already followed the miss rule, so the same shape of address had two answers depending on which half of the tree held it. One rule now: a node that is not there is a miss. The CLI's text/sh formats print nothing and exit 0 as for any miss; the structured formats report the miss and exit 2. A typo in a sub-path is therefore no louder than a typo in a field name — which is what it always was for the top level.
- **BREAKING (pre-1.0, wire + CLI): a `put` replaces the value at its own address; nothing merges implicitly.** `comb put my '{"b":2}'` states all of `my`: a record written earlier at `my` and not named again is gone from the read, and `comb put my.b 2` replaces only `my.b`. Each put address keeps its own stamp, so writing `my.b` no longer renews the age of `my.a`, and `status` lists one row per address (`field` is the address). A put layers over a Source and over `config:` seeds at the same address: the lower layers are hidden, not removed, and removing the put shows them again. A `null` inside the data is absent from what the put states. The directory chain keeps its per-leaf merge: a nearer directory's put replaces only the lower layers of its own directory. The `--replace` flag (wire `"replace"`, `Client::put_with`) is gone — replacing is the only way a put writes.
- **BREAKING (pre-1.0, wire): a `put` may address any namespace, including a provider's.** `put` used to reject any key a builtin or script provider owned — `cannot store under 'git': name is used by a builtin or script provider` — which made a provider's namespace entirely closed. A put now layers over what a Source produces: `comb put git '{"note":1}'` makes `comb get git` answer `{note: 1}` at that directory, and `comb put git.branch '"x"'` hides the Source's `branch` there. The Source keeps refreshing its own layer beneath the put, and removing the put (`comb put git.branch null`) shows it again at once. There is no ownership refusal and no per-record check: a put replaces the node at its own address, whatever Source or `config:` values sit at that directory. `ProviderRegistry::is_registered` survives only as the guard stopping `register_static` from shadowing a provider name; `put` no longer consults it, and a namespace becomes static only when no provider declares it. The CLI's own "put data must be a JSON object" pre-check is gone with it — whether a payload is legal depends on which node the key addresses, which only the daemon knows.
- **`put` with nothing to store creates nothing.** `comb put e '{}'` used to leave an entry carrying an empty `put` map, so `comb get e` answered `{}` for a namespace that had never been written to and `comb status` was unaffected either way. It is now an ok no-op: no entry, and the read is a plain miss.
- **Connecting to the daemon retries on a finer, geometric schedule, within a total budget.** `connect_with_retry` used to sleep 250ms, 500ms, then 1000ms between attempts, so a daemon that bound 20ms into a restart was still not reached for 250ms. Retries now start 5ms apart and double (5, 10, 20, 40, ... ms), clipped to a total budget of 1.5s (`DEFAULT_CONNECT_TIMEOUT`); `connect_with_retry_for(path, budget)` takes an explicit budget and `Client::with_connect_timeout(duration)` sets it per client, where zero means one attempt. Every SDK connect goes through this path.
- **`beachcomber` daemon API: `start_in_process`, `start_in_process_with_cancel` and `start_in_process_with_reaper` return `(JoinHandle<()>, DaemonReady)`.** `DaemonReady` is a oneshot that resolves once the socket is bound and connectable, and errors if the daemon refuses to start (config validation, bind failure), so an embedder awaits readiness instead of sleeping and retrying. `Server` gains `bind()` / `serve(listener)` / `spawn()` around the existing `run()`: `bind` returns synchronously with a listening socket, so a caller that binds first can connect immediately. `Scheduler::use_polling_watcher(interval)` selects the polling watch backend and skips the watch self-test — a diagnostic/test seam; the daemon path is unchanged.
- **BREAKING (pre-1.0, `libbeachcomber` API): `render::render_data` takes the output format.** Was `render_data(data)`, which rendered `text` and `sh` identically; now `render_data(data, format)`, where `"sh"` shell-quotes each rendered value and every other format name (`"text"`, `"json"`, anything unrecognised) renders exactly as before. `render::shell_quote` is newly public alongside it — the one POSIX single-quote helper, shared by the library's rendering and `comb status -f sh`.
- **BREAKING (pre-1.0, wire + CLI): `$HOME` is the global path, and a read resolves static records up the directory chain.** A request whose path canonicalises to `$HOME` — and a request carrying no `path` at all — addresses the global cache entry; the two are one address, so `comb put my '{"a":1}' --path ~` and a pathless wire `put` write the same record. A read at a path `P` now collects the **static records** (source `put`, and later `config:<file>`) from `P`, from every ancestor of `P` up to and including `$HOME` (up to `/` when `P` is outside `$HOME`), and from the global entry — nearest winning, record by record. `put my '{"a":1,"b":1}' --global` plus `put my '{"b":2}' --path ~/ws/project` makes `get my` read `{"a":1,"b":2}` anywhere under the project and `{"a":1,"b":1}` everywhere else, and clearing the project's `b` uncovers the global one again. **Provider-produced records do not walk the chain**: a `PathScoped` source's records are read at the addressed path and a `Global` source's at the global entry, which is what makes a provider declaring one field in both — mise's `<tool>` shape — resolve deterministically to the project record at a project path and to the global record under `--global`, with the two visible together in a whole-namespace read. `watch` follows the same chain: it subscribes to every entry on it, so a `--global` write wakes a watch opened in a project directory, and its frames are the same merged read `get` returns. This is layering, not a fallback — the chain is always merged, never "this entry if it has anything, otherwise that one" — so a record no nearer entry claims is inherited rather than shadowed, and a `put` at a path can no longer hide unrelated global records. A repository at `$HOME` is served from the global entry — the global entry's address is pathless but its directory is `$HOME`, so a path-scoped source addressed there runs at `$HOME` — and a query from any non-repository subdirectory of `$HOME` reads it there, on the one entry, rather than keying a second one.
- **A `get` reports the freshness of the record that answered it, not of the cache entry it came from.** With records resolving up the directory chain, "the entry's age" stopped meaning anything: the value returned could come from an ancestor, from the global entry, or from a Source keyed elsewhere, while `age_ms` reported whichever entry the request happened to address. `age_ms` and `stale` are now per record — a leaf reports its own Source's last refresh and whether that is past the Source's expected interval, restoring what field reads gave before chain resolution; an object assembled from several records reports the **largest** of their ages and is stale if any one of them is; and a static record (`put`, or `config:<file>`) reports the time since it was written, stale only if its `put` carried a `ttl`. A response with no `data` carries neither field, so a template-only hit has no freshness rather than a fabricated zero. `Cache::read_merged` carries one freshness reading per record, keyed by the record's dotted tail, and merges each layer from a borrowed map — cloning only the values that survive instead of every contributing source map on every read.
- **`--force` re-executes every source the read returns, each at its own scope, and never evicts a whole entry.** It used to drop the addressed cache entry and let the miss path repopulate it, which got two things wrong once a namespace could span entries: a `Global` source lives at the global entry, so a `--force` naming a directory never reached it, and the eviction took the entry's static records with it. Coldness is decided per source for the same reason — a warm sibling used to stand in for a cold one, so `comb get mise` at a project path could return the global tool set alone until the scheduler filled the project source in. Both are now per source, at the entry that source's declared scope keys.
- **BREAKING (pre-1.0, CLI): `comb put` defaults to the current directory, `comb get` and `comb put` both take `--global`, and neither uses the session `context` op any more.** `comb put my '{"a":1}'` used to write the global entry while `comb get my.a` in the same shell read the cwd — a mismatch papered over by a retry. Both now default to the cwd, so a plain put/get pair round-trips where you are standing, and `--global` on either addresses `$HOME` (sent as a request with no `path` field) for the machine-wide value. `--global` together with `--path` is an argument error, exit 2. `comb eval` takes the cwd default too, since it is a query like the others. Every `get` the CLI sends now carries its path explicitly — including the virtual-field dependency fetches in `comb get` and `comb eval`, which previously relied on the connection context and would otherwise read the global entry for a path-scoped dep like `git`. The wire `context` op is unchanged and still what the SDK sessions use. Scripts that relied on a bare `comb put` writing globally need `--global`; the Lua and Node SDKs' subprocess transports pass it for a pathless call so their behaviour matches the FFI transport exactly.
- **A `put`-created row's status kind is now `static`, not `virtual`.** `comb status`'s `kind` column (and its JSON/CSV/TSV/sh renderings) reports `static` for a namespace no code or config registered — every one of its records is `put`, or later `config:<file>`, matching the vocabulary `docs/canon/provider_source.md` uses for such a record. `comb status --filter lifecycle=` accepts `static` in place of the old `virtual` value. `introspect providers` likewise reports `static` where it said `virtual`. The row's `source` field is now the literal `put`, not the internal `virtual` label the daemon used to write it under. Naming only — the underlying model (a namespace with no Source instances, holding only stored data) is unchanged.
- **BREAKING (pre-1.0, wire): `refresh` re-executes only the Sources its key demands, and a key with no Sources is an error.** `refresh` used to hand the scheduler a provider name and let it fan out to every Source of that provider at whatever path the request carried, so a `refresh` of `git.branch` re-ran `head`, `refs`, `diff`, `lineage` and `status` — four subprocess Sources nobody asked for — and a `Global` Source was re-run at the addressed directory rather than at the global entry where its records live. The key now selects Sources exactly as it selects which ones a `get` warms: a `refresh` of `git` is every applicable Source, one of `git.branch` is the one Source that owns `branch`, and each runs at the cache entry its own scope keys, the way `--force` already did. `SchedulerMessage::Refresh` carries a `demand: SourceDemand` for it, and a server with no scheduler attached runs the same set inline, so `refresh` has one meaning on every server. **A key naming no Source is now `{"ok":false, "error":"nothing to refresh: <key> has no sources"}`** — a static namespace (`put`- or config-created), an unknown name, or a field no Source owns. A static namespace used to answer `{"ok":true}` and do nothing, which is a silent success for work that cannot happen; `refresh nope` used to be `unknown provider`, which named the wrong problem. Reading configuration afresh is not a refresh — the config watcher does that, so `refresh p:template` is the same error. The facet-syntax check still runs before anything else. The `Refresh` arm builds the same `QueryPlan` every other op does, which leaves `query::resolve_path` with a single caller inside `query.rs`. **The Lua SDK's subprocess transport no longer offers `refresh`**: it faked the op by shelling out to `comb get --force`, short-circuiting to `ok` whenever `comb status` showed a `put` record, which is exactly the silent success this change removes — and there is no `comb refresh` to shell out to. `Client:refresh` over `subprocess` now returns `err.kind == "unsupported"`, as `hello`, `introspect`, `resolve`, `eval` and `watch` already do there, and as the Node SDK's subprocess tier already did for `refresh`; the LuaJIT `ffi` transport calls `bc_refresh` and is unaffected.
- **The config self-watch re-arms after every change, and `comb check config` validates the file client-side.** The watch classifies each change (an edit confined to `providers` reloads in place, above; anything else restarts) and keeps watching afterwards instead of firing once and exiting. The new layers are validated first, by the same per-file rules startup applies: on any error nothing is touched, the previous providers and seed keep being served and each error is logged (`comb check config` reports the same ones). Records written by `put` are untouched by a reseed, whatever configuration says: a reseed drops only `config:`-labelled records, and any leaf the `put` map still holds is dropped from the write plan before it can be overwritten, so a `put` wins at a leaf configuration also sets and survives one whose config record has since been deleted. It is spawned by the daemon runtime (which owns the cache and registry a reseed needs) rather than by the `comb daemon` subcommand; `spawn_config_self_watch_with` takes `FnMut(ChangeKind)` and the argument-free `spawn_config_self_watch` wrapper is gone. It tracks one mtime per file in the composed set rather than a single newest timestamp, so an edit to one file is seen even while another carries a far-future mtime, and it takes a stop token, so the thread exits with the daemon. **`comb check config` validates the config file client-side** as well as reporting the daemon's view, prints both under aligned `daemon` and `local` tags as one verdict list under one count, and exits 1 when the local pass produces warnings, 2 when it produces errors.
- **BREAKING (pre-1.0): a value expression with no tags at all is now its literal text — the bare-expression form is gone.** Canon `field_resolution.md` invariant 14 defines two forms: exactly one `{{ expr }}` tag, which keeps the expression's natural type, or a template (literal text and/or several tags), which is always string-valued. A tagless source used to be accepted as a third, bare form equivalent to the single-tag one, so `env.A != ""` compiled and kept its bool; it is now literal text like any other tagless template, so `comb eval hello` prints `hello` rather than treating `hello` as an expression, and `comb eval 'env.A != ""'` prints the string `env.A != ""` verbatim. Every shipped template in `defaults/` is written in the tagged form; a template of your own written bare is read as literal text under the new rule and must be wrapped in `{{ }}`.
- **BREAKING (pre-1.0, CLI): `comb get -f json` prints the value, not the daemon's response envelope.** A daemon-backed key used to print `{"ok":true,"data":…,"age_ms":…,"stale":…}` under `-f json` while a virtual or `env.*` key printed the bare value, so the shape of the output depended on which route inside `comb get` answered. Canon `field_resolution.md` says `--format json` emits the bare value with no metadata wrapper, and every key now resolves through `libbeachcomber::resolve`, so `comb get git.branch -f json` is `"main"` and `comb get scanline -f json` is the namespace object itself; a multi-key `-f json` is an array of those values in key order, `null` holding the place of a key that produced none. Metadata is asked for through the `:cache` facet — `comb get git:cache.branch`. Anything scripted as `comb get … -f json | jq .data` drops the `.data`.
- **BREAKING (pre-1.0, CLI, C ABI, SDKs): `comb get`, `comb eval`, `bc_resolve` and `bc_eval` resolve through one function.** Each used to carry its own orchestration — `comb get` its routing between an env-first probe, a client-side evaluator and the daemon; `comb eval` a second copy; `bc_resolve`/`bc_eval` a third over a compiled-in registry — and nothing asserted that any two agreed. All four are now thin adapters over `libbeachcomber::resolve` (see Added): `comb get` is parse keys, ensure daemon, one session, `resolve` per key with this process's environment and directory and `exec()` on, render; `comb eval` is the same with `resolve::eval`; `bc_resolve`/`bc_eval` build `Inputs` from their `cwd`/`env_json` arguments and the client's `exec` option. So every SDK's `resolve` docstring says "the same value `comb get` returns" and means it, a template put at runtime is picked up by all of them on the next read, and a nested address (`scanline.widgets.foo`), a group (`scanline.widgets`) and a whole namespace (`scanline`) answer identically everywhere. `get.rs` lost `fetch_daemon_deps`, `fetch_daemon_deps_for_namespace`, `is_virtual_namespace_key`, `is_client_side_key`, `key_needs_daemon`, `BUILTIN_DAEMON_PROVIDERS`, `is_daemon_provider`, `evaluate_client_side`, `path_for_key` and the namespace merge.
- **BREAKING (pre-1.0, CLI): `comb` always requires the daemon.** `comb get conda` and `TF_WORKSPACE=dev comb get terraform.workspace` used to answer from the compiled-in defaults without starting one, and `comb eval` skipped the daemon when an expression named no daemon ref. The client holds no templates now — they are daemon data — so every `comb get` and `comb eval` ensures the daemon first and resolves against it, a key it answers without a request (`env.HOME`) included.
- **`text` and `sh` flatten at every depth.** `comb get scanline -f text` used to print `widgets.clock={"format":"%H:%M"}` — one level of `key=value`, then JSON text. `render_data` now emits one `a.b.c=value` line per leaf at any depth, objects by key and arrays by decimal index, sorted, and under `sh` every value is shell-quoted; `comb watch -f text`/`-f sh` render through the same function.
- **A configuration error in one template fails a namespace query, naming the leaf; a runtime failure omits it.** Every failure inside a namespace used to be silently dropped, so a cycle or a syntax error in `scanline.widgets.foo` made `comb get scanline` quietly answer without it. A template that does not compile, cycles or exceeds the depth limit is now a `ResolveError::Config` that fails the whole query — `comb get scanline` exits 2 with `scanline.widgets.foo: virtual field cycle detected: …` — because someone has to go and edit it; a runtime failure (a failed or disabled `exec()`) is still omitted from the assembled object and fails only a single-leaf query.
- **A rejected top-level key is an error in every format; a rejected ref inside a template is a missing ref.** The daemon answering `ok:false` to the key the caller asked for — an invalid facet key (`a:b:c.x`), an unknown provider — is `FetchError::Rejected` carrying the daemon's own words, printed on stderr with exit 2 in every format, `text`/`sh` included (where a plain miss stays silent and exits 0). The same rejection while binding a ref *inside* a template is a missing ref, undefined and falsy at any depth as canon says, so a template can `{{ maybe.x or 'fallback' }}` over a namespace that does not exist yet.
- **BREAKING (pre-1.0, C ABI, SDKs): `bc_resolve` on a bare provider returns the whole merged namespace.** It used to evaluate the provider's path expression, or fail with `<p> has no declared path expression`. `bc_resolve(c, "python", cwd, env)` is now the same object `comb get python -f json` prints: the cached fields deep-merged with the rendered template tree.
- **BREAKING (pre-1.0, C ABI): a `server_error` envelope's message is the daemon's words alone — the `server error: ` prefix is gone, so every SDK reports the same text the CLI prints.** `{"ok":false,"error":{"kind":"server_error","message":…}}` carried `CombError`'s Display, `server error: nothing to refresh: fx2 has no sources`, where `comb refresh` printed `nothing to refresh: fx2 has no sources` and the Node and Lua subprocess tiers reported the same — so one SDK's message differed by transport, and Node's `ServerError` prefixed it a second time. The envelope's `kind` already says whose words they are; `message` is now exactly the daemon's `error` string, on every tier. Every other kind's message is unchanged. Anything matching `server error:` on an FFI envelope drops the prefix.
- **`comb watch <key>` with no path now addresses the caller's cwd, like `get`/`put`/`refresh`** — it used to always address the global entry. `watch` also takes a `[path]` positional and `--path`/`--global`, the same spellings the others take. A bare `comb watch key` now sees a globally-put key again, through the same chain walk `get` uses.
- **BREAKING (pre-1.0, C ABI + CLI, SDKs): `comb watch`/`bc_watch_open` resolve through the library, like `get`/`bc_resolve`.** `bc_watch_open(client, key, cwd, env_json)` — `cwd` is required and `env_json` nullable, the same inputs `bc_resolve` takes; there is no global-slot form, as there is none for `bc_resolve`. Every SDK's `watch` follows: all six are now `watch(key, cwd, env=None)` (or that SDK's idiom for it — Node and Lua take an options object, mirroring how each SDK's `resolve` already takes its inputs). A watch event is now the *resolved* value — what `comb get`/`bc_resolve` returns for the key — not the daemon's `{data, age_ms, stale}` frame, so `age_ms`/`stale` are gone from watch events on every surface. `comb watch -f json` frames are therefore bare values, compacted to one line, not response envelopes; a miss frame now prints nothing, where it used to print a blank line. `comb watch env.X` is exit 2, `env keys cannot be watched` — an env key has no daemon record to subscribe to. The Node SDK's subprocess tier no longer implements `watch`, joining `resolve`/`eval` there: a resolved watch is `resolve` over time, and the tier already can't carry env fidelity for those; the FFI transport is required for `watch`.
- **BREAKING (pre-1.0, wire): `introspect providers` no longer carries `scope`.** Neither a provider (`"scope": "global"|"path"`) nor a Source reports one; whether a Source has a root is a question asked of a directory, not a property of the provider. `comb check providers` drops the column.
- **BREAKING (pre-1.0, cache): `mise` is one Source, `tools`.** The `global` and `project` Sources are gone. Its instance at a project root reports the project's tools and its instance at `~` the global ones plus those of a `mise.toml`/`.mise.toml` in `$HOME` itself (which wins a clash), so from `~/ws/proj` `mise.node` is the project's and `mise.go`, set only in the global config, is found at `~`; `comb get mise` merges both. Anything keyed on `mise:cache` records for source `global` or `project` now sees source `tools`.
- **BREAKING (pre-1.0, Rust API): `SourceScope`, `SourceMetadata::scope`, `Source::canonical_path` and `query::source_dir` are gone.** A Source overrides `root(dir) -> Result<Option<String>, String>` (default `Ok(None)`: one instance, at `~`), `execute` takes the instance's working directory (`$HOME` for the instance at `~`), and `SchedulerMessage::{QueryActivity, Refresh}` carry the instances instead of a path and a `SourceDemand`. A record a Source makes is read only at an instance the read reached, so a key no Source declares (and no `<tool>` sentinel covers) is not found in a Source's map by a field read.
- **BREAKING (pre-1.0, Rust API): `Source::execute` returns `Result<SourceResult, String>`.** `Err` is a failure — nothing is written and `failback` counts it. `Ok` with no fields is a successful empty result that replaces what the instance stored, so a Source that legitimately reports nothing (a config Source whose `result` renders none, `git` outside a repository, `battery` on a desktop) clears its records instead of leaving stale ones, and is no longer counted as failing. An empty map reads as no data: a namespace made only of empty maps is a miss.
- **A rooted `Watch` or `WatchAndPoll` Source with no watch patterns registers no watch at its root.** It used to register the root and match every event under it, so a config Source whose `watch(...)` named no relative path re-ran on any write in its directory. It now refreshes by poll, by demand and by its absolute paths only; a Source whose `watch(...)` names no relative path is woken by file events at its absolute paths only.

### Removed

- **BREAKING (pre-1.0, config): script providers.** `type = "script"`, `backend = "script"`, a bare `command`, and the keys only they read (`command`, `output`, per-field `scope`) are errors, at the level they appear. A script provider is a Source whose `data` calls `exec()`: `[providers.vpn] command = "vpn-check" output = "kv"` with `invalidation.poll = "10s"` becomes `[daemon.providers.vpn.sources.main]` with `data = "{{ exec('vpn-check') | fromini }}"`, `result.<field>` lines, and `return = "{{ result | poll('10s') }}"`.
- **BREAKING (pre-1.0, config): HTTP providers.** `type = "http"`, `backend = "http"`, a provider-level `url`, and the keys only they read (`url`, `method`, `headers`, `body`, `extract`, `default_timeout`) are errors, at the level they appear. An HTTP provider is a Source whose `data` calls `url()`: `[providers.claude] type = "http" url = "https://status.anthropic.com/api/v2/summary.json" extract = "status"` with `invalidation.poll = "60s"` becomes `[daemon.providers.claude.sources.summary]` with `data = "{{ url('https://status.anthropic.com/api/v2/summary.json') | fromjson }}"`, `result = "{{ data.status }}"` (what `extract = "status"` served: all its fields; `result.indicator = …` picks one), and `return = "{{ result | poll('60s') }}"`. The old automatic fallbacks are gone (a non-JSON body no longer becomes a `body` field, a scalar extract no longer becomes `value`), so write explicit `result.<field>` lines. `${VAR}` in a URL or header is now `env.VAR` in the `url()` call. A non-2xx response fails the render, so the Source fails and its `failback` applies.
- **BREAKING (pre-1.0, config + plugin ABI): library providers.** `type = "library"`, `backend = "library"`, `library_path`, the provider-level `fields` and `invalidation` tables, and the plugin JSON metadata they came with are errors, at the level they appear. Both library ABIs are gone with them: the multi-source symbols (`bc_source_count`, `bc_source_metadata`, `bc_source_execute`) and the legacy ones (`beachcomber_provider_metadata`, `beachcomber_provider_execute`, `beachcomber_provider_free`). A library provider is a Source whose `data` calls `plugin(name, symbol, args...)`, found on `[daemon.plugin] path`: `[providers.gpu] type = "library" library_path = "/opt/beachcomber/libgpu.so"` becomes `[daemon.providers.gpu.sources.main]` with `data = "{{ plugin('gpu', 'read_state') }}"` and `result.<field>` lines (with `libgpu.so` in a directory on `[daemon.plugin] path`, by default `~/.config/beachcomber/plugins`). The library exports one function per call, `const char* symbol(const char* input)`, instead of metadata and execute: the Source declares the fields, schedule and root.
- **BREAKING (pre-1.0, config): the `[providers]` root.** Its knob blocks (`[providers.<p>.<s>]` with `failback_count`/`failback_interval`, and `poll_interval`, `poll_count`, `fsevent_patterns`, `fsevent_abs_paths`, `fsevent_reinstates`, `type`, `scope`, `marker`, `budget_execute`, `budget_stat`) and the provider-level `enabled` are gone, and with them `Config::providers`, `source_override`, every `resolve_*` knob method and the warnings that said a provider block named no registered Source. A top-level `[providers]` is `unknown table [providers]`, naming its file and where its contents went (`[daemon.providers.<p>]` for the daemon's settings, `[client.providers.<p>]` for the client's). A built-in Source is retuned by its `return` (below). A provider is switched off by `[daemon.providers.<p>] enabled = false` (see Added), which is not the old provider-level `enabled`.
- **BREAKING (pre-1.0, config): `[lifecycle]`, `[failback]` and `[tree]`.** Each is `unknown table [<name>]`. `[lifecycle] idle_shutdown_secs` is `[daemon] idle_shutdown`; `poll_interval`, `poll_live_count`, `fsevents_reinstate`, `cache_lifespan`, `grace_period_secs`, `failure_reattempts` and `failure_backoff_interval` are removed, not deprecated (the startup warnings about them are gone). `[failback] count`/`interval` were parsed and never consulted: a Source's failback is on its `return` line, or the engine's `failback('1s', 3)`.
- **BREAKING (pre-1.0, config): `[daemon]` takes a closed list of keys.** `socket_path`, `log_level`, `timeout`, `env_file`, `watchdog_interval`, `watchdog_threshold`, `idle_shutdown`, `budget`, `plugin` and `providers`; any other is `unknown key '<k>' in [daemon]`, and so is a top-level key outside `[client]`/`[daemon]` (`unknown key '<k>' at the top level`). Values are type-checked per file. `log_level` must be one of `off`, `error`, `warn`, `info`, `debug`, `trace` (a misspelling no longer logs at `info`); `timeout` is at least `1ms` and `idle_shutdown` at least `1s` (`0` made every refresh fail, or shut the daemon down the moment it was idle); `env_file` and `socket_path` may not be empty; `watchdog_threshold` without `watchdog_interval` is an error.
- **BREAKING (pre-1.0, config): a mistyped setting is an error, not the default configuration.** `Config::load` used to fall back to defaults when the composed file did not deserialize (`[daemon] provider_timeout_secs = "x"`, a `[daemon]` that is not a table). The daemon now refuses to start and `comb check config` fails, naming the file; the check reads the files the `Config` was composed from, so an edit after the load cannot slip past it, and an in-memory `Config` has its own trees checked. `watchdog_interval = "0s"` (which panicked `tokio::time::interval`) and sub-second watchdog values (silently ignored) are errors: whole seconds, at least `1s`; a `watchdog_threshold` below the interval is an error. A file that is not valid TOML (`socket_path = `) is the same kind of error, in `config.toml` or a `conf.d` file: it was skipped with a log line, so `comb check config` passed and the daemon ran on the other files, while the config self-watch refused the same file. One reader (`Config::read_layers`) now returns each file's error beside the layers it read, startup and `comb check config` report them, and the watch uses the same loader.
- **BREAKING (pre-1.0, `comb check` wire): `introspect config` reports `config_source_count`** (the `[daemon.providers.<p>.sources.<s>]` tables, prototypes and retunes excluded) in place of `provider_count_from_config`, which counted a field that no longer exists; `comb check config` prints `N config Sources`.
- **BREAKING (pre-1.0, config): comb no longer reads `config.toml` or `env` from `$XDG_CONFIG_DIRS`; put them in `$XDG_CONFIG_HOME/beachcomber`.** The configuration is the config home's `defaults/`, `config.toml` and `conf.d/` (what the daemon watches, seeds and reloads; a system-dir file never was), and the default variables file is `env` beside `config.toml`. `config_path_if_exists` is gone: `comb status` and `introspect` report the `config.toml` that was loaded, or none if the file does not exist.
- **BREAKING (pre-1.0, config): `[daemon] socket_path = ""` is an error.** An empty override broke every client (`daemon not responding: Invalid argument`); leave the key out for the default.
- **BREAKING (pre-1.0, wire + CLI + SDKs): the metadata suffixes `:age`, `:stale`, `:fresh`, `:cache` (the bool) and `:source`.** `git.branch:age` now addresses a field named `branch:age`, an ordinary miss: a key has one colon form that means something, the facet, with its colon in the head (below it a colon is just a character; see the key grammar under Changed), and `KNOWN_METADATA_SUFFIXES` and suffix stripping are gone. Ask the `:cache` facet instead — `git:cache.branch` carries `age_ms`, `stale` and `source`. `:fresh` (`!stale`) and the bool `:cache` (whether this request was served from cache, a per-response fact rather than field metadata) have no replacement. `p:put:age` is `invalid facet key: p:put:age`.
- **BREAKING (pre-1.0, config): `fsevent_lifespan`.** It was a second spelling of the poll lifespan, and is an error wherever it is written; a Source's Active window is its poll interval × count, and a watch-only Source takes the default 60 s × 12.
- **BREAKING (pre-1.0, Rust API): `KeepAlive` and `SourceMetadata::keep_alive`.** The Active window is the strategy's `interval × count`. `DecayStep::Step1..Step4` is a plain step number bounded by the entry's `decay`.
- **BREAKING (pre-1.0, CLI + Rust client + C ABI + SDKs): `comb put --null`, `put_null`, `putNull` and `bc_put_null`.** They were a second spelling of a put whose data is JSON `null`, which already removes the put at that address. Removal is now the ordinary put with the language's null: `comb put <node> null`, `Client::put(key, serde_json::Value::Null, …)`, `bc_put(c, key, "null", NULL, path)`, Python `put(key, None)`, Go `Put(key, nil, …)`, Ruby `put(key, nil)`, Node `put(key, null)`, Lua `put(key, nil)`. `data` is required everywhere: `comb put <node>` is a usage error and a wire `put` without `data` is `invalid request: missing field `data``. `--null` is an unknown argument (exit 2). The `bc_put_null` symbol is gone from `beachcomber.h`.
- **BREAKING (pre-1.0): `provider.source` and `provider.source.field` key addressing.** `KeyParse` had four variants; `Source`/`SourceField` let a second (or third) key segment resolve to a whole registered source when it happened to name one — `git.refs` returned every `refs` field and `git.refs.ahead` returned `ahead` via that route, alongside the field's own `git.ahead`. One field, two addresses, and the only way `parse_key` could tell a source from a field apart was by asking the `ProviderRegistry` — a source name is metadata on a record, never part of an address (`docs/canon/provider_source.md` "Record"). `KeyParse` is now `Provider(String)` / `Field(String, String)` only, and `parse_key` no longer takes a registry at all. `get git.refs` and `get git.refs.ahead` now miss like any other unknown field; `git.ahead` is unchanged and is the field's one address. `watch git.refs` still opens — an unknown field is a miss on the wire, not a rejected watch. `mise` is the one provider where this is a capability loss, not just a naming cleanup: `mise.global` and `mise.project` were the only way to name the global and the project tool set explicitly. Both sources declare the same dynamic `<tool>` field name, but live in different cache entries — `"mise"` for the global source, `"mise\0<root>"` for the project one — so `comb get mise.<tool>` at a project path reads the project record and `comb get mise.<tool> --global` reads the global one; what's gone is naming either set explicitly. Also pre-existing, stated here so the record is complete: `source_for_field("mise", "<tool name>")` is `None` — the declared field is the `<tool>` sentinel, not a real tool name — so `comb get mise.node` triggers no cold-miss execute and only answers once `comb get mise` or the scheduler has already warmed the entry.

- **BREAKING (pre-1.0): the 0.9.0 global-entry fallback for `put`-created namespaces, and the CLI's ambient-cwd retry.** A `get` at a path used to read the whole answer from one entry: the requested path's entry when it held anything, and the global entry otherwise. Whichever entry answered answered alone, so a `put --path` of one record hid every unrelated global record of the same namespace, and the fallback was all-or-nothing rather than per record. The chain resolution above replaces it — the global entry is simply the last link of every path's chain, and a nearer record shadows a farther one by name rather than by entry. `Cache::has_entry` is no longer consulted on any read path. The CLI's companion hack goes with it: `comb get` used to notice a miss when the path it sent was the implicit cwd default and silently re-query on a second, context-free connection. Both halves existed to make a pathless `put` reachable from a directory; the chain does that directly, in the daemon, for every client.

- **BREAKING (pre-1.0, CLI): `comb init --write-config`.** It appended a copy of the built-in virtual-field defaults to `config.toml` behind a sentinel comment; the defaults are now files the daemon writes to `~/.config/beachcomber/defaults/` (see Added), and `comb init --write-config` is a clap error. `VirtualFields::to_config_toml` goes with it.

- **BREAKING (pre-1.0, `libbeachcomber` API, C ABI, SDKs, config): the client-side template registry is gone — templates are daemon data.** `libbeachcomber::virtual_fields::VirtualFields` (the registry), its compiled-in `BUILTIN_DEFAULTS`, `EvalContext`, `evaluate_namespace`, and `eval::{daemon_refs, fetch_daemon_data, evaluate}` no longer exist: every surface resolves through `libbeachcomber::resolve`, which fetches each template from the daemon (`provider:template`) alongside the data it references and renders it client-side, so a client holds no template of its own. The `overrides` those served go with them — `bc_resolve`/`bc_eval` no longer take an `overrides_json` argument, and no SDK `resolve`/`eval` takes an `overrides` parameter; a template is set with `put` to `<p>:template` or in `[client.providers.<p>] template.*`. Reference discovery is one classifier: `eval::discover_refs` keeps every segment of a `P.rest…` ref (`foo.object.key` is `Resolved("foo", "object.key")`, the leaf the resolver fetches) rather than cutting at two; `env.*` and `cache.*` classify as before. `render_template` is unchanged. In configuration, `[providers.<p>.virtual]` — the 0.9 home of a provider's templates, which both `validate_providers` and the source parser used to skip by name — is now an error, as is the whole `[providers]` table: `comb check config` and daemon start report `unknown table [providers]: a provider's settings are [daemon.providers.<p>] (the daemon's) and [client.providers.<p>] (the client's); a built-in Source is retuned by [daemon.providers.<p>.sources.<s>] return; templates live in [client.providers.<p>] template.<leaf>, decay in [daemon.providers.<p>.cache._]`, and `Config::virtual_fields()` is gone.

- **BREAKING (pre-1.0, config, `libbeachcomber` API): path expressions and the `path` provider setting.** A provider used to be able to declare, and `[providers.<p>] path = "…"` to override, a client-side jinja expression over `cwd` and `env.*` that computed the cache entry a query read — the mechanism behind the env-selected kubeconfig path. Nothing computes an entry's path any more: a query addresses the caller's directory, `--path`, or `--global`, and static records resolve up the chain from there. `libbeachcomber::path_expr` (`evaluate_path`, `path_expression_for`) and `Config::path_expressions()` no longer exist, and a `path` key under `[providers.<p>]` is now an error at daemon start and from `comb check config`, with the rest of `[providers]`: `unknown table [providers]: a provider's settings are [daemon.providers.<p>] (the daemon's) and [client.providers.<p>] (the client's); a built-in Source is retuned by [daemon.providers.<p>.sources.<s>] return; templates live in [client.providers.<p>] template.<leaf>, decay in [daemon.providers.<p>.cache._]`. A query addresses the caller's directory, `--path`, or `--global`. Because `path` is no longer a setting, it is no longer a forbidden key — `[client.providers.<p>] template.path = "…"` is an ordinary data leaf, seeded as `<p>:template.path`.

- **BREAKING (pre-1.0): the `kubecontext` and `talos` daemon providers.** Both read a config file at a path the client had computed from a path expression, so they went with it. Their fields are now templates in the managed defaults the daemon writes to `~/.config/beachcomber/defaults/` — `kubecontext.toml` renders `context` and `namespace` through `exec('kubectl config current-context')` and an `exec([…])` argv list, `talos.toml` renders `context` through `exec(['talosctl', 'config', 'info', …])` — which honour the shell's own `$KUBECONFIG`/`$TALOSCONFIG`, and the field names are unchanged, so `comb get kubecontext.context` keeps working. What changes is where they render: only where `exec()` is enabled — `comb get`, `comb eval`, `comb status` and `comb watch`, or an SDK client constructed with `exec` on; a client without it gets `exec() is disabled in this context`. The unused `provider::ProviderSource` enum goes in the same sweep. `query::read_chain` — which adds a provider's scope entry to a read's chain when it is not already a link — stays, and for a reason these providers obscured: every `PathScoped` walker (`git`, `terraform`, `asdf`, `direnv`, `mise`, `python`) walks to `/` while the chain stops at `$HOME`, so a project marker *above* `$HOME` keys the entry where the chain from below never reaches; `Cache::read_merged` and the watch subscription both walk `read_chain`, and `tests/suite/path_chain.rs` pins the case.

- **The CLI's ad-hoc `ClientSession::watch`/`read_watch_event`.** These opened a second, independent connection via `libbeachcomber::Client::watch` and adapted its raw `{data, age_ms, stale}` frames into a `Response`, because `libbeachcomber::Session` had no watch of its own to drive from `comb watch`'s persistent connection — leaving that connection's socket idle for the watch's whole lifetime. `comb watch` no longer opens a `ClientSession` at all; it drives `ResolvedWatch::open`/`next` directly (see Added), so the adapter, and the spare socket it held, are gone with it.
- **BREAKING (pre-1.0, `libbeachcomber` API): `WatchStream::read_line_buffered` and `WatchStream::set_read_timeout`.** A watch stream's socket is non-blocking and is read only once `poll(2)` says there is something to read, by `watch::ResolvedWatch` and by `WatchStream::next_event` alike, so neither a bounded read nor a read timeout has a use.

### Fixed

- **A kept `root` is found again when a directory on its walk changes.** A config Source's rendered `root` was kept per directory until the instance it named was evicted, so a marker created after the first render (an `.envrc` in a subdirectory, a `.marker` a `lup` looks for) was not seen for as long as the instance lived, hours for one read every prompt; and the nothing a `| nearest` Source's root found was kept 5 s, so a marker created in that time was missed until then. A kept root now carries the stamps of the directories from the one asked about up to the root it found (up to `$HOME`, or `/`, when it found none), taken before the line rendered; a read checks them, one `stat` per directory, and renders the root again when one moved. Creating or removing a marker moves its directory's mtime, so the read after it has the new instance. The nothing a nearest Source found is checked the same way, with no timer; one not asked about for ten minutes is swept when another is kept. A root line that fails is still answered with its error for 5 s.
- **`comb watch` reports the daemon's refusal of a key in the daemon's words, as `comb get` does.** It printed `error: a:b:c.x: server error: invalid facet key: …`, where `get` prints `error: a:b:c.x: invalid facet key: …` and the C ABI and every SDK report the words alone; the `server error: ` was the client error's own label. A subprocess tier reading the line got it too.
- **A watch whose daemon has already answered and hung up gets the answer.** The fan-in set a read timeout before each read, and macOS refuses a socket option on a unix socket whose peer has closed (`EINVAL`), which the watch took for the end of the stream. So a watch on a key the daemon refuses (`a:b:c.x`), read after the daemon had sent the refusal and closed, reported `eof` instead of the refusal: every time after a 200 ms pause, and now and then under load. The socket is set non-blocking before the request goes out and never touched again, and a frame read before the close is answered before the end. FFI test `a_refusal_sent_before_the_connection_closed_is_still_the_answer` pins it against a stand-in daemon that has hung up before the first `bc_watch_next`.

- **On Linux a watched Source re-ran itself without end.** inotify reports every open, and the daemon took each for a change, so a Source that reads the files it watches refreshed itself: after one `comb get git.branch` in a repository, `git.head` reran on its own reads of `.git/HEAD` about 2,500 times a second, holding 1.5 cores for good. A recursive watch's own walk also reported every directory it opened, which, while the scheduler still awaited each registration in its loop (see Changed), filled the event queue behind a registration whose backend thread was waiting for room in it, so `comb status` hung (the Lua conformance runner's `status/returns_array.json` on Linux CI). A read (an open, a read, a close after reading) is no longer a change; a close after writing still is.
- **A render no longer copies the caller's environment.** Each render bound the caller's whole environment into its context as a fresh JSON object and converted it to an engine value, so with a shell's environment the copying outweighed the templates. The environment is now one engine value per resolution, shared by every render. `env.X`, `env['X']`, `env[var]`, `env | items`, `env | length` and a loop over `env` read it as before, in name order, and an unset variable is still undefined. The same status line with a 140-variable environment: 17 → 8.0 ms a render, within 1 ms of a minimal environment (`docs/performance.md` §3.2).
- **A resolution renders each node once.** A leaf several templates read — a theme group every widget reads, a derived leaf two others read — was rendered again for every read: `libbeachcomber::resolve` memoised fetches per `(key, path)`, not renders. It now keeps what each node resolved to for the rest of the top-level resolution, a render failure included, so the next reader is handed the value instead of rendering it again, and an `exec()` in a shared leaf runs once per resolution. A node asked for while it is being rendered is still a cycle, whatever it resolved to before, and `deps` and `Traced::oldest_input_ms` are unchanged: a read the memo answers used the inputs its first read counted. A status line of 12 widgets in the shape scanline's one-tree config takes, each widget its own resolution: 8.0 → 7.0 ms a render with a minimal environment, 22 → 17 ms with a 140-variable one (`docs/performance.md` §3.1).
- **BREAKING (pre-1.0, Rust API): the env file is loaded before the daemon starts a thread.** `Config::load_env_file` sets the process environment, which is sound only while one thread runs, but the daemon called it inside its tokio runtime, after the runtime's worker threads and the signal, self-watch and reaper tasks had started, under a SAFETY comment saying no thread had been spawned yet. `comb daemon` now loads it once, before it builds its runtime, so a Source's `env.X` and the commands its `exec()` runs see the env file's variables as before. `load_env_file` is an `unsafe fn` whose contract is that precondition, and `daemon::start_in_process` and its variants no longer load the env file: an embedder that wants it calls `load_env_file` before it starts a runtime of its own.
- **The configuration is read once per process, and `comb check config` judges it as the daemon would.** `comb check config --origins` listed four defaults by hand and missed the rest: it now lists every setting comb gives a value of its own that no file sets, read off the code that applies it, so `daemon.env_file` (the `env` beside `config.toml`) and a `daemon.watchdog_threshold` of three intervals show `default` too. `comb check config` loaded its Sources with the checking shell's variables alone; it now adds the env file's over them, as the daemon does, so a `~` in `[daemon.plugin] path` is the env file's `HOME` when the shell has none. The config watch read the files a second time when it started and judged the first change against that, so a setting edited while the daemon started was applied in place with the next provider edit instead of restarting it; it now judges against the configuration the daemon loaded. Starting a daemon no longer loads the configuration just to find the log file, and a `Server` built without one (a test, an embedder) reads no `~/.config/beachcomber`.
- **A reload no longer resets the age of configuration records it did not change.** Every reload reseeds every namespace's `template` and `cache` facets, and each `config(<file>)` record was rewritten with a fresh time, so `comb status -a` showed every template as written at the last reload. A file whose records in a namespace come back exactly as they were now keeps their time; an edit restamps that file's records in that namespace.
- **`tojson` exists.** The docs list it among minijinja's built-in filters and `exec()`'s `stdin=` error points at it, but minijinja's `json` feature was off, so `| tojson` was an unknown filter. It is on: `exec('cmd', stdin=(data | tojson))` passes structured data.
- **A dead client's `watch` lingered until the next write to the watched key.** The stream loop only noticed a gone client when a value change triggered a write and that write failed; until then the subscription, and the connection task holding it, stayed alive indefinitely. The loop now races the chain-change notification against the connection's read half in a `tokio::select!` — any completion of the read (EOF, an error, or even a protocol-violating extra write, since a watch never expects one) ends the watch immediately, dropping its subscription without waiting on a write.
- **A relative path on the command line named a directory below the daemon's cwd, not the caller's.** `comb g git.branch .` sent `.` to the daemon, which canonicalised it against the directory the daemon happened to be started in, so the answer depended on which shell first socket-activated it and every docs snippet using `.` was wrong by accident of history. `comb get`, `comb put`, `comb watch` and `comb eval` now make a relative `--path` or trailing positional absolute against the caller's cwd before sending it; `.` means where you are. When the caller's directory cannot be read (deleted, permission denied), a relative or absent path is now an error (exit 2, `error: current directory: …`) where it used to fall through to the global entry; an absolute path still works from such a directory.
- **A `put` below a repository root was invisible to a `get` from the same directory.** `comb put git.note 1` in `<repo>/sub` wrote the record at `<repo>/sub`, where `put` defaults, but `comb get git.note` from `<repo>/sub` first narrowed its path to the work-tree root and walked the directory chain from there, so a record between the two was never visited: `comb status` listed it while every read missed. The merged read now walks the chain from the requested path and takes the provider's own records from the entry its Sources resolve to (the work-tree root for `git`, the global entry for a `Global` Source), so a static record at any directory between the cwd and `$HOME` layers in with the nearest winning, and a `watch` subscribes to the same links the read walks.
- **A dotted `put` key created a namespace nothing could read.** `comb put my.some.value 5` did not address a node — it took the whole key as a namespace name, so the daemon stored an entry literally called `my.some.value`, and every `get` that went looking for it split the key on its first dot and asked for field `some.value` of namespace `my`, which did not exist. The data was in the cache, reachable by no query. The key is now split the same way `get` splits it, and the write lands at the node it names.
- **A bare-provider `comb get` dropped every cached field when the provider's virtual fields were all pure-env.** `comb get` used to decide a dotless query client-side by one question — does some virtual field of this provider reach into the cache? — and for a provider whose templates read only `env.*` the answer was "no", so adding a `note = "{{ env.FOO }}"` template to `git` reduced `comb get git` to `note=…`, silently losing every cached git field, against canon invariant 12 (a bare provider resolves to its whole subtree: cached fields plus virtual fields, virtual winning on a clash). A bare-provider query now always goes to the daemon, which returns the cached fields and the template tree together, and `libbeachcomber::resolve` renders the tree and deep-merges it over the fields; nothing client-side decides what a provider holds.
- **`comb get -f sh` did not shell-escape object values.** Canon invariant 8 says `text`/`sh` stringify a resolved value and `sh` shell-escapes it, but only the scalar path honoured the second half: a whole-provider or object-valued query rendered through one formatter shared by both formats, emitting `key=value` lines with raw values, so `env=it's a $HOME env` was word-split or expanded the moment `eval` touched it. `sh` object output now quotes each value with the same POSIX single-quote helper the scalar path uses. Keys stay as dotted names — no shell-variable rewrite — and `text` output is unchanged.
- **Every daemon-backed value under `comb get -f sh` came out unescaped.** The fix above reached only the client-side virtual-field paths. A key the daemon answers — every plain scalar, and a bare provider with no virtual fields behind it — short-circuits to `Client::get_formatted_with_flags`, which forwarded its `format` argument nowhere: `libbeachcomber::render::render_data` was a faithful port of the pre-Task-1.8 server-side renderer, which quoted neither format, and it discarded `format` outright. So `comb get git -f sh` emitted raw `key=value` lines and a value carrying a space, a single quote, a `$` or a newline was word-split, expanded, or executed the moment `eval "$(comb get -f sh …)"` touched it. `render_data` now takes the format and POSIX-single-quotes every value it renders under `sh` — the scalar, and each value of a flattened object — leaving keys bare; a miss still renders as nothing rather than `''`. `comb watch -f sh` renders through the same function and is escaped with it. The CLI's client-side object formatter now delegates to `render_data` as well, so one renderer and one quoting helper serve both paths and they cannot drift apart again. `text` and `json` output is byte-for-byte unchanged.
- **A whole-namespace virtual `comb get` printed a trailing newline where every other `text`/`sh` output is bare.** `comb get conda` ended in `\n` while `comb get hostname`, `comb get git.branch` and `comb get conda.env` did not. The contract, pinned by the CLI golden tests, is bare output so a value embeds in a prompt string verbatim; the client-side object path now renders through the same `render_data` call as the daemon-backed one with nothing appended. `comb status -f sh` also shares `libbeachcomber::render::shell_quote` now instead of carrying its own copy.
- **A refresh that arrived while the same source was already executing was dropped.** The scheduler recorded it as a pending rerun, but the rerun path was a stub that only cleared the in-flight marker, deferring the work to the next poll or demand. The execution task now loops: when a run finishes with a rerun pending it executes the source again — once; ten refreshes against one in-flight execution produce exactly two runs — keeping the key in flight across that decision so no concurrent duplicate can start, and honouring failure-backoff suppression before the rerun.
- **The watch self-test blocked an async worker for the length of a kernel watch registration.** `FsWatcher::new()` and `watch()` ran inline on whichever tokio worker the self-test task landed on; FSEvents registration takes ~1.2s on a loaded macOS host, so under a small runtime request handling stalled at startup. Registration now runs on the blocking pool, as `register_path_watch` already did, and the self-test adds no async latency.
- **`git` answered a non-repository directory with zeros instead of a miss.** `git diff --numstat` and `git status` both fail outside a work tree, and the parsers turned that failure into `(0, 0)` and an empty-but-present status — so `comb get git.lines_added` in a directory that is not a repository returned `0`, indistinguishable from a clean work tree with nothing staged. The `GitDiff`, `GitStatus` and `GitRefs` sources now probe for a work tree first and return no records at all when there is none, which is the miss the address deserves. The probe is a filesystem stat, so the non-repository case also stops spawning a subprocess that could only fail.
- **`comb get` and `comb eval` panicked (exit 101) on any non-UTF-8 environment value.** The CLI collected `std::env::vars()`, which panics on such a value; the environment is now read with `vars_os()`, each value converted lossily and an entry whose name is not UTF-8 skipped.
- **The Lua SDK's `resolve`/`eval` returned the JSON-null sentinel table (truthy) on a miss, not `nil`.** A miss is `nil` now, and so is an `eval` whose value is absent.
- **A `Poll` source registered a filesystem watch, and it matched every write under its root.** Canon `provider_source.md` invariant 4 says a `Poll` Source never registers a watch, but the scheduler registered one for every path-scoped source that went Active, building its pattern list from the strategy — empty for `Poll` — and an empty list matches every event under the watched root. So `git`'s `diff` source, which declares no patterns and polls every 30s, re-executed `git diff --numstat` on any write anywhere in the repository, as did its `lineage` source and any config-defined path-scoped `poll` source in the directory it was queried from. A `Poll` source now registers no watch; `Watch` and `WatchAndPoll` sources are unchanged, and a `Watch` source's absolute paths are watched as before. (How an empty pattern list on a `Watch` source is read changed afterwards; see Changed.)
- **A daemon start that config validation refused exited 0.** `comb daemon` logged `Config validation failed … Daemon refusing to start.`, bound nothing, and then exited with the same status as a clean stop, so a supervisor could not tell a refusal from a shutdown. It now exits 2, as a failed managed-defaults write already did. The signal is the daemon's own readiness channel — a daemon that never reported itself bound never served — so a socket that fails to bind is the same exit 2.
- **The Node subprocess tier parsed an envelope that no longer exists; both subprocess tiers now ask `comb get` for the value, its age and its staleness in one spawn, so they answer as the resolver does.** The Node SDK's `comb`-CLI fallback parsed `comb get -f json`'s stdout as the daemon's `{"ok","data","age_ms","stale"}` envelope — an output that no longer exists since `comb get` started resolving and printing the bare rendered value — so every `get` on that tier was broken: a scalar or string surfaced as a raw `TypeError` out of the envelope check, a miss threw `ServerError` instead of reading as `isMiss`, and an object holding an `ok` key was mistaken for the envelope. The Lua tier, and the Node tier's first repair, read the raw node out of `comb status -f json` rows instead, which reimplemented the daemon's resolution client-side and got it wrong at every edge: an ordinary `comb put myapp.x --global` then `get('myapp.x', cwd)` was a miss (no directory chain), a path equal to `$HOME` missed (the daemon keys it as the global entry), `wait` was dropped, a rejection on a warm key (`--force` on a static namespace) was swallowed, and on macOS a `--path /tmp` never matched the `/private/tmp` the daemon canonicalised it to. Both tiers now run one `comb get -f json <key> <p>:cache.<rest> [--path P | --global] [--force] [--wait]` — multi-key `-f json` prints a JSON array in key order with `null` in a missed key's slot — and read the three slots: exit 0 is a hit; exit 2 with the CLI's `Error querying <key>: no data (cache miss)` line for the key is a miss; exit 2 with any other `Error querying <key>: ` line is that refusal, in the daemon's words alone (the CLI's prefix stripped); exit 2 with a null value slot and no such line is the resolver's own error — a template that does not compile, a cycle, a failed `exec()`, which the CLI prints as `<key>: <msg>` — since a rendered value is never null (a missing ref renders `""`), so that slot is never a hit. A facet key (a colon in the provider segment) is asked for alone and answers with age 0 and not stale, as the daemon does over the wire. That makes the tier's `get` exactly the resolver's answer — chain layering, `$HOME`, `--force`/`--wait`, the daemon's refusals — with one documented divergence: `comb get` resolves, so a template-backed key returns its **rendered** value where the FFI tier returns the raw template half; a result from these tiers never carries `template`/`rest`, a template-only node is a hit holding the rendered value (age 0, not stale — its `:cache` slot is a leaf with age 0 and source `template`), and because the CLI renders with `exec()` on, the client's `exec` option has no effect on them — a caller that must not spawn processes from a template needs the FFI tier. Stated in both backend headers and both READMEs. Both tiers now have a live-daemon `get` suite; the Node one also isolates the `comb` children it spawns under the test daemon's `$HOME`, since a config-file `socket_path` beats `$BEACHCOMBER_SOCKET`.

## [0.9.1] - 2026-09-01

### Fixed

- **`validate_providers` rejected the documented legacy flat script-provider shape.** A provider declared with a bare top-level `command` (no `backend` key) legitimately carries `fields` and `invalidation` as provider-level sub-tables (`ScriptProviderConfig::{fields, invalidation}`) — config parsing itself accepts this shape — but validation walked those sub-tables as if they were per-source blocks and flagged both as unrecognized, so a daemon with such a provider refused to start. `validate_providers` now carries the same skip `parse_external_sources` already applied for the Phase 4 multi-source path, scoped to providers with no `backend` key so Phase 4 `backend = "…"` validation is unchanged.
- **Config self-watch restart validation required `config.toml` to exist**, even when a daemon's whole configuration lives in `conf.d/*.toml` drop-ins. A conf.d-only change was detected but validation read the (absent) main config file and always failed, so the daemon never restarted into the change without a workaround empty `config.toml`. A missing main config file is now treated as empty content, the same tolerance `Config::load()` already gives daemon startup.

## [0.9.0] - 2026-08-31

### Added

- **One expression syntax: `{{ }}` everywhere.** A value expression written as exactly one `{{ expr }}` tag keeps the expression's natural type; literal text or more than one tag makes it a string; a bare expression (no tags) is still accepted and equivalent to the single-tag form (`docs/canon/field_resolution.md` §"Value resolution", invariant 14).
- **`libbeachcomber::eval`** — the module that classifies a value expression's form, discovers what it references, and evaluates it: the evaluation API (`Form`, `classify`, `single_tag_expression`, `discover_refs`, `daemon_refs`, `fetch_daemon_data`, `evaluate`, `render_template` — the workspace's one template render) plus the low-level tag scanner (`Tag`, `TagKind`, `scan_tags`) it's built on.
- **`bc_eval` accepts templates and single tags with the same typing rule as the CLI** — and therefore every SDK's `eval` does too.
- **Cross-binding conformance: an `eval` op**, with nine fixtures under `tests/conformance/eval/` run by the Rust reference runner and the five SDK runners with an FFI transport (Python, Node, Go, Ruby, C; Lua under LuaJIT); the PUC Lua subprocess tier reports them as skipped, never passed.
  Two of the nine pin the typing rule past the bool case every binding gets right by accident: `single_tag_keeps_number` (`{{ 1 + 1 }}` is the number 2) and `single_tag_trailing_whitespace_keeps_type` (whitespace around a single tag is not literal text — invariant 14's scenario).
- **Path expressions accept `{{ }}` too.** A provider's `path = "…"` is classified by the same `libbeachcomber::eval` rules a value expression is, so `path = "{{ env.KUBECONFIG or '~/.kube/config' }}"` and the bare `path = "env.KUBECONFIG or '~/.kube/config'"` are one expression, and a template form (`path = "/srv/{{ env.SELECTOR }}"`) renders to its string. Canon `field_resolution.md` §"`env.*` namespace" already said `env.*` was available in path expressions as `{{ env.X }}`; only the bare form actually compiled, and the tagged one silently collapsed the provider to the global slot.
- **`comb init --write-config` writes virtual field expressions in the `{{ }}` form.**

### Changed

- **BREAKING (pre-1.0, CLI): `comb eval` on plain text with no tags is now an expression, not literal text** — a source with no `{{ }}` is two bare identifiers, and now exits 2 with a syntax error instead of printing itself back. Write `{{ }}` for literal text.
- **`comb eval`: a single-tag result that is an object prints as `comb get -f text` does** (sorted `key=value` lines), not minijinja's map debug format.
- **`comb eval`: a missing daemon ref at any depth** (`{{ p.f }}`, `{{ p.f.sub }}`) **renders empty at exit 0 instead of erroring**, and `| default(…)` now fires on a miss.
- **`comb eval` now follows virtual-field dependencies transitively.** With `x.a = {{ b.y or cache.c.z }}` and `b.y = {{ cache.d.w }}`, `comb eval '{{ x.a }}'` fetches `d.w` — 0.8.0 expanded only one level and rendered empty.
- **`-f fmt`, `watch -f fmt` and `status -f` render a null value as empty** where they used to print the literal word `none`; attribute access on a missing value renders empty instead of a template error; and `comb get -f fmt` / `comb watch -f fmt` errors now read `template compile error: …` / `template render error: …` (were `Template error: …`).
- **`comb eval`'s error messages are now correctly kinded**: a template syntax error now reads `template compile error: …` (was unconditionally `template render error: …`, even for a compile failure), and a virtual-field failure reads `p.f: …` (was `Error evaluating p.f: …`).
- **BREAKING (pre-1.0, ABI): `bc_resolve` reports `parse_error`** (was `server_error`) for a virtual field whose expression does not compile — a caller branching on `kind` for that failure must be updated; it now fetches plain `provider.field` refs (not just `cache.*`) and follows virtual fields transitively; and it aborts on a transport failure instead of silently evaluating against an empty map (a daemon miss or unknown provider still stays falsy).
- **`bc_eval`/`bc_resolve` fetch every daemon ref scoped to the supplied `cwd`** — path-scoped providers now resolve correctly, and a virtual field `put` globally (no path) still resolves, through the new daemon global-slot fallback.
- **A resolved minijinja map or sequence is now a JSON object/array**, not a debug-formatted string.
- **BREAKING (pre-1.0, `libbeachcomber` API): `discover_expression_refs` and `VirtualFields::evaluate_expression` are now crate-private** — use `eval::discover_refs` and `eval::evaluate`, which handle all three value-expression forms rather than only the bare one. `Ref` derives `Ord`, and every discovery path returns sorted output.
- **`comb watch` does not take the daemon's global-slot fallback that `get` gained** (below): its initial read and its subscription are keyed together, so a fallback read would emit the global value once and then never update. `get` and `watch` at the same path can therefore differ for a virtual provider `put` globally — `get` answers, `watch` stays silent. Queued in `docs/roadmap.md`, and canon `field_resolution.md` §"Path resolution" now states the carve-out.

### Fixed

- **`get` on a virtual (`put`-created) provider with a path now falls back to the global slot** when the requested slot holds nothing. On 0.8.0 the daemon read only the path-keyed slot for a virtual provider, so any caller that supplied a path or connection context — `comb get`, whose default is the CWD — could not see a pathless `put`, and the CLI masked it with a pathless retry. The daemon now falls back to the global slot, which is also what lets this release's cwd-scoped `bc_eval`/`bc_resolve` reach a global `put`.
- **A deeply nested virtual-field chain now errors instead of exhausting the stack.** Both recursions over the virtual-field graph — the daemon-ref closure and the evaluation itself — were cycle-guarded but not depth-guarded, and a cycle guard only stops a *repeat*: a chain of ~2000 distinct fields, each referencing the next, recursed once per link. Through the C ABI that was a SIGSEGV in the host process (an `overrides_json` is caller-supplied, so any SDK user could trigger it), not an error anything could catch. Nesting deeper than 128 is now `virtual field nesting too deep (limit 128)`.
- **Virtual-field errors now name the field** (`p.f: …`), including in `comb get`. On 0.8.0 a bad expression in a config virtual field surfaced as a bare `expression compile error: …` with nothing pointing at which field to fix.
- **`scripts/conformance-all.sh` builds the Node SDK's `dist/` up front**, and its summary now names every runner that failed, could not run, or skipped fixtures — two distinct defects on 0.8.0. First, attribution: the exit code was already correct when a runner failed or could not run, but the summary named no runner, so a failure couldn't be pinned on a specific one — the Node runner's immediate exit on a clean checkout (`dist/` isn't checked in) scrolled past between other runners' output, invisible as a runner that never ran at all. Second, a runner that only *skipped* fixtures (e.g. Lua's subprocess tier skipping `resolve`/`eval`) exited 0 and still printed a green `conformance-all: all SDK runners passed`.
- **`scripts/conformance-all.sh` now checks that every runner accounts for every fixture.** Its pass-count regex also captured a *denominator* for the Node and Go runners (`Results: 28/43 passed` read as 28 → 43), and nothing checked that a runner's pass + fail + skip added up to the number of fixtures on disk — so a runner that returns early from a fixture without counting it (the C runner's bail-out paths, Ruby's `return unless status_ok`) or enumerates none at all and exits 0 on the empty set (Python) read as green. Both are fixed: the summary parse is per-runner, and a runner whose counts do not add up is named and fails the gate.
- **`cache.P` / `cache.P.F` ref binding order was hash-order dependent** — where a whole-object ref and a same-provider field ref disagreed about a key, which one won could vary run to run. The whole object now always wins, deterministically.

## [0.8.0] - 2026-08-23

The client-unification cycle: the shared Rust client core is exposed as a C ABI,
all six SDKs are rebuilt as thin bindings over it, and the singleton hardening
work (orphan reaping, poll-guaranteed self-supervision, watch and reaper
self-tests) ships alongside.

### Added

- **`libbeachcomber` C ABI (`libbeachcomber.{so,dylib}`).** The shared Rust client (protocol, JSON mapping, client-side field resolution) is now exposed as a C-ABI cdylib built by the new `libbeachcomber-ffi` crate and shipped beside `comb` in every release artifact (tarball, deb, rpm, Homebrew), with a cbindgen-generated `beachcomber.h` kept fresh by a CI check. 22 `bc_*` entry points cover lifecycle, all ops, client-side resolution (`bc_resolve`/`bc_eval` with caller-supplied cwd/env), sessions (busy-guarded), and watch (cancellable, five machine-readable outcomes). Every call returns a JSON envelope; panics are caught at the boundary.
- **All six SDKs are now bindings over the shared library.** Python (`ctypes`), Ruby (`fiddle`), Go (`purego`, vendored), Lua (LuaJIT `ffi`; PUC Lua via a declared subprocess tier), Node (`koffi` optional peer dependency with a subprocess tier), and C (collapsed onto the generated header). Bindings discover the library via `$BEACHCOMBER_LIB` → `../lib` beside the resolved `comb` → the platform linker path, check all symbols at load, expose the daemon's error `kind` machine-readably, and report their transport where more than one exists. The SDKs gain client-side resolution for the first time.
- **Version-skew detection.** The shared client compares its build identity against the daemon's on first connection per client/session; a mismatch is surfaced to callers and named (both versions) in subsequent errors, without failing ops.
- **Cross-binding conformance: resolution + typed-mapping fixture groups.** The fixture format gains a `resolve` op with `virtual`/`env`/`cwd` inputs, plus mapping fixtures pinning the ambiguous JSON conversions (64-bit ints, whole-number floats, null, empty-vs-absent, depth boundary, embedded NUL). All six SDK conformance runners now run in CI against a built `comb`, enforce every documented expectation kind, fail loudly on unknown ones, and skip-not-pass what they don't implement. `scripts/conformance-all.sh` runs the whole gate locally.
- **Restart on config change.** The daemon's self-supervision extends to its configuration: the resolved `config.toml` and any `conf.d/*.toml` drop-ins are watched (fs-event fast path, mtime-poll backstop), and a change restarts the daemon gracefully — parse-gated, so an edit that doesn't parse is logged and ignored, never restarted into. There is no in-place reload; restart is the application mechanism.
- **Config composition via `conf.d/`.** Any `*.toml` in `<config-dir>/conf.d/` is deep-merged onto `config.toml` in lexical filename order (tables merge per key; scalars and arrays are last-wins), before typed parsing, so a drop-in can override a single provider key without clobbering the block. A broken drop-in is warned and skipped at startup; the restart gate requires the whole composed set to parse.
- **`comb status`: POLL column, TTL total budget, `~` paths, and a `--help` legend.** A new POLL column (before TTL) shows seconds to the next poll — or the retry countdown while a source is failing; the TTL cell adds a humanized total time-to-eviction alongside `P×K`; failing rows render `⚠ #N`; `$HOME`-prefixed paths compact to `~` in the human preset (machine formats keep real paths); and `comb status --help` documents every column and glyph. Backed by an additive `next_poll_in_secs` status-row field.
- **Orphan reaping.** The canonical daemon (bound socket equals its own env-free resolution) reaps orphaned `comb daemon` processes at startup and hourly: uid-owned daemons reparented to PID 1, on sockets nothing resolves, carrying neither `--exit-with-parent` nor the new `--no-reap` flag, and older than 60s. Live test daemons, attended foreground runs, and flagged supervised daemons are exempt. Closes the leak class where daemons on session-scoped or deleted-worktree sockets accumulated for weeks (`docs/canon/singleton.md` §"Orphan reaping").
- **`comb daemon --no-reap`** — marks a deliberate, supervised, non-canonical daemon exempt from reaping.
- **Poll-guaranteed self-supervision.** The daemon's binary self-watch gains a 5s mtime poll alongside the fs-event watch. An fs-event stream can be created without error and then deliver nothing (sandboxed CI hosts, a degraded `fseventsd`); with an event-only watch such daemons outlived every rebuild indefinitely. The poll bounds staleness at one interval regardless of backend health.
- **Watch self-test.** At startup the daemon probes whether kernel fs events actually deliver (2s timeout, concurrent with the scheduler loop — no startup latency). If not, provider file-watching falls back to a polling backend (1s scan), and the degradation is surfaced via `comb check daemon` (WARN verdict), `comb status` (stderr warning), and a new `watch_backend` field in the daemon introspect payload.
- **Reaper visibility self-test.** The canonical daemon probes whether its process enumeration plausibly spans the system (PID 1 present in the raw listing) at reaper arming and on every sweep. A confined view (e.g. a daemon auto-spawned from a sandboxed client shell inherits the sandbox's process-visibility limits) is surfaced via `comb check daemon` (WARN verdict), `comb status` (stderr warning), and a new `reaper` object in the daemon introspect payload (`armed`, `visibility`, `sweeps`, `reaped`, `kill_denied`); sweeps continue reaping whatever is visible. Reap kills denied by the OS (EPERM) are counted and surfaced the same way (`docs/canon/singleton.md` §"Reaper visibility self-test", invariant 13).
- **Per-sweep reap summary log.** Every reap sweep logs a debug-level summary — rows enumerated, candidates, exemption tallies by rule, reaped pids, denied/failed kills — so a sweep that found nothing eligible is distinguishable from one that could not see anything.

### Fixed

- **`refresh`/`put_null`/`set_context` swallowed daemon rejections** in the CLI client path, returning success on `ok:false`.
- **Conformance runners for Ruby, Node, Lua, and C could not run at all** (wrong daemon subcommand, ESM/CommonJS mismatch, `/tmp` chmod EPERM against the singleton lock, socket-file readiness probe); the C runner also read fixtures from the wrong checkout in git worktrees and truncated its own test payloads (whole-number floats, embedded NULs). The Go and C runners treated `age_ms=0` as absent.
- **The Lua SDK misclassified empty JSON objects as arrays** after decode.
- **Failed-bind daemon lingered alive and ignored SIGTERM.** A daemon whose socket bind failed (e.g. path over the 104-byte `SUN_LEN` limit) logged the error but then blocked forever awaiting a scheduler that was never told to shut down, with no remaining observer for the signal handler's cancel token — only SIGKILL removed it. The server-error path now shuts the scheduler down and the process exits. `ensure_daemon` and `libbeachcomber` auto-start additionally reject over-long socket paths up front with the real cause instead of forking a doomed daemon and reporting a spawn timeout.
- **Reap fratricide under `$BEACHCOMBER_SOCKET`.** The reaper role is now decided against the env-free resolution (config override → `/tmp/beachcomber-<uid>/sock`), ignoring `$BEACHCOMBER_SOCKET`. Previously a daemon auto-spawned under the env override resolved *itself* as canonical — as did the default-path daemon — and each classified the other as an unflagged orphan: mutual reaping on alternating sweeps. Auto-spawn (`ensure_daemon` in the CLI, `auto_start` in `libbeachcomber`) now also appends `--no-reap` when the spawn path was resolved from `$BEACHCOMBER_SOCKET`, so deliberate override daemons are spared without user action (`docs/canon/singleton.md` §"Who reaps", invariants 10/11). Corollary: an environment where every client uses an override socket runs no reaper.
- **Reaped orphans left corpse socket files.** After a reaped orphan's confirmed death its socket and sibling pid files (`pid`, `daemon.pid`) are now removed. A corpse socket re-latched old existence-probing clients (`libbeachcomber` ≤0.1.1) into respawning a daemon on the dead path — the mechanism that kept one orphan path continuously resurrected for four months. Cleanup probes first and never unlinks a socket that is serving again (`docs/canon/singleton.md` §"Corpse cleanup", invariant 14). Sweep summaries and the `SweepReport` gain a `corpses_unlinked` count.
- **Sandbox-blind orphan reaping (macOS).** The reaper's pid list now comes from `sysctl KERN_PROC_ALL` instead of libproc's `proc_listallpids`, which seatbelt sandbox profiles silently filter to the session's own processes (observed: 51 of 737 pids). A canonical daemon that happened to be respawned from a sandboxed client shell could never see — and therefore never reaped — orphan daemons from other sessions; the 2026-07-16 investigation found one such orphan surviving 19 hours across ~19 sweeps with clean logs.
- **Orphan reaping was blind on Linux.** The `/proc` stat parse read the state field as the ppid, so every row failed to parse and the uid-owned process listing was always empty — the reaper enumerated nothing, and both `boundaries_proc_table` smoke tests failed on Linux CI. The parse now indexes the correct field.
- **The published Lua rock could not load its own submodules.** The rockspec installed modules under a `libbeachcomber.*` namespace while the code requires `beachcomber.*`; the module keys now match the code (the LuaRocks package name is unchanged). The 0.7.0 rock has the same defect.
- **Watch registration stalled the scheduler for seconds.** Kernel FSEvents registration (1–3s per call under load) ran inline on the scheduler task, once per source even for a shared path — a whole-provider get could block every pending response for ~6s. Registration is now deduplicated per path and runs off the scheduler task.
- **`comb get <virtual>.<field>` missed put-created entries and failed silently.** The CLI defaulted the request path to the process CWD, so global virtual entries missed while the raw socket answered; misses from that ambient default now retry pathlessly, and every error path writes its cause to stderr instead of a bare exit 2.
- **The Lua SDK dropped a JSON `null` nested in an object.** Decode now produces an exported `beachcomber.null` sentinel at any depth (encode emits `null` for it); the wire's miss encoding still reads as a miss. The conformance fixture pinning this is now required to pass.
- **The Go and Ruby SDKs never autostarted the daemon.** Go hardcoded `autostart: false` with no override; Ruby defaulted it off. Both now defer to the shared library's default (on), with explicit opt-out; autostart applies only to the auto-discovered socket path, never an explicit per-client one.

### Changed

- **BREAKING (wire): the server-rendered `text`/`sh` sub-protocol is removed.** `get` and `watch` no longer accept a `format` field; the daemon always answers NDJSON, and text/sh rendering happens client-side. The old sub-protocol could not represent values beginning `error:` (indistinguishable from failures) or containing blank lines (frame desync). A stale client sending `format` gets a normal JSON response. `comb get`/`comb watch -f text|sh` are unchanged for users — rendering moved, output didn't.
- **The hand-written C SDK protocol implementation is deleted** (`beachcomber.c`, `json.c`) — the C SDK is now the generated ABI header plus build glue.
- **`beachcomber-client/` is renamed `libbeachcomber/`**, matching its package name.
- **BREAKING: `$XDG_RUNTIME_DIR` no longer participates in socket path resolution.** Canonical resolution is now config override → `$BEACHCOMBER_SOCKET` → `/tmp/beachcomber-<uid>/sock`, in the daemon and all clients (CLI, `libbeachcomber`, and the C/Go/Lua/Node/Python/Ruby SDKs). Session-scoped environments (sandboxes, containers, per-session `XDG_RUNTIME_DIR` shims) previously resolved distinct socket paths and auto-spawned one daemon per session; singleton enforcement is per-socket-path, so the default must be a stable per-user path (see `docs/canon/singleton.md`). Environments that want a different placement (e.g. `/run/user/<uid>` on systemd) set `$BEACHCOMBER_SOCKET` or the config override. **Migration:** a daemon running on an old XDG-derived socket is unreachable by upgraded clients; the first client invocation spawns a daemon at the stable path, and the old daemon exits on binary replacement (self-supervision) or can be killed manually.

### Known gaps

- The Lua SDK cannot represent a JSON `null` nested inside an object (Lua `nil` semantics); tracked in the roadmap with a fix shape, reported as a named known-defect skip by its conformance runner.
- Node without `koffi` and PUC Lua run a reduced subprocess tier (documented per binding; `transport()` reports which tier is active).

## [0.7.0] - 2026-06-23

The post-0.6.1 cycle: an **env-cascade** overhaul plus a broad provider-correctness
sweep. Each environment-aware provider is split into a daemon-side **data provider**
(pure on-disk/state enumeration, no environment reads) and a client-side **consumer
namespace** (virtual fields + path/value expressions that fold in the *querying
shell's* environment) — fixing the long-standing "frozen daemon environment" class
of bugs where the daemon reported its own launch-time env instead of the caller's.
Many changes are breaking; pre-1.0, they ship under a minor bump.

### Added

#### Field resolution model + `cache.*` namespace (env cascade)

- **New canon doc `docs/canon/field_resolution.md`.** Defines the client-side field-resolution model: field-type taxonomy (`native` / `external` / `literal` / `virtual` / `env`), the `cache.*` namespace, path expressions, and value expressions. This is now the authoritative spec for how consumers address and resolve provider fields.
- **`cache.*` value-expression model.** Expressions reference raw cached values as `cache.<provider>.<field>` (the stored value, bypassing any field expression) vs bare `<provider>.<field>` (the resolved field, with expression applied). A cached field's default expression is the identity; no rename is needed when a virtual field overrides a same-named cached value.
- **Path expressions.** A provider's cache-key path is computed client-side by an expression over `cwd` and `env.*` (`[providers.<name>] path = "<expr>"`). Empty/falsy ⇒ global slot. Built-in defaults compiled into the CLI; user config overrides per provider.

#### Data providers and consumer namespaces

- **`aws` → `aws_profiles` data provider.** The `aws` daemon provider is now named `aws_profiles`. It returns one field per profile (each an `Object{region}`) parsed from `~/.aws/config`. The `aws` consumer namespace is now composed of **virtual fields** that index the data provider by the active profile selector: `aws.region = env.AWS_REGION or env.AWS_DEFAULT_REGION or cache.aws_profiles[env.AWS_PROFILE or env.AWS_VAULT or env.AWS_DEFAULT_PROFILE or "default"].region`. `comb get aws` returns computed fields; `comb get aws_profiles` returns the raw profile enumeration.
- **`gcloud` → `gcloud_configs` data provider.** The `gcloud` daemon provider is now named `gcloud_configs`. It returns one field per gcloud configuration (each an `Object{project, account}`) plus an `active_config` field, parsed from `~/.config/gcloud/`. The `gcloud` consumer namespace is virtual fields indexing the data provider by active config. `comb get gcloud` returns computed fields; `comb get gcloud_configs` returns the raw config enumeration.

#### Env-selected file providers (Tier B)

- **`kubecontext` is now PathScoped.** The provider reads the kubeconfig file named by the path expression `env.KUBECONFIG or '~/.kube/config'`. A `:`-joined list is merged (later file wins). The daemon watches each resolved file via `Source::watched_files`; the daemon never reads `$KUBECONFIG` itself — the CLI resolves it to a path and sends that as the cache coordinate.
- **New `talos` provider.** Same shape as `kubecontext`: reads the Talos config file named by `env.TALOSCONFIG or '~/.talos/config'` as a PathScoped source. Fields: `context` (string), `endpoints` (array), `nodes` (array). Watches the resolved file via `Source::watched_files`.
- **`Source::watched_files`.** New trait method (default: empty) returning the explicit file paths this source needs to watch, given the resolved path. Used by Tier B env-selected-file providers to register per-file watches without relying on pattern-based watch registration.

#### CLI

- **Client-side `env.*` and virtual-field evaluation.** `comb get` / `comb eval` resolve `env.*` references and virtual expressions in the client; a query that references only `env.*` skips the daemon round-trip entirely. Includes a typed evaluator with undeclared-variable discovery and a `basename` filter on the shared minijinja environment.
- **`comb init --write-config`** materialises the built-in virtual-field defaults into `config.toml` (idempotent; safe to re-run).

#### Daemon

- **`--exit-with-parent`** flag: the daemon self-exits when the process that spawned it dies (e.g. an integration that owns the daemon's lifetime).

### Changed (breaking, pre-1.0)

- **BREAKING (pre-1.0):** `aws` daemon provider renamed to `aws_profiles`. `aws.config_region` field removed. `comb get aws_profiles` returns the raw profile dump; `comb get aws` evaluates the consumer virtual namespace. Scripts querying `aws.config_region` must be updated.
- **BREAKING (pre-1.0):** `gcloud` daemon provider renamed to `gcloud_configs`. `gcloud.config_project` field removed. `comb get gcloud_configs` returns the raw config dump; `comb get gcloud` evaluates the consumer virtual namespace. Scripts querying `gcloud.config_project` must be updated.
- **BREAKING (pre-1.0):** `terraform.path_workspace` renamed back to `terraform.workspace`. The P1 rename was forced by a virtual-field self-reference cycle; the `cache.*` model eliminates the cycle, so the field returns to its natural name.
- **BREAKING (pre-1.0):** `python.version` renamed to `python.venv_version`; new `python.local_venv_name` field added. The daemon no longer reads `$VIRTUAL_ENV`. Scripts querying `python.version` must update.
- **BREAKING (pre-1.0): daemon providers no longer read environment variables.** Under the env-cascade model the daemon enumerates on-disk state only; per-shell environment is applied client-side. Removed daemon env reads: `aws` (`$AWS_PROFILE`/`$AWS_REGION`/…), `gcloud` (`$CLOUDSDK_ACTIVE_CONFIG_NAME`), `terraform` (`$TF_WORKSPACE`), `python` (`$VIRTUAL_ENV`). The user-facing `aws.region`, `gcloud.project`, and `terraform.workspace` values are now computed client-side from `env.*` plus the cached data provider, so they finally track the querying shell rather than the daemon's launch environment.
- **BREAKING (pre-1.0): `conda` and `op` are now client-side virtual fields, not daemon providers.** Both were structurally env-frozen as daemon providers (they read the daemon's process environment, which never reflects the querying shell). They are reborn as virtual fields evaluated in the client: `conda.env` resolves `$CONDA_DEFAULT_ENV`, and `op.signed_in` reflects whether `$OP_SERVICE_ACCOUNT_TOKEN` is set — so both finally track the querying shell. The daemon no longer runs the conda/op providers (no `op whoami` subprocess); `op`'s previous `account` field and live-session validity check are gone.

### Fixed

- **git is now correct in worktrees and submodules.** A shared `resolve_git_dir` follows `.git`-as-a-file (`gitdir:` pointers), so `git.state` (rebase/merge/cherry-pick progress) and `git.stash` reflect reality in linked worktrees and submodules instead of always reporting "clean"/0. The git executor no longer inherits `$GIT_DIR` / `$GIT_COMMON_DIR` / `$GIT_WORK_TREE`. Refs moved to a read-always mechanism with a split `GitHead` source.
- **gcloud read a path that doesn't exist.** It read `~/.config/gcloud/properties` (absent on a standard install) and returned empty for essentially everyone; it now follows the `active_config` two-level indirection to the real `configurations/config_<name>/properties`.
- **kubecontext merges a multi-file `$KUBECONFIG`.** A `:`-joined list is merged (later file wins) instead of reading only the first path, and context-name matching is anchored (no more `prod` matching `prod-east`).
- **`user.name` is thread-safe.** Replaced `getpwuid` with `getpwuid_r`, removing undefined behaviour under `spawn_blocking`.
- **direnv reads the allow database directly** instead of shelling out to `direnv status`, so `direnv allow` from any shell is reflected.
- **sudo** omits the `active` field when the (root-only) timestamp file is unreadable, instead of silently reporting `false`.
- **asdf** falls back to the global `~/.tool-versions` and emits a flat field schema consistent with the other providers.
- **network:** removed the hardcoded `en0` interface assumption, added an IPv6 field, and now detects Tailscale (`tailscale0`) as a VPN.
- **A wedged daemon no longer blackholes the socket.** On startup, when another daemon holds the lock with the same build, the new process now probes the canonical socket before exiting: it exits silently only if that daemon is actually serving. A same-build owner that acquired the lock but never bound the socket (or whose socket was deleted) is superseded after a short grace, so a healthy daemon rebinds instead of clients hitting a permanently dead socket. Startup orphan-reaping (which could kill peer daemons on other socket paths) was removed in favour of this targeted probe.

- **`cargo xtask set-version X.Y.Z`** rewrites all 14 version touchpoints (both Cargo manifests, both lockfiles, the 5 SDK manifests, 3 AUR PKGBUILDs, the nix flake, the `release.yml` rockspec reference, the 8 README download URLs, and the Lua rockspec including its versioned filename) in one command, with count-guarded digit-boundary replacement that aborts on any drift.

- Env-cascade (env-selected file resolution, Tier B providers) adds **no** wire-protocol change. The existing `path` field on the `Get` request carries the client-resolved file path as the cache coordinate. See `docs/protocol-spec.md`.

## [0.6.1] - 2026-05-29

### Fixed

- **Socket-path resolution now agrees across the daemon, CLI, and every client.** All client SDKs (Rust, Go, Python, Ruby, Node, Lua, C) resolve the daemon socket as `$BEACHCOMBER_SOCKET` → `$XDG_RUNTIME_DIR/beachcomber/sock` → `/tmp/beachcomber-<uid>/sock`, mirroring the daemon's bind path (minus the daemon-only config-file step). Previously the clients ignored `BEACHCOMBER_SOCKET` and consulted `$TMPDIR` (a per-session `/var/folders/...` path on macOS), so on macOS with `XDG_RUNTIME_DIR` unset a client could look in `$TMPDIR` while the daemon bound `/tmp/beachcomber-<uid>/sock` — and they would fail to find each other. There is no longer an existence probe on the `XDG_RUNTIME_DIR` step: clients resolve to the single path the daemon binds and rely on connect-retry; non-standard layouts use `BEACHCOMBER_SOCKET`.
- Node SDK published type artifact (`dist/types.d.ts`) regenerated so the `IntrospectSubject` union reflects the `backoff` → `lifecycle` rename from 0.6.0. The npm publish step rebuilds `dist/` from `src/` via `prepublishOnly`, so the compiled artifact can no longer drift from source.

A large release. The daemon's internal model was rebuilt around a
Provider→Source→Field architecture, the wire protocol and CLI were overhauled,
and typed client SDKs reached parity across all six languages. Many changes are
breaking; pre-1.0, these ship under a minor bump.

### Added

#### Provider / Source / Field architecture

- **Provider→Source→Field model.** A `Provider` is now a namespace declaring 1+ `Source` objects; each `Source` has its own `InvalidationStrategy`, `KeepAlive`, `FailbackConfig`, `SourceScope`, and field set.
- Lifecycle keying moved from `(provider, path)` to `(provider, path, source)` — each source instance has an independent Active/Decay/Evicted lifecycle.
- Cache entries at `(provider, path)` hold per-source sub-entries; field ownership is disjoint across sources, so flatten reads are unambiguous.
- **Per-source eviction:** an evicting source removes only its own contribution; the `(provider, path)` entry is dropped only when its last source evicts.
- `InvalidationStrategy::Watch` gains `abs_paths` for absolute-path filesystem watches; global sources can watch `$XDG_CONFIG_HOME` and other absolute roots directly. `expand_abs_path()` expands `~`, `$HOME`, and the XDG vars in `Source::metadata()`.
- Pure-watch global sources (`Watch + Global + KeepAlive::Never`) execute once on first demand, re-execute only on fs events, and never decay.
- `ProviderRegistry` builds a `field → source` reverse map at registration; `comb get git.branch` routes to the owning `git.refs` source without a linear scan.

#### Source-aware query planning

- New `src/query.rs` request planner (`QueryPlan` / `SourceDemand`); `get` and `watch` build one plan so they share identical key semantics.
- A field query warms **only its owning source** — `comb get git.branch` no longer warms sibling `git` sources (`diff`, `status`). Whole-provider queries still warm all applicable sources.
- New addressing forms `provider.source` and `provider.source.field` accepted by `get`, `refresh`, and `watch`; `watch` now resolves source-qualified keys identically to `get`.

#### Protocol, clients, and SDKs

- `Request::Introspect` wire op with subjects `daemon`, `providers`, `config`, `cache`, `lifecycle`, `watches`, `timers`, `demand`, `procs`. `comb check` rewired onto it (top-level aggregation; each subject a subcommand).
- Typed client surface across `beachcomber-client` and all six SDKs (Python, Go, Node, Ruby, C, Lua): `status()` returns typed cache rows directly; `RowKind` discriminator and `FailureSnapshot` exposed on `CacheRow`.
- Provider conformance harness wired into the test suite; protocol spec / hello version negotiation documented.
- **Client connect retry** in the CLI and all six SDKs + `beachcomber-client`: transient `ECONNREFUSED`/`ENOENT` retried 3× with exponential backoff (250ms / 500ms / 1s), covering the daemon-restart window.

#### Daemon lifecycle

- **Singleton enforcement** via an exclusive `flock` on a PID file: a same-version second daemon exits; a different-version one takes over the old (SIGTERM → SIGKILL).
- **Automatic restart on binary change** (the daemon fs-watches its own executable) and **orphan reaping** of stale `comb daemon` processes sharing its binary path.
- `comb --version` reports `BEACHCOMBER_VERSION`, including git sha for dev/dirty builds.
- `BEACHCOMBER_SOCKET` env var overrides the socket path.

#### CLI: get / put / status

- `comb get` variadic keys, `--force` (immediate recompute) and `--wait` (block for a fresh value); `comb put --null` clears a virtual entry.
- `comb status` tabular output (one row per warm entry) with a `TTL`/lifecycle column (`★`/`3`–`0` countdown, poll interval, keep-alive, fsevents-reinstate), a failure `⚠` indicator, and flags `--filter`, `--sort` (incl. `lifecycle`), `--no-trunc`, `--max-width` (int or `auto`), `--color` (`auto`/`always`/`never`), `--ascii`, and `-f/--format` presets (`human`/`tsv`/`json`/`csv`/`table`/`sh`).
- minijinja templating in `comb eval` and the `.f` format suffix (filters: `truncate`, `default`, `upper`, `lower`, `length`); script provider `output = "text"`.

### Changed

- **BREAKING (pre-1.0):** daemon socket path no longer depends on `$TMPDIR` — resolution is config override → `$XDG_RUNTIME_DIR/beachcomber/sock` → `/tmp/beachcomber-<uid>/sock`. On macOS all shells now share one daemon.
- **BREAKING (pre-1.0):** `introspect` subject `backoff` → `lifecycle`, with state values `Active` / `Decay1`–`Decay4` replacing `Grace` / `SlowPoll` / `Frozen` / `Evict`; all SDK constants renamed (no legacy alias).
- **BREAKING (pre-1.0, all SDKs):** `status_rows()` removed; `status()` returns typed rows. The C SDK `comb_status_rows` is redesigned to heap-allocating (pair with `comb_free_cache_rows()`); `comb_cache_row_t` fields are now owned `char*`.
- **BREAKING (pre-1.0):** `comb status` defaults to the `human` preset regardless of TTY (use `-f tsv` / `-f json` in scripts); `--no-color` removed in favour of `--color=never|auto|always`.
- `comb status` default sort is `(provider, path, field)`; `--max-width` default raised 40 → 120; TSV/CSV gain one column per `CacheRow` field.
- Provider scope declared per field via `FieldSchema::scope`; `Provider::execute` returns `Vec<(Option<String>, ProviderResult)>` (wire protocol unchanged).

### Fixed

- Cache decay works end-to-end (Active → Decay1–4 → Evicted with exponential backoff); previously the decay stages were unreachable and entries never evicted.
- Global providers no longer create ghost cache entries when queried with an explicit path; `mise.global` is no longer duplicated per project directory.
- Library (FFI) provider dispatch is now strict UTF-8 (was silently lossy).
- **Lua SDK:** `Client:get_with_flags` returns `nil, error` on server-side failures, matching `Client:get`.
- `:age` metadata suffix returns a JSON number, not a string. Watcher registrations are GC'd on cache eviction and on a periodic tick.

### Removed

- **BREAKING (pre-1.0):** wire ops `poke` → `refresh`, `store` → `put`; `Request::List` removed; `status` reshaped to a cache-row array (old health fields via `introspect daemon`).
- **BREAKING (pre-1.0):** CLI `comb refresh`/`r`, `comb fetch`/`f`, `comb list`/`l` removed; single-brace `{field}` template syntax removed (use `{{ field }}`).
- **BREAKING (pre-1.0):** `InvalidationStrategy::Once`, `Watch::fallback_poll_secs`, and `Poll::floor_secs` removed; TOML moved to per-source `[providers.<name>.<source>]` blocks with `poll_*` / `fsevent_*` / `failback_*` prefixes (old flat source-knob keys are rejected with a clear error).
- `[lifecycle] cache_lifespan` (now derived as `poll_interval × poll_live_count`), `poll_idle_interval`, `poll_live_interval` (→ `poll_interval`), and `eviction_timeout_secs` config keys removed.

### Internal

- Test-suite-health initiative: dependency-injection seams for process / git / HTTP / library boundaries, golden CLI tests, mock-clock TTL tests, a shared git fixture, the provider conformance harness, and a coverage gate raised to 70%.

## [0.5.0] - 2026-04-14

### Added
- Git provider: `commit_summary` field — first line of HEAD commit message, extracted from the existing `git log` call (no additional subprocess)
- Git provider: `push_ahead` and `push_behind` fields — commits ahead/behind the push remote (distinct from tracking remote `ahead`/`behind`)
- Synchronous cache miss — `comb get` on a cold cache executes the provider inline via `spawn_blocking` and returns data immediately instead of returning empty
- Single-letter command aliases: `d`aemon, `g`et, `p`ut, `r`efresh, `w`atch, `s`tatus, `l`ist, `k`ill
- Format suffix syntax — append `.p` (plain text), `.j` (json), `.s` (sh), `.c`/`.C` (csv), `.t`/`.T` (tsv), `.f` (template) to a command for quick output format selection without `-f` flag
- New output format: `sh` — `key=value` pairs, sourceable in shell scripts (replaces old `text` behavior for objects)
- New output formats: `csv`/`tsv` (values only), `CSV`/`TSV` (with header row) for structured data export
- New output format: `fmt` — `{field_name}` template interpolation per field, e.g. `comb g.f '{branch} ({dirty})' git .`
- `comb kill` (alias `k`) — stop the running daemon via SIGTERM; socket-activates fresh on the next query. Queries the daemon's pid via the status socket so it works even when the pid file is stale
- `status` response now includes `pid` and `version` fields
- `comb eval` (alias `e`) — template interpolation across providers: `comb eval "branch: {git.branch} load: {load.one}" .`
- `comb fetch` (alias `f`) — batch get, query multiple keys in a single connection with format-aware output
- Field metadata access — colon delimiter on key (`git.branch:age`, `git.branch:stale`, `git.branch:source`) returns cache metadata instead of data
- `sudo` provider — detect active sudo timestamp. Global, poll 30s. Fields: `active` (bool)
- `op` provider — detect active 1Password CLI session. Global, poll 60s. Fields: `signed_in` (bool), `account` (string)
- `comb init` (alias `i`) — auto-detect installed tools (p10k, starship, tmux, neovim, polybar, waybar, sketchybar, oh-my-zsh) and print integration snippets
- `comb check` (alias `c`) — health check with subcommands: `all`, `daemon`, `config`, `providers`, `cache`, `procs`
- `comb check procs` — process exec tracing via eslogger (macOS) or /proc scanning (Linux) to measure beachcomber's potential impact
- Shell integration scripts: `scripts/chpwd.sh` (directory change hook for zsh/bash/fish), `scripts/polyfill.sh` (POSIX fallback function)
- Help screen branding with NavistAu authorship, beachcomber.sh URL, MIT license, format suffix usage hint

### Changed
- CLI: `comb poke` renamed to `comb refresh`
- CLI: `comb store` renamed to `comb put`
- **Breaking:** `text` output format for objects now returns raw values only (no key= prefix). Use `sh` format for the old `key=value` behavior
- **Breaking:** Default output format is now `text` (was `json`). `comb g git.branch .` prints just the branch name. Pass `-f json` or use the `.j` suffix for the old JSON envelope
- **Breaking:** Format suffixes remapped for better ergonomics: `.t` → `.p` (plain text, now the default — `.p` is rarely needed), `.sh` → `.s` (shell), `.s` → `.t` (tsv), `.S` → `.T` (tsv+header), `.fmt` → `.f` (template). `.j`, `.c`, and `.C` are unchanged
- The daemon now exits cleanly on SIGTERM as well as SIGINT (SIGTERM is what `comb kill` sends)

# powerlevel10k Integration

## Introduction

powerlevel10k (p10k) is one of the fastest zsh themes. It already uses gitstatus — a purpose-built C++ daemon — for git information, and integrates it tightly into its rendering pipeline. There is no benefit to routing git data through beachcomber when p10k's built-in git segments are faster and more feature-complete for that use case.

beachcomber complements p10k by providing cached data for everything p10k does not cover natively: Kubernetes context, battery, network, cloud contexts (gcloud, AWS), conda environments, and Terraform workspaces. These are the areas where beachcomber adds real value.

## Prerequisites

- beachcomber installed and the daemon running (`comb status` should succeed)
- powerlevel10k installed and configured (`p10k configure` has been run at least once)
- `~/.p10k.zsh` exists (generated by the configuration wizard)

## Adding custom segments

p10k supports custom prompt segments via shell functions named `prompt_<segment_name>`. Any function following that naming convention can be referenced in the `POWERLEVEL9K_LEFT_PROMPT_ELEMENTS` or `POWERLEVEL9K_RIGHT_PROMPT_ELEMENTS` arrays.

### Step 1: Define segment functions

Add the following to `~/.p10k.zsh`, after the `typeset -g` declarations near the top of the file.

```zsh
# Kubernetes context from beachcomber
function prompt_bc_kube() {
    local ctx=$(comb get kubecontext.context -f text 2>/dev/null)
    [[ -n "$ctx" ]] || return
    p10k segment -f cyan -i '☸' -t "$ctx"
}

# AWS profile from beachcomber
function prompt_bc_aws() {
    local profile=$(comb get aws.profile -f text 2>/dev/null)
    [[ -n "$profile" ]] || return
    p10k segment -f yellow -i '' -t "$profile"
}

# GCloud project from beachcomber
function prompt_bc_gcloud() {
    local project=$(comb get gcloud.project -f text 2>/dev/null)
    [[ -n "$project" ]] || return
    p10k segment -f blue -i '' -t "$project"
}

# Conda environment from beachcomber
function prompt_bc_conda() {
    local env=$(comb get conda.env . -f text 2>/dev/null)
    [[ -n "$env" ]] || return
    p10k segment -f green -i '' -t "$env"
}

# Terraform workspace from beachcomber
function prompt_bc_terraform() {
    local ws=$(comb get terraform.workspace . -f text 2>/dev/null)
    [[ -n "$ws" ]] || return
    p10k segment -f magenta -i '' -t "$ws"
}

# Network SSID from beachcomber
function prompt_bc_network() {
    local ssid=$(comb get network.ssid -f text 2>/dev/null)
    [[ -n "$ssid" ]] || return
    p10k segment -f white -i '' -t "$ssid"
}

# Battery from beachcomber
function prompt_bc_battery() {
    local pct=$(comb get battery.percent -f text 2>/dev/null)
    [[ -n "$pct" ]] || return
    p10k segment -f green -i '' -t "${pct}%%"
}
```

Only define the functions for providers you have enabled in your beachcomber config. Unused segment functions are harmless but add minor noise.

### Step 2: Add segments to the prompt

Find the `POWERLEVEL9K_RIGHT_PROMPT_ELEMENTS` array in `~/.p10k.zsh` and add the segment names you want. The names must match what follows `prompt_` in the function names defined above.

```zsh
typeset -g POWERLEVEL9K_RIGHT_PROMPT_ELEMENTS=(
    status
    command_execution_time
    background_jobs
    # beachcomber-backed segments
    bc_kube
    bc_aws
    bc_gcloud
    bc_conda
    bc_terraform
    bc_network
    bc_battery
)
```

Add only the segments relevant to your workflow. Each segment function returns early when the provider has no data, so unused segments produce no output even if listed.

### Step 3: Reload

```sh
source ~/.p10k.zsh
```

No need to restart zsh or the beachcomber daemon. Changes take effect immediately.

## Performance note

p10k uses instant prompt and renders custom segments asynchronously. Segment functions that call external commands run in a background context and do not block the initial prompt draw.

`comb get` returns cached data in approximately 34 microseconds (measured over a Unix socket). In practice, beachcomber-backed segments appear at the same time as p10k's built-in segments. There is no perceptible latency difference compared to purely internal p10k segments.

## Troubleshooting

- **Segment not showing:** verify the function name exactly matches `prompt_<segment_name>` and the segment name is in the `PROMPT_ELEMENTS` array. A typo in either causes p10k to silently skip it.
- **Changes not taking effect:** run `source ~/.p10k.zsh`. If instant prompt was active when you edited the file, a full shell restart may be needed.
- **Icons not rendering:** the glyphs require a Nerd Font. p10k's own patched fonts include all required glyphs. Replace icons with text labels if your font lacks them.

See the [Troubleshooting](./troubleshooting.md) guide for general diagnostics.
